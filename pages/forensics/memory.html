Memory Forensics

Memory Acquisition

Capture a full physical memory dump before analysis. Acquisition is volatile — act fast, minimize footprint on the target system.

Linux — LiME (Linux Memory Extractor)

# Build LiME kernel module (must match target kernel)
git clone https://github.com/504ensicsLabs/LiME.git
cd LiME/src
make

# Acquire memory — dump to local file
sudo insmod lime-$(uname -r).ko "path=/tmp/memory.lime format=lime"

# Acquire over network (avoid writing to target disk)
sudo insmod lime-$(uname -r).ko "path=tcp:4444 format=lime"
# On forensic workstation:
nc <target_ip> 4444 > memory.lime

# Formats: lime (recommended), raw, padded
# "lime" preserves address space gaps; "raw" is flat binary

Process Analysis Techniques

Identifying Hidden Processes

Compare pslist (walks EPROCESS linked list) with psscan (pool tag scan). Processes in psscan but not pslist have been unlinked via DKOM (Direct Kernel Object Manipulation).

# Cross-reference process lists
vol3 -f memory.raw windows.pslist > pslist.txt
vol3 -f memory.raw windows.psscan > psscan.txt

# Diff the PID lists — unlinked processes appear only in psscan
diff <(awk '{print $1}' pslist.txt | sort) <(awk '{print $1}' psscan.txt | sort)

Process Hollowing Detection

Process hollowing: attacker starts a legitimate process (e.g., svchost.exe) suspended, unmaps its image, maps malicious code, then resumes. The process looks legitimate in task manager but runs attacker code.

# Indicators:
# 1. Process image path doesn't match the code in memory
# 2. malfind shows PE headers (MZ/PE) in executable memory regions
# 3. PEB ImageBaseAddress differs from actual loaded image
# 4. Section permissions mismatch (private RWX where image section expected)

vol3 -f memory.raw windows.malfind --pid <suspect_pid>
# If you see MZ header at the start of a VAD region → likely hollowed

# Dump the injected PE for static analysis
vol3 -f memory.raw windows.malfind --pid <suspect_pid> --dump
file pid.<pid>.*.dmp    # check if it's a valid PE

DLL Injection Detection

# Compare three PEB DLL lists
vol3 -f memory.raw windows.ldrmodules --pid <pid>
# Columns: InLoad, InInit, InMem — all should be True for legitimate DLLs
# False in any column for an image-backed DLL = suspicious

# Check for unusual DLLs loaded into processes
vol3 -f memory.raw windows.dlllist --pid <pid>
# Red flags:
#   DLLs loaded from temp directories
#   DLLs with random/gibberish names
#   DLLs not in expected System32/SysWOW64 paths
#   Unsigned DLLs in otherwise fully signed processes

Rootkit Detection

DKOM (Direct Kernel Object Manipulation)

Rootkits unlink their process from the ActiveProcessLinks doubly-linked list in EPROCESS. The process still runs (scheduler uses a different list) but is invisible to pslist.

# Detection: pslist vs psscan diff (as shown above)
# psscan finds all EPROCESS structures via pool tag scanning
# regardless of list manipulation

# Additional DKOM targets:
#   - Thread lists (ETHREAD unlinking)
#   - Driver lists (hiding kernel drivers)
#   - Handle table manipulation

SSDT & IDT Hooks

# SSDT (System Service Descriptor Table) hooking
# Rootkit replaces function pointers in SSDT to intercept syscalls
vol3 -f memory.raw windows.ssdt
# Look for entries pointing outside ntoskrnl.exe or win32k.sys

# IRP hooks — driver dispatch function hooking
vol3 -f memory.raw windows.driverirp
# Check if IRP handlers point to unexpected modules

# Inline hooks — patching function prologues
vol3 -f memory.raw windows.callbacks
# Lists kernel notification callbacks (process, thread, image load)

Kernel Module Analysis

# List loaded kernel modules
vol3 -f memory.raw windows.modules
vol3 -f memory.raw windows.modscan    # pool tag scan — finds unlinked modules

# Compare — hidden drivers appear only in modscan
vol3 -f memory.raw windows.driverscan  # scan for DRIVER_OBJECT structures

# Dump suspicious kernel module
vol3 -f memory.raw windows.moddump --dump --base <module_base>

Custom Volatility 3 Plugins

"""
Custom Volatility 3 plugin template.
Save to: volatility3/volatility3/framework/plugins/custom_plugin.py
"""
from volatility3.framework import interfaces, renderers
from volatility3.framework.configuration import requirements
from volatility3.plugins.windows import pslist

class SuspiciousProcesses(interfaces.plugins.PluginInterface):
    """Find processes with indicators of compromise."""

    _required_framework_version = (2, 0, 0)

    @classmethod
    def get_requirements(cls):
        return [
            requirements.TranslationLayerRequirement(
                name="primary", description="Memory layer"
            ),
            requirements.SymbolTableRequirement(
                name="nt_symbols", description="Windows kernel symbols"
            ),
            requirements.PluginRequirement(
                name="pslist", plugin=pslist.PsList, version=(2, 0, 0)
            ),
        ]

    def _generator(self):
        suspicious_names = ["cmd.exe", "powershell.exe", "rundll32.exe",
                            "mshta.exe", "wscript.exe", "cscript.exe",
                            "regsvr32.exe", "certutil.exe"]
        for proc in pslist.PsList.list_processes(
            self.context, self.config["primary"], self.config["nt_symbols"]
        ):
            name = proc.ImageFileName.cast("string", max_length=14, errors="replace")
            ppid = proc.InheritedFromUniqueProcessId
            if name.lower() in suspicious_names:
                yield (0, (proc.UniqueProcessId, name, ppid,
                           proc.CreateTime.render()))

    def run(self):
        return renderers.TreeGrid(
            [("PID", int), ("Name", str), ("PPID", int), ("Created", str)],
            self._generator(),
        )
# Run custom plugin
vol3 -f memory.raw custom_plugin.SuspiciousProcesses

# Plugin development tips:
# - Place .py files in volatility3/framework/plugins/ or use --plugin-dirs
vol3 --plugin-dirs /my/plugins/ -f memory.raw custom_plugin.MyPlugin
# - Use PsList.list_processes() to iterate processes
# - Use context.layers to access memory translation layers
# - Renderers: TreeGrid for tables, text output via format_hints

Lab 12: Custom Volatility 3 Plugin Development

Hard

Objective: Write a custom Volatility 3 plugin that identifies processes with suspicious characteristics — unexpected parent, network activity from GUI apps, or encoded command lines.

Setup:

# Save as: suspicious_finder.py
# Place in volatility3/framework/plugins/ or use --plugin-dirs

from volatility3.framework import interfaces, renderers
from volatility3.framework.configuration import requirements
from volatility3.plugins.windows import pslist, cmdline
import re, base64

class SuspiciousFinder(interfaces.plugins.PluginInterface):
    """Identify processes with suspicious indicators."""

    _required_framework_version = (2, 0, 0)

    @classmethod
    def get_requirements(cls):
        return [
            requirements.TranslationLayerRequirement(
                name="primary", description="Memory layer"),
            requirements.SymbolTableRequirement(
                name="nt_symbols", description="Windows kernel symbols"),
            requirements.PluginRequirement(
                name="pslist", plugin=pslist.PsList, version=(2, 0, 0)),
        ]

    def _generator(self):
        suspect_parents = {
            "svchost.exe": ["services.exe"],
            "smss.exe": ["System"],
            "csrss.exe": ["smss.exe"],
            "lsass.exe": ["wininit.exe"],
        }
        for proc in pslist.PsList.list_processes(
            self.context, self.config["primary"],
            self.config["nt_symbols"]
        ):
            name = proc.ImageFileName.cast(
                "string", max_length=14, errors="replace")
            pid = proc.UniqueProcessId
            ppid = proc.InheritedFromUniqueProcessId
            flags = []

            # Check parent legitimacy
            lower = name.lower()
            if lower in suspect_parents:
                flags.append("CHECK_PARENT")

            yield (0, (pid, name, ppid, ", ".join(flags) if flags else "OK"))

    def run(self):
        return renderers.TreeGrid(
            [("PID", int), ("Name", str), ("PPID", int),
             ("Flags", str)],
            self._generator(),
        )

Tasks:

  1. Save the plugin and run: vol3 --plugin-dirs ./ -f memory.raw suspicious_finder.SuspiciousFinder
  2. Extend the plugin: add a check for processes with encoded PowerShell command lines
  3. Add network connection correlation: flag GUI processes (explorer children) that have ESTABLISHED connections
  4. Add a --output-file option to write results to JSON
  5. Test against a known-clean memory dump — verify low false-positive rate
  6. Test against an infected dump — confirm detection
