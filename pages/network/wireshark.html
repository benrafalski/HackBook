Combining Filters

# AND / OR / NOT
ip.addr == 192.168.1.100 && tcp.port == 80
http || dns
!arp && !dns

# Parentheses for grouping
(ip.src == 10.10.10.1 || ip.src == 10.10.10.2) && http

# Contains (substring match)
http.host contains "example"
frame.contains "FLAG{"

# Matches (regex)
http.request.uri matches ".*\\.php$"

# In operator
tcp.port in {80, 443, 8080, 8443}
ip.addr in {10.10.10.0/24}

tshark CLI

Command-line Wireshark. Same display filter syntax. Essential for scripting and server-side analysis.

# Basic capture
sudo tshark -i eth0

# Capture with display filter
sudo tshark -i eth0 -Y "http.request"

# Read pcap with filter
tshark -r capture.pcap -Y "dns"

# Extract specific fields
tshark -r capture.pcap -Y "http.request" \
  -T fields -e ip.src -e http.request.method -e http.host -e http.request.uri

# Extract DNS queries
tshark -r capture.pcap -Y "dns.qry.name" \
  -T fields -e dns.qry.name | sort | uniq -c | sort -rn

# Save filtered packets to new pcap
tshark -r large.pcap -Y "http" -w http_only.pcap

# Capture N packets then stop
sudo tshark -i eth0 -c 100 -w quick_capture.pcap

# Follow TCP stream
tshark -r capture.pcap -z follow,tcp,ascii,0

# Protocol hierarchy
tshark -r capture.pcap -z io,phs

# Statistics — conversations
tshark -r capture.pcap -z conv,tcp
tshark -r capture.pcap -z conv,ip

# Extract HTTP objects
tshark -r capture.pcap --export-objects http,./extracted_files/

Pcap Analysis Methodology (CTF)

Systematic approach when handed a pcap in a CTF:

# 1. Get an overview — what protocols are present?
tshark -r challenge.pcap -z io,phs -q

# 2. Check conversations — who talked to whom?
tshark -r challenge.pcap -z conv,ip -q

# 3. Look for low-hanging fruit
# HTTP requests
tshark -r challenge.pcap -Y "http.request" -T fields -e http.host -e http.request.uri
# DNS queries (check for tunneling)
tshark -r challenge.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | sort -u
# Search for flag format
tshark -r challenge.pcap -Y 'frame.contains "FLAG"' 
# or in Wireshark: Edit → Find Packet → String → "FLAG{"

# 4. Extract files
# Wireshark: File → Export Objects → HTTP / SMB / TFTP
tshark -r challenge.pcap --export-objects http,./http_files/

# 5. Check for credentials
tshark -r challenge.pcap -Y "http.request.method == POST" -T fields \
  -e ip.src -e http.request.uri -e urlencoded-form.value
tshark -r challenge.pcap -Y "ftp.request.command == PASS" -T fields -e ftp.request.arg

# 6. Look for anomalies
# ICMP with unusual payload sizes
tshark -r challenge.pcap -Y "icmp && data.len > 0" -T fields -e data.data
# DNS with long subdomain names (tunneling)
tshark -r challenge.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | awk '{if(length($0)>50)print}'

Finding Credentials in Pcaps

# HTTP POST (form login)
tshark -r capture.pcap -Y "http.request.method == POST" -T fields \
  -e frame.number -e ip.src -e http.host -e http.request.uri

# Then follow the HTTP stream of matching packets
# Look for: username=, password=, passwd=, login=, user=

# HTTP Basic Auth (Base64)
tshark -r capture.pcap -Y "http.authorization" -T fields -e http.authorization
# Decode: echo "dXNlcjpwYXNz" | base64 -d

# FTP credentials (cleartext)
tshark -r capture.pcap -Y "ftp.request.command == USER || ftp.request.command == PASS" \
  -T fields -e ftp.request.command -e ftp.request.arg

# Telnet (cleartext, character-by-character)
tshark -r capture.pcap -Y "telnet.data" -T fields -e telnet.data

# SMTP auth
tshark -r capture.pcap -Y "smtp" | grep -i "AUTH\|USER\|PASS"

# POP3
tshark -r capture.pcap -Y "pop.request" -T fields -e pop.request.command -e pop.request.parameter

# NTLM / Kerberos — use NetworkMiner or ntlmrelayx tools
# For NTLM hashes in SMB:
tshark -r capture.pcap -Y "ntlmssp.auth" -T fields -e ntlmssp.auth.username -e ntlmssp.auth.domain

Common CTF Pcap Patterns

HTTP Flag Exfiltration

# Flag hidden in HTTP headers, cookies, POST data, or URL parameters
tshark -r ctf.pcap -Y "http" -T fields -e http.cookie -e http.set_cookie
tshark -r ctf.pcap -Y "http.request" -T fields -e http.request.uri | grep -i flag
tshark -r ctf.pcap -Y "http.response" -T fields -e http.response.code -e http.content_type

# Check custom headers
tshark -r ctf.pcap -Y "http" -V | grep -i "X-Flag\|X-Secret\|X-Hidden"

DNS Tunneling

# Data encoded in DNS subdomain labels
tshark -r ctf.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | sort -u

# Look for long, hex/base64-encoded subdomains:
#   64686973206973207468652064617461.evil.com
# Extract and decode:
tshark -r ctf.pcap -Y "dns.qry.name contains evil.com" -T fields -e dns.qry.name | \
  sed 's/.evil.com//' | xxd -r -p

# TXT record responses can also carry data
tshark -r ctf.pcap -Y "dns.txt" -T fields -e dns.txt

ICMP Data Exfiltration

# Data hidden in ICMP echo request/reply payloads
tshark -r ctf.pcap -Y "icmp" -T fields -e data.data

# Extract and decode
tshark -r ctf.pcap -Y "icmp.type == 8" -T fields -e data.data | tr -d ':' | xxd -r -p

# Check for varying payload sizes (each packet = one character)
tshark -r ctf.pcap -Y "icmp" -T fields -e data.len

FTP Transfers

# FTP uses separate control (21) and data channels
# Find commands
tshark -r ctf.pcap -Y "ftp.request" -T fields -e ftp.request.command -e ftp.request.arg

# Find transferred files (follow FTP-DATA streams)
tshark -r ctf.pcap -Y "ftp-data" -T fields -e tcp.stream | sort -u
# Then follow each stream in Wireshark → Save As → Raw

Lab 3: Analyze Suspicious Traffic Patterns

Hard

Objective: Analyze a pcap file containing mixed legitimate and malicious traffic. Identify C2 beaconing, data exfiltration, and lateral movement indicators.

Setup: Use a pcap from malware-traffic-analysis.net or generate your own with a C2 framework in a lab.

# Step 1: Protocol overview — what stands out?
tshark -r suspicious.pcap -z io,phs -q

# Step 2: Conversation analysis — who talks to whom, how much data?
tshark -r suspicious.pcap -z conv,ip -q
# Look for: unusual destinations, high volume to single IP, periodic connections

# Step 3: Check for beaconing (regular interval connections)
tshark -r suspicious.pcap -Y "ip.dst == <suspect_ip>" \
  -T fields -e frame.time_delta_displayed | head -30
# Consistent intervals (e.g., every 60s) = beaconing

# Step 4: DNS analysis — look for tunneling or DGA domains
tshark -r suspicious.pcap -Y "dns.qry.name" -T fields -e dns.qry.name | \
  awk '{print length, $0}' | sort -rn | head -20
# Long random-looking domains = DGA or tunneling

# Step 5: HTTP analysis — user agents, POST data sizes
tshark -r suspicious.pcap -Y "http.request" -T fields \
  -e ip.dst -e http.request.method -e http.host -e http.user_agent | sort | uniq -c | sort -rn

# Step 6: Check for data exfil — large outbound transfers
tshark -r suspicious.pcap -z conv,tcp -q
# Sort by bytes — large outbound to external IP = exfil

# Step 7: Look for lateral movement (internal → internal on SMB/RDP/WinRM)
tshark -r suspicious.pcap -Y "ip.src == 192.168.0.0/16 && ip.dst == 192.168.0.0/16 && (tcp.port == 445 || tcp.port == 3389 || tcp.port == 5985)"

Tasks:

  1. Identify the compromised host(s) and the C2 server IP
  2. Determine the beaconing interval
  3. Extract any exfiltrated data or transferred files
  4. Map the attack timeline: initial compromise → C2 → lateral movement → exfil
  5. Write tshark one-liners to detect each stage

Lab 6: Lua Dissector Writing

Hard

Objective: Write a custom Lua dissector for Wireshark to decode a proprietary protocol running on TCP port 9999.

# Save as ~/.local/lib/wireshark/plugins/custom_proto.lua
# The protocol: [2-byte length][1-byte command][payload]
# Commands: 0x01=HELLO, 0x02=DATA, 0x03=BYE
# custom_proto.lua (Lua for Wireshark)
custom_proto = Proto("CustomProto", "Custom Protocol")

-- Field definitions
local f_length = ProtoField.uint16("custom.length", "Length", base.DEC)
local f_command = ProtoField.uint8("custom.command", "Command", base.HEX,
    {[0x01] = "HELLO", [0x02] = "DATA", [0x03] = "BYE"})
local f_payload = ProtoField.string("custom.payload", "Payload")

custom_proto.fields = {f_length, f_command, f_payload}

function custom_proto.dissector(buffer, pinfo, tree)
    if buffer:len() < 3 then return end

    pinfo.cols.protocol = "CUSTOM"
    local subtree = tree:add(custom_proto, buffer(), "Custom Protocol")

    local length = buffer(0, 2):uint()
    subtree:add(f_length, buffer(0, 2))
    subtree:add(f_command, buffer(2, 1))

    local cmd = buffer(2, 1):uint()
    if cmd == 0x01 then
        pinfo.cols.info = "HELLO"
    elseif cmd == 0x02 then
        local payload = buffer(3, length - 1):string()
        subtree:add(f_payload, buffer(3, length - 1))
        pinfo.cols.info = "DATA: " .. payload:sub(1, 50)
    elseif cmd == 0x03 then
        pinfo.cols.info = "BYE"
    end
end

local tcp_port = DissectorTable.get("tcp.port")
tcp_port:add(9999, custom_proto)
# Load: Wireshark → Help → About → Folders → Personal Lua Plugins
# Copy the .lua file there, then Ctrl+Shift+L to reload
# Or launch with: wireshark -X lua_script:custom_proto.lua

Lab 12: Pcap Timeline Reconstruction & Conversation Tracking

Medium

Objective: Reconstruct a complete incident timeline from a pcap. Track conversations, follow streams, and build a narrative of network events.

#!/usr/bin/env python3
"""Build an incident timeline from a pcap file."""
from scapy.all import *
from collections import defaultdict
import json

pkts = rdpcap("incident.pcap")
timeline = []
conversations = defaultdict(lambda: {"packets": 0, "bytes": 0, "first": None, "last": None})

for pkt in pkts:
    ts = float(pkt.time)
    event = {"time": ts}

    if pkt.haslayer(IP):
        src, dst = pkt[IP].src, pkt[IP].dst
        key = tuple(sorted([src, dst]))
        conv = conversations[key]
        conv["packets"] += 1
        conv["bytes"] += len(pkt)
        if conv["first"] is None:
            conv["first"] = ts

        if pkt.haslayer(TCP):
            flags = str(pkt[TCP].flags)
            if flags == "S":
                timeline.append({"time": ts, "type": "TCP_CONNECT",
                    "src": src, "dst": dst, "port": pkt[TCP].dport})
            elif "R" in flags:
                timeline.append({"time": ts, "type": "TCP_RESET",
                    "src": src, "dst": dst, "port": pkt[TCP].sport})

        if pkt.haslayer(DNS) and pkt[DNS].qr == 0:
            timeline.append({"time": ts, "type": "DNS_QUERY",
                "src": src, "query": pkt[DNSQR].qname.decode()})

        if pkt.haslayer(Raw):
            payload = pkt[Raw].load
            if b"HTTP" in payload:
                timeline.append({"time": ts, "type": "HTTP",
                    "src": src, "dst": dst, "data": payload[:100].decode(errors="ignore")})

# Output timeline
timeline.sort(key=lambda x: x["time"])
for event in timeline[:50]:
    print(f"[{event['time']:.3f}] {event['type']}: {event}")

# Top conversations
print("\n=== Top Conversations ===")
for k, v in sorted(conversations.items(), key=lambda x: x[1]["bytes"], reverse=True)[:10]:
    print(f"  {k[0]} ↔ {k[1]}: {v['packets']} pkts, {v['bytes']} bytes")

Challenge 3: Decode the Covert Channel

Hard

Someone is exfiltrating data through a covert ICMP channel. The flag is hidden in the ICMP echo request payloads. Extract and decode it.

# Step 1: Filter for ICMP echo requests
tshark -r covert.pcap -Y "icmp.type == 8"

# Step 2: Extract the data payload from each echo request
tshark -r covert.pcap -Y "icmp.type == 8" -T fields -e data.data

# Step 3: The data may be encoded in different ways:

# Method A: Each packet's payload is a hex-encoded chunk
tshark -r covert.pcap -Y "icmp.type == 8" -T fields -e data.data | \
  tr -d ':\n' | xxd -r -p

# Method B: One byte per packet (payload length = the character)
tshark -r covert.pcap -Y "icmp.type == 8" -T fields -e data.len | \
  while read len; do printf "\\$(printf '%03o' $len)"; done

# Method C: Data in the ICMP ID or sequence fields
tshark -r covert.pcap -Y "icmp.type == 8" -T fields -e icmp.ident | \
  while read id; do printf "\\$(printf '%03o' $((id)))"; done
# Python approach with scapy
from scapy.all import *

packets = rdpcap("covert.pcap")
data = b""

for pkt in packets:
    if pkt.haslayer(ICMP) and pkt[ICMP].type == 8:  # echo request
        if pkt.haslayer(Raw):
            data += pkt[Raw].load

print(data.decode(errors="ignore"))
# Look for FLAG{...} in the output

# If one byte per packet:
flag = ""
for pkt in packets:
    if pkt.haslayer(ICMP) and pkt[ICMP].type == 8:
        if pkt.haslayer(Raw):
            flag += chr(pkt[Raw].load[0])
print(flag)

Filter for ICMP echo requests (icmp.type == 8) and extract the data.data field. The payloads aren't random — they contain the flag encoded as hex or ASCII. Try concatenating all payloads and decoding. If the raw data doesn't make sense, try looking at only the first byte of each payload, or the ICMP sequence numbers as ASCII values. Use the scapy script for easy extraction and try multiple decoding strategies.

Challenge 6: Protocol Anomaly Detection

Hard

A pcap appears to contain normal HTTP browsing traffic, but packets are being used to tunnel data. The tunneled data uses non-standard values in protocol fields. Find and extract the hidden data.

from scapy.all import *

pkts = rdpcap("anomaly.pcap")
hidden = []

for pkt in pkts:
    if pkt.haslayer(IP) and pkt.haslayer(TCP) and pkt[TCP].dport == 80:
        # Check for anomalies in IP header
        # Normal IP ID is random/incremental — sequential ASCII is suspicious
        ip_id = pkt[IP].id
        if 32 <= ip_id <= 126:  # printable ASCII range
            hidden.append(chr(ip_id))

        # Also check: TTL variations, IP options, TCP reserved bits
        # TCP timestamp low byte
        for opt_name, opt_val in pkt[TCP].options:
            if opt_name == "Timestamp":
                ts_val = opt_val[0] & 0xFF
                if 32 <= ts_val <= 126:
                    hidden.append(chr(ts_val))

print("Hidden data (IP ID):", "".join(hidden[:50]))
print("Look for FLAG{ pattern...")

The data is hidden in the IP Identification field of outbound HTTP packets. Extract the IP ID from each packet to port 80, convert to ASCII, and concatenate. Only use packets from the internal host (source IP starting with 192.168). The values form printable ASCII text including the flag.

Challenge 8: Timing Analysis

Medium

Data is being exfiltrated using inter-packet timing. Each bit of the flag is encoded as a time delay between consecutive ICMP packets: short delay = 0, long delay = 1. Decode the binary to ASCII.

from scapy.all import *

pkts = rdpcap("timing.pcap")
icmp_pkts = [p for p in pkts if p.haslayer(ICMP) and p[ICMP].type == 8]

# Calculate inter-packet delays
delays = []
for i in range(1, len(icmp_pkts)):
    delta = float(icmp_pkts[i].time) - float(icmp_pkts[i-1].time)
    delays.append(delta)

# Determine threshold between short (0) and long (1) delays
avg = sum(delays) / len(delays)
bits = "".join("0" if d < avg else "1" for d in delays)

# Convert binary to ASCII (8 bits per character)
flag = ""
for i in range(0, len(bits) - 7, 8):
    byte = bits[i:i+8]
    flag += chr(int(byte, 2))
print(f"Flag: {flag}")

Calculate the time delta between each consecutive ICMP echo request. Delays cluster around two values (e.g., 0.1s and 0.5s). Use the average as a threshold: below = 0, above = 1. Group the bits into 8-bit bytes and convert to ASCII.

Challenge 9: Multi-Protocol Exfiltration

Hard

Data was exfiltrated using three different protocols simultaneously: DNS (subdomain encoding), HTTP (custom headers), and ICMP (payload). Each carries one-third of the base64-encoded flag. Reassemble all three parts.

from scapy.all import *
import base64

pkts = rdpcap("multi_exfil.pcap")
dns_data, http_data, icmp_data = "", "", ""

for pkt in pkts:
    # Part 1: DNS — encoded in subdomain labels
    if pkt.haslayer(DNSQR):
        qname = pkt[DNSQR].qname.decode()
        if "exfil.evil.com" in qname:
            chunk = qname.split(".exfil.evil.com")[0].replace(".", "")
            dns_data += chunk

    # Part 2: HTTP — encoded in X-Data header
    if pkt.haslayer(Raw) and b"X-Data:" in pkt[Raw].load:
        line = [l for l in pkt[Raw].load.decode(errors="ignore").split("\r\n")
                if l.startswith("X-Data:")][0]
        http_data += line.split(": ")[1]

    # Part 3: ICMP — in echo request payload
    if pkt.haslayer(ICMP) and pkt[ICMP].type == 8 and pkt.haslayer(Raw):
        icmp_data += pkt[Raw].load.decode(errors="ignore")

combined = dns_data + http_data + icmp_data
flag = base64.b64decode(combined).decode()
print(f"Flag: {flag}")

Extract data from all three channels separately. DNS data is in subdomain labels before .exfil.evil.com. HTTP data is in a custom X-Data header. ICMP data is in echo request payloads. Concatenate in order (DNS + HTTP + ICMP) and base64-decode the result.

Challenge 10: Conversation Tracker

Easy

A pcap contains traffic from 50 hosts. One host communicated with more unique external IPs than any other. Find that host's IP and the count of unique external destinations. The flag is FLAG{ip_count}.

# Method 1: tshark conversations
tshark -r traffic.pcap -z conv,ip -q | sort -t'<' -k5 -rn | head

# Method 2: tshark fields + sort
tshark -r traffic.pcap -T fields -e ip.src -e ip.dst | \
  awk '$1 ~ /^192\.168/ {print $1, $2}' | \
  sort -u | awk '{count[$1]++} END {for(ip in count) print count[ip], ip}' | \
  sort -rn | head -5
from scapy.all import *
from collections import defaultdict

pkts = rdpcap("traffic.pcap")
external_dests = defaultdict(set)

for pkt in pkts:
    if pkt.haslayer(IP):
        src, dst = pkt[IP].src, pkt[IP].dst
        if src.startswith("192.168.") and not dst.startswith("192.168."):
            external_dests[src].add(dst)

top = max(external_dests, key=lambda x: len(external_dests[x]))
print(f"FLAG{{{top}_{len(external_dests[top])}}}")

Filter for traffic where the source is internal (192.168.x.x) and destination is external. Count unique destination IPs per source. The host with the most unique external destinations is likely compromised (C2 beaconing or scanning).
