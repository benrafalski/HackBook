Memory Management

Virtual vs Physical Memory

Every process gets its own virtual address space — a flat, contiguous view of memory that the kernel and MMU translate to physical frames. Processes cannot directly access another process's physical memory.

ConceptDescription
Virtual AddressWhat the process sees. Translated by the MMU via page tables to a physical address.
Physical AddressActual location in RAM. Managed by the kernel; userspace never sees it directly.
PageFixed-size block (typically 4 KB). Smallest unit of memory mapping.
Page FaultTriggered when accessing unmapped/non-present virtual memory. Kernel handles it (allocates frame, loads from disk, or kills process).

Address Translation Overview

The CPU's Memory Management Unit (MMU) walks the page tables on every memory access to convert virtual → physical addresses. The CR3 register points to the base of the current process's page table structure. The TLB (Translation Lookaside Buffer) caches recent translations for performance.

# View CR3 (page table base) in kernel debug contexts
# In /proc, you can see mapped translations:
cat /proc/self/pagemap | xxd | head

Key flags per page table entry: Present (P), Read/Write (R/W), User/Supervisor (U/S), No-Execute (NX/XD), Accessed (A), Dirty (D).

ASLR — Address Space Layout Randomization

ASLR randomizes the base addresses of key memory regions on each execution, making it harder to predict where code/data lives.

# Check system ASLR setting
cat /proc/sys/kernel/randomize_va_space
# 0 = disabled, 1 = stack/mmap/VDSO, 2 = full (+ brk/heap)

# Toggle ASLR (requires root)
echo 0 | sudo tee /proc/sys/kernel/randomize_va_space   # disable
echo 2 | sudo tee /proc/sys/kernel/randomize_va_space   # enable full

# Per-process disable (no root)
setarch $(uname -m) -R ./binary

Memory Mapping: mmap, munmap, mprotect

// mmap — map memory (anonymous or file-backed)
#include <sys/mman.h>

// Anonymous RW mapping (private heap-like region)
void *p = mmap(NULL, 4096, PROT_READ | PROT_WRITE,
               MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

// File-backed mapping
int fd = open("data.bin", O_RDONLY);
void *m = mmap(NULL, filesize, PROT_READ, MAP_PRIVATE, fd, 0);

// Executable mapping (shellcode)
void *rwx = mmap(NULL, 4096, PROT_READ | PROT_WRITE | PROT_EXEC,
                 MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

// munmap — unmap a region
munmap(p, 4096);

// mprotect — change permissions on existing mapping
mprotect(p, 4096, PROT_READ | PROT_EXEC);  // RW→RX

Memory Permissions & Security Implications

PermissionExploit Relevance
r-x (code)Can execute but not modify. ROP/JOP reuses existing code.
rw- (data/stack/heap)Can write shellcode but can't execute it (if NX enforced).
rwxWrite + execute = trivial shellcode execution. JIT engines, some interpreters.
r--Read-only. Overwriting requires mprotect or a kernel bug.

W^X (Write XOR Execute): A security policy where no memory is both writable and executable simultaneously. Enforced by NX bit + loader. Bypass: mprotect to add PROT_EXEC, or ROP into mmap with RWX.

DEP / NX Bit

The NX (No-Execute) bit (AMD) / XD (Execute Disable) bit (Intel) is set in page table entries to mark memory as non-executable. The OS uses this to enforce DEP (Data Execution Prevention).

AspectDetail
HardwareBit 63 of each page table entry. If set, CPU raises #PF on instruction fetch.
LinuxEnabled by default. Stack and heap are rw-, code is r-x.
WindowsDEP enabled per-process (OptIn/OptOut/AlwaysOn). VirtualProtect can change.
BypassROP, ret2libc, mprotect/VirtualProtect to make a region executable, JIT spraying.

Copy-on-Write (CoW)

When a process forks, the child shares the parent's physical pages (marked read-only). A write triggers a page fault → kernel copies the page → each process gets its own copy. This is efficient: pages that are only read are never duplicated.

pid_t pid = fork();
// At this point, parent and child share all memory pages (read-only)
// First write by either process triggers CoW — kernel copies that page

// Security relevance:
// - Dirty CoW (CVE-2016-5195): race condition in CoW handling
//   allowed writing to read-only mappings (privesc to root)
// - fork()-based servers: child inherits parent's memory layout
//   → ASLR base is the SAME in every child (brute-forceable)

Shared Memory & IPC

// POSIX shared memory
#include <sys/mman.h>
#include <fcntl.h>

int fd = shm_open("/myshm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);
void *ptr = mmap(NULL, 4096, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
// Now two processes mapping "/myshm" see the same physical memory

// SysV shared memory (legacy)
int shmid = shmget(IPC_PRIVATE, 4096, IPC_CREAT | 0666);
void *addr = shmat(shmid, NULL, 0);
shmdt(addr);
shmctl(shmid, IPC_RMID, NULL);

Security note: Shared memory regions are common IPC attack surfaces. If permissions are too open (0666), any local process can read/write. Sensitive data in shared memory can be leaked by a compromised process.

KASLR — Kernel ASLR

Randomizes the kernel's base address at boot. Without KASLR, the kernel is always loaded at a fixed address (e.g., 0xffffffff81000000), making kernel ROP trivial.

#include <string.h>
#include <sys/mman.h>
#include <unistd.h>
#include <stdint.h>

// x86-64 shellcode: write(1, "OK\n", 3)
unsigned char shellcode[] =
    "\x48\x31\xc0"             // xor rax, rax
    "\x48\xc7\xc0\x01\x00\x00\x00" // mov rax, 1  (sys_write)
    "\x48\xc7\xc7\x01\x00\x00\x00" // mov rdi, 1  (stdout)
    "\x48\x8d\x35\x0a\x00\x00\x00" // lea rsi, [rip+10]
    "\x48\xc7\xc2\x03\x00\x00\x00" // mov rdx, 3
    "\x0f\x05"                 // syscall
    "\xc3"                     // ret
    "OK\n";

int main() {
    printf("shellcode is at %p\n", shellcode);
    printf("shellcode is in .data (rw-, not executable)\n");
    
    // Try calling it without mprotect — should SEGFAULT
    // ((void(*)())shellcode)();
    
    // Page-align the address
    uintptr_t page = (uintptr_t)shellcode & ~0xFFF;
    
    // Make the page executable
    if (mprotect((void *)page, 4096, PROT_READ | PROT_WRITE | PROT_EXEC) == -1) {
        perror("mprotect");
        return 1;
    }
    
    printf("mprotect succeeded — shellcode page is now rwx\n");
    
    // Now call it
    ((void(*)())shellcode)();
    
    printf("shellcode executed successfully!\n");
    return 0;
}

Lab 4: TLB Analysis with perf

Medium

Objective: Measure TLB miss rates for sequential vs random access patterns and understand TLB impact on performance.

// tlb_test.c — gcc -O2 -o tlb_test tlb_test.c
#include <stdio.h>
#include <stdlib.h>
#include <time.h>

#define SIZE (256 * 1024 * 1024)  // 256 MB
#define ITERATIONS 10000000

int main(int argc, char **argv) {
    char *buf = malloc(SIZE);
    int stride = (argc > 1) ? atoi(argv[1]) : 64;
    volatile char sink;

    // Touch all pages
    for (size_t i = 0; i < SIZE; i += 4096) buf[i] = 1;

    struct timespec t1, t2;
    clock_gettime(CLOCK_MONOTONIC, &t1);

    // Access pattern: stride determines TLB pressure
    // stride=64 → many accesses per page (TLB friendly)
    // stride=4096 → one access per page (TLB thrashing)
    for (int i = 0; i < ITERATIONS; i++) {
        size_t idx = ((size_t)i * stride) % SIZE;
        sink = buf[idx];
    }

    clock_gettime(CLOCK_MONOTONIC, &t2);
    double elapsed = (t2.tv_sec - t1.tv_sec) + (t2.tv_nsec - t1.tv_nsec) / 1e9;
    printf("Stride %d: %.3f sec (%.1f ns/access)\n",
           stride, elapsed, elapsed / ITERATIONS * 1e9);
    free(buf);
    return 0;
}
# Compare TLB performance
./tlb_test 64       # TLB-friendly (same page reused)
./tlb_test 4096     # one access per page (TLB thrashing)
./tlb_test 16384    # even worse — skipping pages

# Use perf to measure TLB misses
perf stat -e dTLB-load-misses,dTLB-loads ./tlb_test 64
perf stat -e dTLB-load-misses,dTLB-loads ./tlb_test 4096

Lab 5: Huge Pages

Medium

Objective: Allocate huge pages (2MB) and compare TLB miss rates against standard 4KB pages for large allocations.

// hugepage.c — gcc -O2 -o hugepage hugepage.c
#include <stdio.h>
#include <stdlib.h>
#include <sys/mman.h>
#include <time.h>

#define SIZE (64 * 1024 * 1024)  // 64 MB
#define ITERS 5000000

void benchmark(void *buf, const char *label) {
    volatile char sink;
    struct timespec t1, t2;
    clock_gettime(CLOCK_MONOTONIC, &t1);
    for (int i = 0; i < ITERS; i++) {
        size_t idx = ((size_t)i * 4096) % SIZE;
        sink = ((char *)buf)[idx];
    }
    clock_gettime(CLOCK_MONOTONIC, &t2);
    double ns = ((t2.tv_sec - t1.tv_sec) * 1e9 + (t2.tv_nsec - t1.tv_nsec)) / ITERS;
    printf("%s: %.1f ns/access\n", label, ns);
}

int main() {
    // Standard 4KB pages
    void *normal = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                        MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);
    // Huge pages (2MB)
    void *huge = mmap(NULL, SIZE, PROT_READ | PROT_WRITE,
                      MAP_PRIVATE | MAP_ANONYMOUS | MAP_HUGETLB, -1, 0);
    if (huge == MAP_FAILED) {
        perror("mmap(HUGETLB) — need: echo 64 > /proc/sys/vm/nr_hugepages");
        return 1;
    }

    // Touch all pages
    for (size_t i = 0; i < SIZE; i += 4096) ((char *)normal)[i] = 1;
    for (size_t i = 0; i < SIZE; i += 4096) ((char *)huge)[i] = 1;

    benchmark(normal, "4KB pages");
    benchmark(huge,   "2MB huge pages");

    munmap(normal, SIZE);
    munmap(huge, SIZE);
    return 0;
}

    munmap(mapped, sb.st_size);

    // Verify: read file normally
    printf("On disk: ");
    system("cat testfile.dat && echo");
    return 0;
}

Lab 8: Copy-on-Write Demonstration

Medium

Objective: Observe copy-on-write (CoW) behavior after fork() — verify parent and child share physical pages until one writes.

// cow_demo.c — gcc -o cow_demo cow_demo.c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

void print_rss(const char *label) {
    char buf[256];
    snprintf(buf, sizeof(buf), "grep VmRSS /proc/%d/status", getpid());
    printf("[%s pid=%d] ", label, getpid());
    fflush(stdout);
    system(buf);
}

int main() {
    size_t size = 100 * 1024 * 1024;  // 100 MB
    char *data = malloc(size);
    memset(data, 'A', size);  // fault in all pages

    printf("--- Before fork ---\n");
    print_rss("parent");

    pid_t pid = fork();
    if (pid == 0) {
        // Child — initially shares all pages with parent (CoW)
        printf("\n--- Child before write ---\n");
        print_rss("child");

        // Write to half the pages → triggers CoW for those pages
        memset(data, 'B', size / 2);

        printf("\n--- Child after writing 50MB ---\n");
        print_rss("child");

        free(data);
        _exit(0);
    }

    sleep(1);

Lab 9: Page Fault Handling with userfaultfd

Hard

Objective: Use userfaultfd to intercept page faults in userspace and provide custom page content on demand.

// userfaultfd_demo.c — gcc -o uffd_demo userfaultfd_demo.c -lpthread
#define _GNU_SOURCE
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <unistd.h>
#include <pthread.h>
#include <sys/mman.h>
#include <sys/ioctl.h>
#include <sys/syscall.h>
#include <linux/userfaultfd.h>
#include <poll.h>

#define PAGE_SIZE 4096
static int uffd;

void *fault_handler(void *arg) {
    struct uffd_msg msg;
    char page[PAGE_SIZE];

    for (;;) {
        struct pollfd pfd = { .fd = uffd, .events = POLLIN };
        poll(&pfd, 1, -1);
        read(uffd, &msg, sizeof(msg));

        if (msg.event != UFFD_EVENT_PAGEFAULT) continue;

        printf("Page fault at %p!\n", (void *)msg.arg.pagefault.address);

        // Fill the page with custom content
        memset(page, 'X', PAGE_SIZE);
        snprintf(page, PAGE_SIZE, "fault-handled page at %p",
                 (void *)msg.arg.pagefault.address);

        struct uffdio_copy copy = {
            .dst = msg.arg.pagefault.address & ~(PAGE_SIZE - 1),
            .src = (unsigned long)page,
            .len = PAGE_SIZE,
        };
        ioctl(uffd, UFFDIO_COPY, &copy);
    }
}

int main() {
    uffd = syscall(SYS_userfaultfd, O_NONBLOCK);
    struct uffdio_api api = { .api = UFFD_API };
    ioctl(uffd, UFFDIO_API, &api);

    // Map anonymous memory without populating it
    size_t size = 4 * PAGE_SIZE;
    char *region = mmap(NULL, size, PROT_READ | PROT_WRITE,
                        MAP_PRIVATE | MAP_ANONYMOUS, -1, 0);

    // Register for page faults
    struct uffdio_register reg = {
        .range = { .start = (unsigned long)region, .len = size },
        .mode = UFFDIO_REGISTER_MODE_MISSING,
    };
    ioctl(uffd, UFFDIO_REGISTER, &reg);

    // Start fault handler thread
    pthread_t thr;
    pthread_create(&thr, NULL, fault_handler, NULL);

    // Access pages — triggers faults handled by our thread
    printf("Content: %s\n", region);               // fault on page 0
    printf("Content: %s\n", region + PAGE_SIZE);   // fault on page 1

    munmap(region, size);
    return 0;
}

  3. Modify to serve different content for each page based on address

Challenge 2: Partial Overwrite

Hard

A PIE binary with ASLR. You can only overflow 1 byte past the return address. Use a partial overwrite to redirect execution to win().

// partial.c - gcc -o partial partial.c -pie -fno-stack-protector
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

void win() {
    execve("/bin/sh", NULL, NULL);
}

void vuln() {
    char buf[40];
    printf("Input: ");
    // Off-by-one: reads 1 byte more than buffer+rbp
    // Can overwrite the LOWEST byte of the return address
    read(0, buf, 40 + 8 + 1);  // buf + saved RBP + 1 byte of ret
}

int main() {
    vuln();
    return 0;
}

Setup: Create a flag file: echo "FLAG{partial_overwrite_ftw}" > flag.txt

The return address normally points back into main after the call vuln instruction. Both main and win are in the same page (or nearby pages) of the PIE binary. Overwrite just the lowest byte of the return address with the low byte of win()'s address. Since the bottom 12 bits are NOT randomized by ASLR, if win and the original return site share the same upper bytes, you only need to change the page offset. Check with objdump -d partial | grep -E 'win|main' to find the offsets. You may need a 4-bit brute force (~16 attempts) if they differ in the second nibble.

# 2. How many bits change between samples?

Challenge 5: Shared Memory Race

Hard

#include <string.h>
#include <fcntl.h>
#include <sys/mman.h>
#include <unistd.h>

Challenge 6: COW Exploitation

Hard

A setuid binary forks and the child checks a password from a file. Since fork shares memory via CoW, leak the parent's memory to find the password without reading the file.

// cow_leak.c — gcc -o cow_leak cow_leak.c
#include <stdio.h>
#include <string.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

int main() {
    char password[64];
    FILE *f = fopen("secret_password.txt", "r");
    if (!f) { puts("Put password in secret_password.txt"); return 1; }
    fgets(password, sizeof(password), f);
    fclose(f);
    password[strcspn(password, "\n")] = 0;

    pid_t pid = fork();
    if (pid == 0) {
        // Child process — password is in our memory (CoW)!
        // But we "shouldn't" have access via the normal API
        char guess[64];
        printf("Guess the password: ");
        fgets(guess, sizeof(guess), stdin);
        guess[strcspn(guess, "\n")] = 0;

        if (strcmp(guess, password) == 0) {
            printf("Correct! Flag: flag{cow_memory_inheritance}\n");
        } else {
            printf("Wrong!\n");
        }
        _exit(0);
    }
    wait(NULL);
    return 0;
}

After fork, the child has a copy of the parent's entire memory, including the password variable on the stack. If you can attach GDB to the child (gdb -p $(pgrep cow_leak)) or read /proc/[child_pid]/mem before the child exits, you can dump the password directly. Alternatively, if the binary has a format string or buffer read vulnerability, leak the stack to find the password. The key insight: fork does NOT protect parent secrets from the child.
