Binary Exploitation Fundamentals

ELF Format

Every Linux binary is an ELF (Executable and Linkable Format) file with three layers:

Compilation Pipeline

source.c → [Preprocessor] → [Compiler] → [Assembler] → [Linker] → executable
              cpp              cc1           as            ld
             .c → .i         .i → .s      .s → .o      .o → ELF

# Compile with protections disabled (for practice)
gcc -o vuln vuln.c -fno-stack-protector -z execstack -no-pie -Wl,-z,norelro

# Compile normally (all protections on)
gcc -o vuln vuln.c

ELF Header

$ readelf -h ./binary
  Magic:   7f 45 4c 46 02 01 01 ...    # "\x7fELF" magic bytes
  Class:   ELF64                        # 64-bit
  Type:    EXEC / DYN (PIE)             # static or position-independent
  Entry:   0x401060                     # where execution begins (_start)

Key Sections

SectionPurpose
.textExecutable code (your compiled functions)
.dataInitialized global/static variables
.bssUninitialized globals (zeroed at load)
.rodataRead-only data (string literals, constants)
.pltProcedure Linkage Table — stubs for shared library calls
.got / .got.pltGlobal Offset Table — resolved external function addresses
.dynamicDynamic linking info (shared libs, symbol tables)
.symtab / .dynsymSymbol tables (function/variable names + addresses)

Memory Layout

High addresses (0x7fff...)
┌───────────────────────┐
│       Stack           │ ← grows downward (RSP decreases)
│                       │   local vars, return addrs, args
├───────────────────────┤
│         ↓             │
│    (unmapped gap)     │
│         ↑             │
├───────────────────────┤
│       Heap            │ ← grows upward (brk/mmap)
│                       │   malloc'd memory
├───────────────────────┤
│       .bss            │ ← uninitialized data
├───────────────────────┤
│       .data           │ ← initialized globals
├───────────────────────┤
│       .text           │ ← code (read + execute)
├───────────────────────┤
Low addresses (0x400000)

Security Protections

checksec --file=./binary
# RELRO:      Full RELRO        # GOT is read-only after startup
# Stack:      Canary found      # stack buffer overflow detection
# NX:         NX enabled        # no shellcode on stack/heap
# PIE:        PIE enabled       # code at random base address
# FORTIFY:    Enabled           # hardened libc functions
ProtectionWhat It DoesBypass
NX/DEPStack/heap non-executableROP, ret2libc
Stack CanaryRandom value before ret addr; checked on returnLeak canary, brute force (32-bit fork), avoid overwriting it
PIEBinary loaded at random baseLeak code address, partial overwrite
ASLRStack/heap/libs randomized each runLeak addresses, brute force (32-bit)
Full RELROGOT read-only after relocationCan't overwrite GOT; target __malloc_hook, __free_hook, stack
Partial RELROGOT still writableGOT overwrite viable

Pwntools Essentials

from pwn import *

# Setup
context.arch = 'amd64'
context.os = 'linux'
context.log_level = 'debug'     # show all I/O

# Connect
p = process('./binary')                        # local
p = remote('challenge.ctf.com', 1337)          # remote
p = gdb.debug('./binary', 'b main\nc')         # auto-attach GDB

# ELF analysis
elf = ELF('./binary')
libc = ELF('./libc.so.6')

# I/O
p.send(b'data')                  # send raw bytes
p.sendline(b'data')              # send + newline
p.sendlineafter(b'> ', b'data')  # wait for prompt, then send
p.recv(1024)                     # receive up to N bytes
p.recvline()                     # receive until newline
p.recvuntil(b'flag{')            # receive until marker
p.interactive()                  # drop to interactive shell

# Packing (little-endian by default)
p64(0xdeadbeef)                  # pack to 8 bytes
u64(b'\xef\xbe\xad\xde\x00\x00\x00\x00')  # unpack
u64(leaked.ljust(8, b'\x00'))    # partial leak unpack

# ELF symbols
elf.symbols['main']              # address of main
elf.got['puts']                  # GOT entry
elf.plt['puts']                  # PLT entry
next(elf.search(b'/bin/sh'))     # find string

# ROP
rop = ROP(elf)
pop_rdi = rop.find_gadget(['pop rdi', 'ret']).address
ret = rop.find_gadget(['ret']).address

# Shellcode
shellcode = asm(shellcraft.sh())          # /bin/sh shellcode
shellcode = asm(shellcraft.cat('flag'))   # cat flag

Data Representation

ConceptDetails
Endiannessx86 = little-endian. 0xdeadbeef stored as ef be ad de
Signed integersTwo's complement. MSB = sign bit. -1 = 0xffffffffffffffff
Pointers64-bit: 8 bytes. Only 48 bits used (canonical addresses). User space: 0x0000..., kernel: 0xffff...
Alignmentx86_64 stack must be 16-byte aligned before call. Misalignment → SIGSEGV in libc functions using SSE (movaps)

Challenge 7: Multi-Part Key Recovery

Medium

A binary computes a key from multiple function return values XOR'd together. Use GDB to recover all parts and reconstruct the key.

// challenge7.c
// gcc -o challenge7 challenge7.c -no-pie -O0
#include <stdio.h>
#include <string.h>
#include <stdlib.h>

int part1() { return 0xCAFE; }
int part2() { return 0xBEEF; }
int part3() { return 0xDEAD; }

int main() {
    int p1 = part1();
    int p2 = part2();
    int p3 = part3();
    int key = p1 ^ p2 ^ p3;

    char expected[32];
    snprintf(expected, 32, "KEY-%X", key);

    char input[32];
    printf("Enter the key: ");
    fgets(input, 32, stdin);
    input[strcspn(input, "\n")] = 0;

    if (strcmp(input, expected) == 0) {
        printf("CTF{gdb_multi_break_%X}\n", key);
    } else {
        printf("Wrong! Try GDB.\n");
    }
    return 0;
}

Break after each call and check $eax for the return value: 0xCAFE, 0xBEEF, 0xDEAD. XOR them: 0xCAFE ^ 0xBEEF ^ 0xDEAD = 0x6E5C (verify in GDB or Python). Or break at strcmp and inspect RSI to read the expected string directly.

Challenge 9: Memory Map Explorer

Medium

A binary prints six addresses from different memory regions. Identify which region each belongs to and verify via /proc/PID/maps.

// challenge9.c
// gcc -o challenge9 challenge9.c -no-pie
#include <stdio.h>
#include <stdlib.h>
#include <unistd.h>

int global_var = 42;
int bss_var;
const char *rodata = "read-only string";

int main() {
    int stack_var = 1;
    char *heap_var = malloc(64);

    printf("Address A: %p\n", &stack_var);
    printf("Address B: %p\n", &global_var);
    printf("Address C: %p\n", heap_var);
    printf("Address D: %p\n", main);
    printf("Address E: %p\n", &bss_var);
    printf("Address F: %p\n", printf);

    printf("\nMap A-F to: stack, .data, heap, .text, .bss, libc\n");
    printf("Verify: cat /proc/%d/maps\n", getpid());
    sleep(30);

    free(heap_var);
    return 0;
}

Run the binary, map each address to its memory region, then verify with /proc/PID/maps.

A = stack (high address near 0x7fff...), B = .data (near 0x40xxxx), C = heap (above binary, below stack), D = .text (near 0x40xxxx), E = .bss (right after .data), F = libc (high random address from ASLR). Open another terminal and run cat /proc/PID/maps to confirm each range.

Challenge 10: Binary Identification Gauntlet

Hard

Given 4 mystery binaries, determine the architecture, endianness, linking, and protections of each. Then exploit the most vulnerable one to get the flag.

# Setup: create 4 mystery binaries

#include <stdio.h>

void flag() { printf("CTF{binary_gauntlet_master}\n"); }

Binary B is hardest (all protections + stripped). Binary C is 32-bit — remember args go on the stack, not registers.
