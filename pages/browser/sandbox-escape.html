Mojo IPC — The Attack Surface

Mojo is Chrome's IPC system. Renderers communicate with the browser process through Mojo interfaces. Each interface is a potential attack surface for sandbox escape.

Mojo IPC Architecture:
┌──────────────┐     Mojo Messages      ┌──────────────┐
│   RENDERER   │ ◄══════════════════════►│   BROWSER    │
│   (sandbox)  │                         │  (privileged)│
│              │  Interface bindings:    │              │
│  Remote<Foo> ├─── FooImpl ────────────►│ FooImpl      │
│              │                         │  (validates  │
│              │  Callback:              │   all input) │
│  Receiver    │◄── Response ────────────┤              │
└──────────────┘                         └──────────────┘

Key Mojo concepts:
- Interface: defined in .mojom files (IDL)
- Remote<T>: client-side proxy (in renderer)
- Receiver<T>: server-side implementation (in browser)
- Message pipe: bidirectional IPC channel
- Associated interfaces: share message ordering

Sandbox Bypass Techniques

From V8 Sandbox to Process-Wide R/W

Escape Vectors (V8 sandbox → full process):

1. WASM Instance Data Corruption
   - WasmTrustedInstanceData has raw pointers
   - Corrupt via trusted pointer table
   - Redirect jump_table_start → shellcode
   - Most reliable current vector

2. External Pointer Table Corruption
   - Overwrite table entries within the cage
   - Redirect ArrayBuffer backing_store
   - Gives R/W outside cage

3. Code Pointer Table Corruption
   - Redirect JIT code pointers
   - Execute arbitrary code at chosen address
   - Mitigated by W^X on code pages

4. JIT Code Corruption (pre-sandbox)
   - Older technique: overwrite JIT code in-place
   - Now mitigated by Code Pointer Table + W^X

From Process-Wide R/W to OS Sandbox Escape

Renderer Sandbox Escape Strategies:

1. Mojo IPC Exploitation (most common)
   - Craft malicious Mojo messages
   - Exploit browser process message handlers
   - Need a bug in browser-side code

2. Shared Memory Corruption
   - Corrupt shared memory regions between processes
   - Target browser process via shared buffers

3. Kernel Exploitation
   - Use allowed syscalls to trigger kernel bugs
   - Bypass seccomp-bpf via kernel vulnerability
   - e.g., namespace escape, userfaultfd abuse

4. GPU Driver Exploitation
   - Send malicious GPU commands via command buffer
   - Exploit driver code running in GPU process
   - Driver runs in kernel → direct kernel access

Kernel Exploitation from Browser

The ultimate escape: from the renderer sandbox directly to kernel code execution, bypassing both the V8 sandbox and the OS sandbox.

Full Chain: Renderer → Kernel
┌─────────────┐    ┌──────────────┐    ┌──────────┐
│ V8 Exploit  │───►│ Sandbox      │───►│ Kernel   │
│ (JIT bug)   │    │ Escape       │    │ Exploit  │
│ - OOB       │    │ - Mojo bug   │    │ - LPE    │
│ - Type conf │    │ - IPC forge  │    │ - Driver │
│ - Arb R/W   │    │ - GPU driver │    │ - Syscall│

Kernel vectors from sandboxed renderer:
- Allowed syscalls with kernel bugs (e.g., futex, mmap bugs)
- GPU driver ioctl (if allowed through sandbox)
- /proc/self/ information leaks
- Filesystem race conditions (if any FS access)

# lab4_seccomp.sh

# 1. Find Chrome's seccomp policy in source
# Key files:
# sandbox/linux/seccomp-bpf-helpers/syscall_parameters_restrictions.cc

# Method B: Use seccomp-tools to dump the filter
# Install: gem install seccomp-tools
# Attach to renderer:
# seccomp-tools dump -p $RENDERER_PID

# 3. Test which syscalls are blocked
# From within the sandbox (requires compromised renderer or test harness):
# strace -f -e trace=open,connect,execve chrome --type=renderer ...
// Simplified Chrome seccomp-bpf policy (renderer):
// Source: sandbox/linux/seccomp-bpf-helpers/baseline_policy.cc

bool AllowedSyscall(int sysno) {
  switch (sysno) {
    // Memory management — ALLOWED
    case __NR_brk:
    case __NR_mmap:
    case __NR_munmap:
    case __NR_mprotect:
    case __NR_madvise:
      return true;
    
    // IPC — ALLOWED (needed for Mojo)
    case __NR_recvmsg:
    case __NR_sendmsg:
    case __NR_socketpair:  // Only AF_UNIX
      return true;
    
    // Threading — ALLOWED
    case __NR_clone:       // Only with CLONE_THREAD flag
    case __NR_futex:
      return true;
    
    // File operations — BLOCKED
    case __NR_open:
    case __NR_openat:
    case __NR_creat:
      return false;
    
    // Network — BLOCKED
    case __NR_connect:
    case __NR_bind:
    case __NR_listen:
      return false;
    
    // Process — BLOCKED
    case __NR_execve:
    case __NR_fork:
      return false;
    
    default:
      return false;  // Deny by default
  }
}

// External Pointer Table structure:
class ExternalPointerTable {
  struct Entry {
    // Encoded as: pointer | tag
    // Tag prevents type confusion between different external pointer types
    std::atomic<Address> encoded;
  };
  
  Entry* table_;       // Array of entries
  uint32_t capacity_;  // Max entries
  uint32_t length_;    // Current count
  
  // Lookup: given index, return decoded pointer
  Address Get(ExternalPointerHandle handle, ExternalPointerTag tag) {
    Entry& entry = table_[handle >> kExternalPointerIndexShift];
    Address decoded = entry.encoded.load() & ~kExternalPointerTagMask;
    // Verify tag matches — prevents type confusion
    CHECK_EQ(entry.encoded.load() & kExternalPointerTagMask, tag);
    return decoded;
  }
};
