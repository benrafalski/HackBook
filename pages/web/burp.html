Burp Suite

Setting Up Burp Suite

Proxy Configuration

Burp listens on 127.0.0.1:8080 by default. Configure your browser to route traffic through this proxy.

# Verify Burp is listening
curl -x http://127.0.0.1:8080 http://example.com

# Firefox: Settings → Network Settings → Manual proxy
# Set HTTP Proxy: 127.0.0.1  Port: 8080
# Check "Also use this proxy for HTTPS"

CA Certificate Install

Required for intercepting HTTPS traffic. Without it, browsers reject Burp's self-signed certs.

# 1. With Burp running, navigate to http://burpsuite (or http://127.0.0.1:8080)
# 2. Click "CA Certificate" to download cacert.der

# Firefox: Settings → Privacy & Security → Certificates → View Certificates
#   → Authorities → Import → select cacert.der → Trust for websites

# Chrome/System: Settings → Security → Manage certificates
#   → Authorities → Import → select cacert.der

# CLI (Linux system-wide)
sudo cp cacert.der /usr/local/share/ca-certificates/burp.crt
sudo update-ca-certificates

Browser Setup Tips

Use a dedicated browser profile or FoxyProxy to toggle proxy on/off quickly.

# FoxyProxy (Firefox/Chrome extension)
# Add proxy: Title=Burp, Type=HTTP, IP=127.0.0.1, Port=8080
# Toggle via toolbar icon — avoids re-configuring system proxy

# Chromium with Burp proxy (isolated)
chromium --proxy-server="http://127.0.0.1:8080" --user-data-dir=/tmp/burp-profile

# Burp's embedded browser: no cert install needed
# Project options → Misc → Embedded Browser → enable

Proxy Tab

Intercept

Toggle Intercept is on/off to capture requests before they reach the server. While intercepted you can:

  • Forward — send the request as-is (or after editing)
  • Drop — discard the request entirely
  • Send to Repeater/Intruder — right-click or Ctrl+R / Ctrl+I

Target Tab

Site Map

Hierarchical view of all observed hosts, paths, and parameters. Built automatically as you browse through the proxy.

  • Right-click a host → Add to scope — filters proxy history and Scanner to only in-scope items
  • Right-click → Spider this host — actively crawl (Pro only)
  • Filter bar — show only in-scope, hide images/CSS/JS, filter by MIME type

Scope

Define what's in scope to reduce noise. Target → Scope → Add or right-click from site map.

# Include scope (regex)
^https?://target\.com/.*

# Exclude scope
^https?://target\.com/logout
^https?://.*\.google\.com/.*

Enable Proxy → Options → "Don't send out-of-scope items to history" to keep things clean.

Repeater

Manually modify and resend individual requests. Essential for testing parameter tampering, auth bypasses, and injection points.

# Workflow:
# 1. Intercept a request in Proxy (or find in HTTP history)
# 2. Right-click → Send to Repeater (Ctrl+R)
# 3. Modify parameters, headers, or body
# 4. Click "Send" — response appears on the right
# 5. Compare responses by opening multiple Repeater tabs

# Useful modifications:
# - Change parameter values to test SQLi/XSS
# - Swap HTTP methods (GET ↔ POST)
# - Add/remove cookies or auth headers
# - Change Content-Type for deserialization attacks

Payload Types

  • Simple list — paste or load a wordlist
  • Numbers — sequential or random range (e.g., IDs 1–1000)
  • Recursive grep — extract token from response, use in next request (anti-CSRF bypass)
  • Brute forcer — character set + min/max length
  • Null payloads — repeat request N times with no change (rate limit testing)

Comparer

Diff two requests or responses side-by-side. Useful for spotting subtle differences in blind injection, auth bypass, or A/B testing.

# Workflow:
# 1. Right-click response in Repeater/Proxy → Send to Comparer
# 2. Send a second (modified) response to Comparer
# 3. Select both items → click "Words" or "Bytes"
# 4. Differences are highlighted — look for content-length changes,
#    different error messages, or missing/added headers

Sequencer

Statistical analysis of session tokens and other random values to detect weak randomness.

# Workflow:
# 1. Find a request that returns a token (e.g., Set-Cookie: session=...)
# 2. Right-click → Send to Sequencer
# 3. Configure token location in response
# 4. Click "Start live capture" — collects ~10,000+ samples
# 5. Click "Analyze now" — provides entropy/randomness rating

# Good randomness: "overall quality is excellent" (entropy close to 128 bits)
# Weak randomness: predictable tokens → session hijacking possible

Collaborator

Out-of-band (OOB) testing server. Provides unique subdomains that log DNS/HTTP/SMTP interactions. Proves blind vulnerabilities when no in-band response is visible.

# 4. Click "Poll now" in Collaborator client to check for interactions
# 5. DNS/HTTP/SMTP hits confirm the vulnerability

Tips for CTF Usage

  • Scope everything — add the challenge domain to scope immediately to avoid noise
  • Check cookies & hidden params — inspect every Set-Cookie, hidden form fields, and custom headers in Proxy history
  • Repeater is your best friend — manually iterate on payloads faster than a browser
  • Use Decoder for multi-layer encoding — CTFs love nesting base64 → URL → hex
  • Intruder for brute force — even Community Edition works (just throttled). Use Turbo Intruder for speed
  • Search proxy history — Ctrl+Shift+F to search all recorded traffic for flags, tokens, or keywords
  • Compare responses — send valid vs invalid auth responses to Comparer to spot the exact diff
  • Save your project — Burp project files preserve all history; save before closing

Lab 3: Extension-Based Testing

Hard

Objective: Use Burp extensions (Autorize + JWT Editor) to find broken access control in a JWT-authenticated API.

# app.py — JWT auth with broken access control
import jwt
from flask import Flask, request, jsonify

app = Flask(__name__)
SECRET = 'burp-lab-secret-key'

@app.route('/login', methods=['POST'])
def login():
    user = request.json.get('username', '')
    pwd = request.json.get('password', '')
    if user == 'admin' and pwd == 'admin':
        token = jwt.encode({'user': 'admin', 'role': 'admin'}, SECRET)
        return jsonify({'token': token})
    if user == 'guest' and pwd == 'guest':
        token = jwt.encode({'user': 'guest', 'role': 'viewer'}, SECRET)
        return jsonify({'token': token})
    return jsonify({'error': 'Invalid credentials'}), 401

@app.route('/api/users')
def users():
    token = request.headers.get('Authorization', '').replace('Bearer ', '')
    try:
        data = jwt.decode(token, SECRET, algorithms=['HS256'])
    except:
        return jsonify({'error': 'Invalid token'}), 401
    return jsonify({'users': ['admin', 'guest', 'bob']})

@app.route('/api/admin/flag')
def admin_flag():
    token = request.headers.get('Authorization', '').replace('Bearer ', '')
    try:
        data = jwt.decode(token, SECRET, algorithms=['HS256'])
    except:
        return jsonify({'error': 'Invalid token'}), 401
    # BUG: checks role from token without verifying against DB
    if data.get('role') == 'admin':
        return jsonify({'flag': 'BURP{jwt_3xt3ns10n_ftw}'})
    return jsonify({'error': 'Admin only'}), 403

app.run(debug=True)

  1. Install JWT Editor and Autorize from the BApp Store
  2. Login as guest:guest via POST to /login — save the JWT token
  3. Access /api/users with the guest token — confirm it works
  4. Try /api/admin/flag with the guest token — expect 403
  5. JWT Editor approach: Decode the guest JWT, change "role":"viewer" to "role":"admin", re-sign if possible (try alg:none or brute force the weak secret)

Lab 4: Macro-Based Authentication

Medium

Objective: Configure a Burp macro to automatically login and refresh session tokens before each request.

# app.py — Session-expiring app
from flask import Flask, request, session, jsonify
import secrets, time

app = Flask(__name__)
app.secret_key = secrets.token_hex(16)

tokens = {}

@app.route('/login', methods=['POST'])
def login():
    user = request.form.get('username', 'guest')
    token = secrets.token_hex(16)
    tokens[token] = {'user': user, 'expires': time.time() + 30}  # 30s expiry
    return jsonify({"token": token})

@app.route('/api/data')
def data():
    token = request.headers.get('X-Token', '')
    t = tokens.get(token, {})
    if not t or t['expires'] < time.time():
        return jsonify({"error": "Token expired. Re-login required."}), 401
    return jsonify({"data": "sensitive_info", "flag": "BURP{m4cr0_4uth}"})

app.run(debug=True)

Tasks:

  1. Notice that tokens expire after 30 seconds — manual testing is frustrating
  2. In Burp: Project Options → Sessions → Session Handling Rules
  3. Add a rule: Run a macro → Record a macro that POSTs to /login
  4. Configure the macro to extract the token from the response
  5. Set the rule to add/update X-Token header on all requests in scope
  6. Now every request automatically gets a fresh token

Lab 10: Extension Development Basics

Hard

Objective: Write a simple Burp extension in Python (Jython) that adds a custom header to every request.

# custom_header.py — Burp extension (Jython)
from burp import IBurpExtender, IHttpListener

class BurpExtender(IBurpExtender, IHttpListener):
    def registerExtenderCallbacks(self, callbacks):
        self._callbacks = callbacks
        self._helpers = callbacks.getHelpers()
        callbacks.setExtensionName("Custom Header Injector")
        callbacks.registerHttpListener(self)

    def processHttpMessage(self, toolFlag, messageIsRequest, messageInfo):
        if messageIsRequest:
            request = messageInfo.getRequest()
            analyzed = self._helpers.analyzeRequest(request)
            headers = list(analyzed.getHeaders())
            headers.append("X-Custom-Auth: BURP{3xt3ns10n_d3v}")
            body = request[analyzed.getBodyOffset():]
            messageInfo.setRequest(
                self._helpers.buildHttpMessage(headers, body)
            )
