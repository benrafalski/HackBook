AdminSDHolder & SDProp

AdminSDHolder is a container whose ACL is stamped onto all protected groups (Domain Admins, Enterprise Admins, etc.) every 60 minutes by the SDProp process. Backdooring AdminSDHolder grants persistent access to all protected groups.

# View AdminSDHolder ACL
(Get-ACL "AD:\CN=AdminSDHolder,CN=System,DC=domain,DC=local").Access |
  Format-Table IdentityReference, AccessControlType, ActiveDirectoryRights

# Protected groups (their ACLs get overwritten by AdminSDHolder):
# Domain Admins, Enterprise Admins, Schema Admins, Administrators,
# Account Operators, Server Operators, Print Operators, Backup Operators,
# Domain Controllers, Read-only Domain Controllers, Cert Publishers,
# Replicator, krbtgt

# Detect backdoor: look for unexpected ACEs on AdminSDHolder
$acl = Get-ACL "AD:\CN=AdminSDHolder,CN=System,DC=domain,DC=local"
$acl.Access | Where-Object { $_.IdentityReference -notmatch "Domain Admins|Enterprise Admins|SYSTEM|Administrators" }

# Check if a user is protected (adminCount = 1)
Get-ADUser -Filter { adminCount -eq 1 } -Properties adminCount, memberOf |
  Select-Object Name, adminCount, memberOf

    "D4F940AB-401B-4EFC-AADC-AD5F3C50688A",  # Block Office child processes
    "3B576869-A4EC-4529-8536-B80A7769E899",  # Block Office exe content
    "75668C1F-73B5-4CF0-BB93-3ECF5CB7CC84",  # Block Office injection
    "9E6C4E1F-7D60-472F-BA1A-A39EF669E4B2",  # Block cred stealing from LSASS

Credential Protection

Credential Guard

Uses VBS (Virtualization-Based Security) to isolate LSASS secrets in a protected container. Even with kernel-level access, an attacker cannot extract credentials from the isolated LSA process.

# Requirements: UEFI, Secure Boot, TPM 2.0, 64-bit, Enterprise/Education edition
# NOTE: Do NOT enable on Domain Controllers (breaks replication)

# Check if Credential Guard is running
Get-CimInstance -ClassName Win32_DeviceGuard -Namespace root\Microsoft\Windows\DeviceGuard |
  Select-Object -ExpandProperty SecurityServicesRunning
# 1 = Credential Guard running

# Enable via GPO:
# Computer Configuration → Administrative Templates → System → Device Guard
#   "Turn on Virtualization Based Security" = Enabled
#   "Credential Guard Configuration" = Enabled with UEFI lock

# Enable via registry
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\DeviceGuard" -Name "EnableVirtualizationBasedSecurity" -Value 1
Set-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\Lsa" -Name "LsaCfgFlags" -Value 1
# LsaCfgFlags: 0=Disabled, 1=Enabled with UEFI lock, 2=Enabled without lock

# Verify status
msinfo32  # Check "Credential Guard" in System Summary
# Or PowerShell:
Get-ComputerInfo | Select-Object DeviceGuardSecurityServicesRunning

# What Credential Guard protects:
# - NTLM hashes (no more pass-the-hash from LSASS)
# - Kerberos TGTs (no more pass-the-ticket from LSASS)
# - Derived domain credentials
# What it does NOT protect:
# - Credentials for local accounts
# - Service account credentials cached by applications
# - Credentials in third-party credential providers
